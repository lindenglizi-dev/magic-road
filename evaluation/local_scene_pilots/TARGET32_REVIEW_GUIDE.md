# 32帧完整目标审核与配对诊断

双击打开 `intersection_2415171_target32_v2/annotate.html`。这是离线页面，不上传图片、不需要安装服务。内置浏览器可能限制 file 协议，此时用系统浏览器打开此文件。v2补充了删除目标和导入覆盖的确认；v1仅留作初版审计记录。

## 填写方法

1. 逐帧框出所有可见行人和机动车，包括算法没有框出的目标和静止车辆。不要把人少等同于候选少。
2. 框住目标可见部分的紧框，不根据想象补全被遮挡部分。分别填写类别、可见性和移动状态。骑行者先记 `ignore`，子类填 `rider_bicycle`；其他不能归类对象说明子类。
3. 同一目标跨帧使用同一轨迹ID，例如 `p01`、`v01`。不确定移动状态时选 `uncertain`。报告会单独统计 `moving` 与全部可见目标；不会把静止车漏检当成移动目标检出失败。
4. 每帧完成后勾选“本帧已全部检查”。没有目标的帧也要确认；不可用自动候选代替完整帧标注。
5. 页面默认隐藏蓝色CCL框，全部不显示分类器分数。需要核对候选位置时才打开蓝框。黄色框由你填写，框错可删除重画。
6. 建议每完成几帧点击“导出审核JSON”保存草稿；可以导入继续。确认全部32帧、填写真实审核者和实际日期后，再勾选亲自核对。

请将导出的 `intersection_2415171_targets_review.json` 放回该标注包目录或告诉助手保存位置。未填写的记录不会被当成背景，AI初标不会自动升格为人工真值。

## 配对诊断口径

- 源视频：`2415171-hd_1920_1080_24fps.mp4`，SHA256 `5bd44aededccb88ac75febb170ae0f916b909277a0b4e8450adc4e33d440ea6b`。
- 抽样：frame 120、150……1050，共32帧。抽样不使用分类分数、框数或正确率。
- 参考候选：已完成的 frame0 因果背景、frame120–1079 基线 top4；不重新学习背景或修改参数。
- 原图坐标为0起始闭区间；映射到256×144时各边使用 `floor(coord/5)`，对应5×5采样格的覆盖范围。使用既定FPGA灰度与32×32最近邻缩放。
- 主匹配：原图框IoU≥0.5，类别无关、最大匹配数优先，匹配数相同时最大化总IoU。一帧中一个候选不能重复认领多个目标。
- IoU≥0.25仅作为几何敏感性附录，不挑选效果最好的阈值作主结果。
- 对全部GT框统计冻结模型的分类结果；对成功匹配的相同目标比较GT ROI与CCL ROI。未匹配的目标进入漏检分母。
- 端到端召回 = 匹配成功且分类正确的目标 / 对应GT目标。分别报告移动目标与全部可见目标、每类原始计数和独立轨迹数。32个抽样帧不能代表完整视频时序准确率。
- 未匹配候选不自动写成invalid：可能是人体碎片、重复框或其他目标，需独立审核。

## 命令

在项目根目录执行，输出必须使用不存在的新目录：

```powershell
python tools/local_paired_diagnostic.py evaluate --annotations evaluation/local_scene_pilots/intersection_2415171_target32_v2/intersection_2415171_targets_review.json --output evaluation/local_scene_pilots/intersection_2415171_paired_human_v1
```

评分程序拒绝缺少审核确认、未完成帧、错误坐标、缺失轨迹ID、视频或候选哈希改变等输入。输出可追溯的逐目标pairs和分组report；不写训练集、不修改生产RTL。

# CCL 扫描上界优化与容量预算

软件参考保留每条 run 的原始标签升序合并，只去掉最高匹配标签之后的空 bitmap 扫描。未修改生产 RTL。

| 配置/分支 | 实验容量/位宽 | 超限帧 | 逻辑数组位数（含新增上界寄存器） | 扫描访问总量减少 | 峰值：全容量扫描/上界扫描 |
|---|---|---:|---:|---:|---|
| baseline256/current | 128/8 | 0/960 | 12739 | 77.2% | 82689/17715 |
| baseline256/keep_all | 192/8 | 0/960 | 16515 | 80.2% | 180262/33412 |
| ddr640/current | 256/9 | 0/960 | 23757 | 84.1% | 402976/70846 |
| ddr640/keep_all | 1024/11 | 0/960 | 78289 | 85.1% | 4057975/573375 |

扫描访问不是 RTL 总周期，逻辑位数不是综合资源。容量扩大没有改变候选几何或分类效果。

实现约束：最大重叠原始标签必须随 run 清零；收齐全部 previous-row 返回后才开始扫描，最后一次返回的上界更新须在下一拍可见；union 的根变化不能重排原始标签；超限输出不得作为成功发布。

正式验证仍须覆盖最后返回拍、不同合法间隙、满表、union 链、溢出取消和随后空帧/正常帧，比较逐 run 最终根分区与面积框。

本批 3840 个过滤 Mask 与 OpenCV 分区一致；自检 44 个用例通过。

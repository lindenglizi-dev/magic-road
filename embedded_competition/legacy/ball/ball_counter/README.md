# 彩色小球检测与计数

打开 `td_project/camera_to_dsi_display.al`。器件为安路 PH1P35MDG324，速度等级 -3；开发环境为 Tang Dynasty 6.2.168116。顶层模块为 `design_top_wrapper`，视频分辨率为1280×720。

工程引用均使用相对路径。搬移时请复制整个 `ball_counter` 文件夹。`rtl` 为检测、追踪、计数与显示模块，`user_source` 为相机、ISP、DDR和HDMI等底层源码及IP，`td_project` 为工程与约束，`release/ball_counter.bit` 为下载文件。重新编译可使用TD界面；目录中的 `syn_1`、`phy_1` 同时提供独立批处理配置，执行时以各运行目录为工作目录，将相应的 `camera_to_dsi_display.tcl` 作为 `td_commands_prompt.exe` 的位置参数；生成bit使用物理运行目录的 `camera_to_dsi_display_bitgen.tcl`。

## 操作

| 按键（FPGA引脚） | 短按 | 长按约1秒 |
| --- | --- | --- |
| KEY1（D5） | 切换TRACK/COUNT4 | 曝光1991→480→240→120 |
| KEY2（A9） | 原图/颜色掩膜 | 增益16→32→4→8 |
| KEY3（B9） | NORMAL/STRICT | 白纸校准 |
| KEY4（C7） | 清除计数及轨迹 | 同短按 |

TRACK为单球跟随。COUNT4最多同时维护4条轨迹，分别显示编号1～4，并对红、绿、黄球去重计数。球从左向右进入检测区域，在计数线左侧获得两次检测确认，中心越过右侧迟滞线后计数一次；停止或短暂反向不会重复计数。应保持球之间可见间隔，避免紧贴或严重遮挡。BALLS包含短暂失联保留的灰色框；连续8次有效检测缺失后槽位释放，编号可复用。长时间丢失后重新入镜不保证原身份。

白纸校准时，固定灯光、曝光和增益，让白纸覆盖画面中心，长按B9约1.5秒，出现WBSET后移开。校准只修正显示通道，不改变检测阈值。切换模式或颜色档会清除轨迹并保留计数；C7不会清除白纸校准。

## 调整范围

COUNT默认保留宽高24～384像素、宽高比不大于3:2且满足填充和轮廓条件的目标。在 `rtl/ball_runtime.v` 调整 `C_COUNT_MIN_SIZE`、`C_COUNT_MAX_SIZE`、`C_COUNT_COMPACT` 后重新编译。尺寸为像素值，需要固定机位和距离后标定，不能直接作为毫米尺寸。

CCL4行的N为合格候选数；W/H/A/F/R描述最大完整区域，可能来自被排除的背景。R为拒绝原因位：1面积、2尺寸、4宽高比、8填充或轮廓。ERR：1检测溢出、2容量不足、3未完成上游确认、5统计故障、6计数饱和、7视频协议错误。超过4颗时保守跳过该帧的新增计数。

## 验证

Python 3.10及以上，安装Icarus Verilog并将其bin目录加入PATH后，在工程根目录运行 `python sim/run_checks.py`。检查包含111帧多球关联、停止、漏检、反向、容量与饱和用例，以及8帧RGB到DDR输出的完整运行链路；后者验证四球分别计数和方块排除。输出保存到 `build` 下独立目录。

当前bit与COUNT4基线相同，仅打包结构和两处注释经过整理。基线实现时序：SWNS +0.109ns、HWNS +0.021ns，STA覆盖率93.70%；并非所有时序路径均受覆盖。bit的SHA256为 `15fa71a173a15852ce3e4ec448f57f2ffc5a09a39bccc6306c4930d4398cdd6e`。仿真不能代替实板验证；复杂遮挡、紧贴同色目标及极快跳线仍可能漏检或身份交换。代码尚有严格静态格式检查未通过项，本次未改动RTL逻辑进行格式重构。

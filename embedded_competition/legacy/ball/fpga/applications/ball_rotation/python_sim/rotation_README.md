# 带标记小球旋转：Python工程演示

入口为 `E:/project/ball/fpga/applications/ball_rotation/python_sim/rotation.py`，双击同目录“启动旋转模拟.cmd”。原检测/计数入口main.py保留。

这是实际处理RGB像素的软件算法工程，不是RTL逐周期仿真，也没有修改FPGA bit。算法输入只有RGB图像和时间戳，不接收演示球的坐标、转角或转速真值。演示生成器的真值仅用于CSV最后一列和离线误差统计。

## 第一版场景约束

- 单球，旋转轴固定并大致朝向摄像头。球可以在画面里平移；不保证任意倾斜轴、自由滚动的真实三维转速。
- 红、黄或绿球上贴**一个**哑光黑圆点，大小约为球直径的1/10，放在正面偏心处；在图像里距球心约0.4～0.7个球半径。不要贴在旋转轴正中心或轮廓边缘。
- 标记应有清晰边界，建议球直径至少80像素。球完整处于ROI `X64～1215 / Y160～639`，避开高光直射标记。
- 相机固定。相机转动、球体遮挡、轴倾斜和透视变化都可能污染角度测量。白平衡/亮度仍会影响已有球颜色分割。

## 启动与输入

在 `E:/project/ball/fpga/applications/ball_rotation/python_sim` 中执行：

```powershell
python rotation.py
python rotation.py --headless --frames 720
python test_rotation.py
```

交互键：空格暂停；C清除当前球的旋转参考与圈数；M查看黑点掩膜；Q或Esc退出。暂停demo时不推进源帧或模拟时间。默认交互demo持续运行，headless默认720帧。只运行默认demo不会打开真实摄像头。

处理电脑可访问的摄像头或视频：

```powershell
python rotation.py --source 0 --record
python rotation.py --source "D:/videos/marked_ball.mp4" --headless
```

`--source 0`指电脑摄像头设备，不会直接访问FPGA上的SC520 MIPI相机；该相机需要先有可被电脑读取的视频输入。外部视频等比例缩放并填边到1280×720，避免把球拉伸成椭圆。

视频文件优先采用文件帧时间戳，缺失时采用FPS时间轴；电脑摄像头用实际读取的单调时钟。demo采用 `--fps 60` 的模拟时间轴，运行计算速度单独写入summary，不能把演示60fps当成实板吞吐或本机处理帧率。摄像头模式暂停后存在未观察时段，恢复时可能标PARTIAL。

摄像头模式录制的视频使用固定写入FPS，播放时长可能与实际读取时间不同；转速测量以CSV中的单调时间戳为准。正式计量应先验证相机采集时间戳与丢帧情况。

可调参数：

- `--max-rpm 120`：真实绝对转速的**先验上界**，用于判断跨缺帧相位是否还能唯一展开；不是已验证最高性能。必须保证实际转速低于该值。采样混叠可能把高速转动看成低速或静止，程序无法仅凭两帧自动证明没有混叠。
- `--dark-ratio 0.45`：黑点阈值为球内部中位灰度乘此比例，可在0.1～0.8间调整。M掩膜中应只留下球面黑点；同时出现多个合格暗块会拒绝测量。
- `--frames N`：限制处理帧数。`--output 路径`：独立输出目录，避免覆盖前一次输出。默认输出为同目录output/rotation。

## 图像工程结构

```text
纯RGB图像与时间戳
  → 原pipeline.segment颜色分割
  → 原ComponentRAM的4×4同色组件
  → 原TargetTracker关联球体
  → 取当前实测组件，拟合外轮廓包围圆
  → 圆内部亮度阈值、暗块面积/形状/偏心筛选
  → 黑点相对实测球心的atan2角度
  → 相位展开、已知转速上界和缺帧校验
  → 约0.3秒窗口估计RPM、方向与整圈
  → 画面叠加、视频、逐帧CSV及验证摘要
```

旋转测量使用实测球心，不使用PRED预测显示坐标。Python中包围圆、连通区域、atan2和窗口拟合属于本次算法验证，后续上FPGA需要设计对应RTL及重新验证资源、时序，不能把本次运行称为硬件通过。

## 画面数值的定义

- ANGLE：黑点相对球心、从画面右方向起的0～360°图像相位；不是绝对三维姿态。
- RPM：估计转速绝对值；状态CW为**相机视角顺时针**，CCW为逆时针。CSV signed_rpm的正负分别对应CW/CCW。
- STOP：估计绝对转速小于2 RPM，用于抑制像素抖动，不等于证明物理上绝对静止。转速至少需要4个有效观测且跨度至少0.1秒，平滑窗口通常约0.3秒；低采样率时保留最近4点，响应时间更长。
- NET：从参考帧开始、有效观测段累计的有符号净转角/360；反转会回减。
- FULL CW / FULL CCW：各连续同方向运动段内完成的整圈次数。反向超过8°确认新的运动段；不足一圈的往返不直接算成完整一圈，接近整圈边界时存在像素精度不确定性。
- CONTINUOUS：目前所有相邻有效相位都能在已知转速上界及短缺口约束下连接，不等于无条件证明物理全程可观测。
- PARTIAL：曾发生长缺口、相位跳变或不可唯一展开。缺口期间冻结圈数，恢复后重建相位参考，**不补造缺失圈数**；此后数值仅代表已测到的部分，直到C清零。
- UNAVAILABLE：还没有任何可用黑点观测。无标记不能显示为“已测转速为0”。短时丢失也显示RPM为--。
- ID：当前关联球编号；球消失后重新搜索会建立新编号并重置旋转参考，不能把不同球或无法确认身份的重现混为同一条旋转记录。

不超过0.25秒、且按先验转速上界算出的最大位移小于150°时，短遮挡可以在恢复时补上唯一相位差；不满足任一条件则标PARTIAL。例如上界120RPM时，可连接缺口还须短于约0.208秒。没有标记、多个暗块、球出ROI、组件溢出时不输出新角度。无纹理纯色球不能通过球的位置变化判断自转。

## 输出与验算

完整demo按12秒时间轴安排：30RPM顺转3秒 → 静止1.5秒 → 45RPM逆转3.5秒 → 60RPM顺转4秒；球体同时平移，并在5.40～5.45秒隐藏黑点。生成：

- rotation_input.mp4：原始渲染图像，无算法结果。
- rotation_result.mp4：实际图像算法输出。
- rotation_pipeline.png及01～04阶段PNG：颜色分割、黑点掩膜、最终显示。
- rotation_trace.csv：每帧实测球心、黑点、角度、RPM、圈数、状态、缺口标志。最后一列reference_rpm_demo_only仅用于demo验算，外部视频为空。
- summary.json：实际处理时间、有效观测数、稳定段误差和范围声明。

test_rotation.py的8组检查覆盖三色正反转、纯平移、停止/反转、短长遮挡、无标记/多暗块、变暗/噪声、相位跨零、变间隔时间戳、清零和输入校验。允许误差是这些合成图像的验收范围，不是实拍精度承诺。完整demo的稳定段误差排除变速边界0.5秒，避免把平滑器响应时间隐去后当成瞬时响应。

实际照片/视频中黑点的反光、运动模糊、曝光、轴偏斜、相机晃动等仍需上机测试。这里没有修改现有检测/计数RTL，也没有操作开发板或Flash。

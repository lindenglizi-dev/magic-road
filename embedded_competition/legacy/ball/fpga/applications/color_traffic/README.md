# SC520 固定 ROI 颜色检测与交通灯识别

在 TD 6.2.1 打开 `td_project/camera_to_dsi_display.al`，顶层 `design_top_wrapper`，器件 PH1P35MDG324、速度等级 -3。这是从指定的 `lab_ex1_mipi_hdmi_SC520 (2)/lab_ex1_mipi_hdmi_SC520/lab_ex1_mipi_hdmi` 复制并接入的新工程，源工程没有修改；本目录包含摄像头、DDR、HDMI、IP 和约束，不依赖另一个应用目录。

已生成下载文件：`td_project/camera_to_dsi_display_Runs/phy_1/camera_to_dsi_display.bit`。当前版本基础仿真、TD综合与布局布线通过，最终SWNS +0.120ns、HWNS +0.020ns；上板效果待实测。后续修改RTL或参数后需重新生成bit。

## 已实现

- 固定 ROI 内红、黄、绿、蓝像素检测、按帧计数及主色判定。
- 交通灯模式识别红、黄、绿；蓝色不会输出为交通灯状态。
- 最近三帧多数投票，三帧不一致为未知；未知也参与投票，避免目标消失后一直保留旧灯色。前两帧预热显示未知。
- 白色 ROI 框、识别结果色块、模式与阈值指示，原图/颜色掩膜切换。
- 右上角中文/英文模式名称，左侧安路 logo；模式文字与检测模式按帧同步。
- 模式下方显示“识别为：红灯/黄灯/绿灯”或“识别为：红色/黄色/绿色/蓝色”；未形成有效多数时显示“识别为：未知”。
- 四键双触发器同步、约 20 ms 双向消抖、长按只触发一次，模式和阈值在帧边界生效。

这是固定 ROI 的灯色判别，不包含全画面交通灯定位、灯形识别或多灯目标跟踪。应把单个待识别交通灯放进白框，避免红色衣物、广告等同时占据 ROI。适用于当前定点场景原型；真实道路识别率需要实际素材标定，未做上板实测。

## 开发链与接口

`SC520 RAW10 → 原 MIPI/解包 → demosaic → AWB → 检测/投票及状态块 → 模式文字与logo OSD → 96/128 打包 → 原 video_in/DDR → HDMI`

保持 1280×720，AWB 时钟域每拍四像素，每像素 `{R,G,B}`，最左像素为 `[95:72]`。每帧 230400 个有效输入组、172800 个 DDR 字。算法不需要行缓存、除法器或新时钟。

AWB 的 `tuser` 是提前帧通知，单独延迟一拍送到原 `video_in`，保留 FIFO 提前复位时间。处理支路根据有效像素重建首像素、行末及帧末，忽略可能出现在消隐区的 AWB `tlast`；有效空拍不改变坐标或打包相位。检测/叠加寄存一级，文字/logo OSD三级，打包再一级；OSD同步延迟全部有效与行帧标记，不改变每帧像素数量。没有 ready 背压，沿用原摄像头连续采集契约；帧结束至少需要一个空拍完成统计，原链路消隐满足此条件。

`rtl/color_traffic_core.v` 是四像素检测、统计、投票和显示模块；`rtl/color_traffic_runtime.v` 负责按键和打包。`rtl/rgb96_pack128_valid.v` 复用已有开发链的有效组打包器。原工程仅改动 ISP 接入、顶层四键输入和管脚约束三处。

`rtl/color_mode_osd.v` 复用既有四像素同步ROM显示结构，内含字模和logo ROM定义。`rtl/color_osd_assets_rom.v` 仅为兼容注释文件，不重复定义模块。字模/logo常量嵌在RTL内，不依赖运行时外部mem路径。`generate_osd.py` 可从本目录 `assets/anlogic_source.png` 和 Windows 黑体字体重新生成；正常综合不需要执行。修改文字后运行生成脚本，再重新综合。

结果显示采用一个统一的帧状态来源：检测核心在提前帧通知时锁存 `display_result` 和 `active_traffic`，并通过 `O_display_result`、`O_display_traffic` 输出给文字OSD。左侧结果色块与右上文字读取同一份快照；runtime不再重复锁存模式，也不复制投票或清空判断。检测、帧状态和文字渲染通过明确端口连接。统计结果 `result` 仍在帧末更新，显示快照在下一帧生效；模式/阈值变更时两处显示一起回到未知，不会把上个模式的红灯结果显示为红色。

## 按键与显示

上电为交通灯模式、普通阈值、原图叠加。

| 按键 | 管脚，低有效 | 功能 |
|---|---|---|
| KEY0 | D5 | 交通灯 / 四色检测切换 |
| KEY1 | A9 | 原图叠加 / 颜色掩膜切换 |
| KEY2 | B9 | 普通 / 严格阈值切换 |
| KEY3 | C7 | 恢复上电模式 |

同时按键时 KEY3 恢复默认优先。更换模式或阈值会清空投票历史，重新积累三帧；更换掩膜显示不清空。按钮按住不会连发。

左上角 `(16,16)～(79,47)` 为结果色块：灰=未知、红=红、黄=黄、绿=绿、蓝=蓝。旁边 `(88,16)～(111,47)` 橙色代表交通灯、青色代表四色检测；第三块 `(120,16)～(143,47)` 深灰为普通阈值、白为严格阈值。白色 ROI 边框宽两像素。掩膜模式只显示 ROI 内命中的四色，框外黑色；交通灯模式下蓝色可用于观察干扰，但不参与灯色候选。

右上角 `(848,16)～(1263,127)` 显示深色底、浅黄色三行文字：第一、二行保留“颜色检测 / COLOR”或“红绿灯识别 / TRAFFIC”，第三行显示“识别为：红灯”等投票结果。KEY0请求在下一帧边界同时切换检测和文字，帧中按键不改变当前标签。左侧 `(16,64)～(143,143)` 显示128×80安路logo，沿用已有工程的官方图案、白底及红蓝配色；放在原状态色块下方，避免覆盖原功能。掩膜模式同样显示名称、结果和logo。实际RTL输出的顶部预览见 `reports/osd_actual_preview.png`（红灯）和 `reports/osd_color_preview.png`（红色），不是相机实拍。

当前帧统计完成后更新内部 `result`，下一帧边界锁存到画面，因此整帧色块稳定。运行中颜色切换通常需两个新颜色帧形成多数，随后下一帧显示；初次启动需收集三个完整帧。输入停帧时不会自动清除结果。

## ROI 与参数调整

在 `color_traffic_core.v` 参数表修改 ROI，重新综合即可：

| 参数 | 默认 | 含义 |
|---|---:|---|
| W / H | 1280 / 720 | 必须与摄像头、ISP、DDR、HDMI保持一致 |
| X0 / Y0 | 480 / 180 | ROI 左上角，包含 |
| X1 / Y1 | 800 / 540 | ROI 右下边界，不包含 |
| MIN_PIXELS | 128 | 候选颜色最低命中像素数 |
| DOM_MARGIN | 32 | 第一名必须比其他候选至少多 33 个像素 |

必须满足 `0 <= X0 < X1 <= W`、`0 <= Y0 < Y1 <= H`，W 为16的倍数，W/H不超过4095。坐标为最终 AWB 图像坐标。默认 ROI 为中央 320×360，可按实际灯大小缩小。ROI 不必按4像素对齐。

`classify` 函数中普通/严格亮度下限分别100/150，通道差分别30/50。红色要求 R 高于 G、B；绿色、蓝色同理。黄色要求 R、G 均达到亮度下限且高于 B，R/G 差不超过60。计算使用扩展位宽，避免8位加法溢出；白、灰不归入任何颜色。采用 RGB 比较，避免 HSV 除法资源开销。

先对准灯并等待曝光、白平衡稳定，再用 KEY1 看掩膜；漏检先用普通阈值，误检先缩小 ROI 或选严格阈值。阈值受 AWB、曝光、距离影响，不建议一开始改动原摄像头寄存器。若需细调，修改函数内100/150、30/50、60和计数参数，重新综合。当前未加入串口配置界面。

内部状态编码：0未知、1红、2黄、3绿、4蓝。`frame_result` 为单帧结果，`result` 为投票结果，四个 `*_count` 为最近完成帧的像素数；这些输出在 ISP 时钟域，可接入片上调试。板级未新增外部状态引脚。`error` 为粘滞的帧重叠提示，打包错误合入 `O_error`。未接出的调试信号可能被综合优化，需要观察时增加调试连接。

## 构建、基础校验与上板

在本目录运行：

```powershell
./sim/run_verify.ps1
E:/anaconda3/python.exe audit_project.py
./run_td.ps1 -SynthesisOnly
# 需要生成下载文件时运行完整实现：
./run_td.ps1
```

脚本默认 TD `E:/TD/6.2.1/bin`、Vivado `E:/Xilinx/Vivado/2022.2/bin`，可传 `-TdBin` 或 `-VivadoBin` 修改。`build_project.py` 是从原工程重新复制接线的脚本，会覆盖本副本的原工程文件；正常打开工程不需要运行。

基础仿真用160×64缩小图像验证16帧颜色、投票、无目标、阈值、行内空拍、ROI计数（包括末拍）、行帧标记和 DDR 字节顺序；另用8帧1280×720检查未知→红灯、切换模式后清空→红色，以及logo、中英文名称、KEY0帧中请求/帧边界切换、原ROI和状态块、全帧DDR逐字输出。全工程执行原厂综合和正常布局布线。未扩大为强对抗测试。具体结果见 `reports/verification.md`。

生成 bit 后使用原有下载方式上板，接摄像头与 HDMI。先观察原图、ROI 和灰色未知状态；依次将红/黄/绿发光目标放入白框，等待三帧以上确认结果；移开目标检查恢复灰色；切到四色模式测试蓝色。最后测试四个按键和掩膜。

可直接用浏览器打开 `sim/demo_target.html`，点击按钮或按1～6切换红、黄、绿、蓝、熄灭、白色目标。屏幕颜色和真实交通灯曝光不同；仿真日志不是摄像头实拍演示记录。用 `reports/上板演示记录.md` 记录目标、光照、距离、阈值档位、结果及视频文件名。

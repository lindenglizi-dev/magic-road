## 2 第一版场景边界

单球模式：搜索 ROI 内只有一颗待追踪的红、绿或黄球，允许向任意方向移动。固定搜索 ROI 可覆盖大部分画面；目标框随球移动。保留固定搜索区，避免把检测 ROI 收缩到旧框后丢失快速移动的球。

流水线模式：背景尽量采用无红、绿、黄的哑光材料；摄像头固定，输送方向在图像中接近水平。不同球的 X 方向投影之间必须有足够空列，且球不并排、不超车、不发生复杂遮挡。二维上看似分开但 X 投影重叠的摆放不属于本方法的保证范围。

整幅画面允许多球同时存在，包括两颗同色球。计数门区内同时至多一颗球，相邻球之间门区必须连续空出至少 3 个完整检测帧。这个条件需要在实际速度、门宽和帧率下验证，不能仅凭肉眼看到一点间隙判断满足。

计数语义是从左到右通过计数门的次数。长期完全漏检、并排输送、贴近同色球、反复取出后重新从上游放入，不属于对同一物理球永久去重的承诺。

## 4 ROI 与颜色分割

ROI 使用半开区间 `[X0,X1) × [Y0,Y1)`；四个像素分别比较坐标，边界不要求四像素对齐。可先使用大搜索 ROI，再在流水线模式切换为只覆盖输送带的长条 ROI。

复用现有 RGB 比较思路，黄色优先于红、绿，保证一个像素至多属于一种颜色：

- 红：R 达到亮度下限，并明显高于 G、B。
- 绿：G 达到亮度下限，并明显高于 R、B。
- 黄：R、G 同时达到亮度下限，均明显高于 B，且 R/G 差值不大。
- 白、灰、黑、蓝不作为三色球命中。

比较中的通道加法至少扩成 9 位，避免 8 位溢出。阈值、亮度下限和黄色允许色差保留为编译参数；球体反光与原交通灯目标不同，原有 100/150、30/50、60 只能作为标定起点。第一版保留原图/掩膜切换，通过实际球体调节。

暂不串联完整形态学模块。先用 ROI、列噪声阈值和候选面积/尺寸过滤；实拍掩膜证明这些不足时，再增加对应的局部处理。

## 5 分离小球并计算位置

不能按每种颜色统计整幅图的一个框，否则两颗分开的红球仍会合成一个框。第一版采用适合水平单列输送的 X 方向投影。

每列保存红、绿、黄命中数量，以及全部命中像素的 ymin/ymax。帧末按 X 从左到右扫描三色并集投影，将相邻有效列合成一个片段；最多允许合并 `GAP_MERGE` 个内部空列。不同球之间的空列数必须大于该值，并留出阈值误差余量。

每个片段累加三色面积并确定主色，输出一个候选。这样同一颗球表面的少量颜色变化不会自动拆成三个目标。候选包含 `frame_id`、采集配置代号 `config_epoch`、颜色、命中面积、xmin/xmax/ymin/ymax、中心坐标及有效标志。

用最小面积、宽高范围、宽高比和颜色占比排除小块噪声；所有阈值需实拍标定。这是受控背景下的颜色目标检测，不保证区分彩色球与颜色、形状相似的其他物体。

候选边界采用包含最大像素坐标的表示：

```text
width  = xmax - xmin + 1
height = ymax - ymin + 1
cx = (xmin + xmax) >> 1
cy = (ymin + ymax) >> 1
```

这里的中心是检测框几何中心。第一版不计算按颜色像素加权的质心，因而无需为每个目标增加 sum_x/sum_y 除法。

### RAM 与并行更新

四像素输入按 `x mod 4` 分到四个 bank，每拍每个 bank 更新一列。列内每种颜色最多 720 个像素，计数各用 10 位；ymin、ymax 各 10 位，再加有效位，每列约 51 位。

1280 列双缓冲的理论存储为 `1280 × 51 × 2 = 130560 bit`，约 15.94 KiB。这只是数据容量，不能直接等同于实际 ERAM 个数；端口、宽深粒度和综合映射需另验。

一组帧 bank 采集当前帧，另一组扫描上一完整帧。RAM 采用同步读改写流水，不能用异步复位循环清空整片 RAM。可在每个完整帧的第一行覆盖初始化全部列，包括 ROI 外的列；复位后丢弃未完整采集的统计，等待下一次 early 开始完整帧。扫描必须等待末拍 RAM 写入排空，最后一个片段在图像最右列仍要 flush。

超过 8 个合格候选时显式置 `candidate_overflow`。该帧不能继续作为“计数输入正常”处理；视频继续输出，计数门进入阻塞并等待清空。

## 6 单球动态追踪

单球模式只维护一个轨迹槽，状态为 `SEARCH → CONFIRM → TRACK → LOST → SEARCH`。

首次从合格候选中选择面积最大的目标，连续 2 帧确认位置关联及颜色后进入 TRACK。已有轨迹时优先匹配距离上次位置最近、且在最大位移窗口内的候选。颜色由轨迹内部短期确认，不能把颜色编码直接当作球身份。

短暂漏检 1～2 帧时保留上次位置并显示暂失状态，不生成新的测量坐标。第 3 帧仍未找回则回 SEARCH；重新确认后恢复正常框。不能靠持续缩小搜索 ROI 或无限保留旧框掩盖丢失。

第一版不加入速度预测和坐标平滑，方便逐帧核对真实框与坐标。框、十字、颜色文字使用同一份帧快照。流水线模式显示最多 8 个候选框，并可显示当前门内球的坐标，无需为每个显示框分配永久 ID。

## 7 流水线去重计数

在检测 ROI 内设置连续矩形计数门 G，中心线为 `L`。候选中心满足 `cx <= L-HYST` 时属于门内上游区 A，满足 `cx >= L+HYST` 时属于门内下游区 D，中间为迟滞区。A、D 都必须位于 G 内。

初始标定可从 `L=640`、`HYST=16` 和 `G.x=[544,736)` 开始，门的 Y 范围覆盖输送带；这些是待标定示例，不是已经测出的最佳参数。门要足够宽，使球在实际速度下能够被完整帧观察到 A 和 D。

**用候选中心从 A 到 D 的顺序判定通过方向。** 不能仅以球的轮廓同时碰到两条像素带作为通过证据，因为一颗较大的球可以同时覆盖两条带。

计数门同时观察原始颜色并集占用，以及候选框是否与门相交。二者任一存在就不能判断门已清空；候选过滤失败不应立即解锁。原始占用阈值与候选门判断需采用同一帧的 `frame_id`。

| 状态 | 行为与转移 |
|---|---|
| `WAIT_CLEAR` | 复位或清零后先等整门连续空 3 帧，再进 READY；开机时已经压在门上的球不计 |
| `READY` | 一个合格球在 A 连续确认 2 帧且颜色稳定，锁存颜色后进 ARMED；首次仅见 D/迟滞区则进 BLOCKED |
| `ARMED` | 同一门区目标中心到达 D 时产生一次 count_event，进入 HOLD；停留、迟滞区抖动或短暂漏检保持状态；若最终空 3 帧且未过 D，回 READY，不计 |
| `HOLD` | 已计数；颜色改变或球停留都不再次累计；整门空 3 帧后回 READY；此前又确认 A 区候选则置间距或逆行异常，进入 BLOCKED |
| `BLOCKED` | 方向不明、多球同时占门、候选溢出、完整帧统计错误等不产生计数事件；等待整门有效清空后回 READY |

无论在哪个占用状态，都不能因为“过了几秒”自动释放。`ARMED/HOLD` 中 1～2 帧全漏检仅累积空帧数，不重建计数状态。满 3 帧清空才重新就绪。整门完全漏检达到 3 帧后，单靠视觉占用无法保证区分原球与新球，这属于第一版边界。

在 G 内检测到两颗球、稳定颜色无法确认或对象关联条件不满足时，宁可阻塞并提示异常，也不把不确定目标累计为正常球数。计数依赖门内单目标约束，不依赖全画面的追踪 ID。短间距违规若没有形成可分离候选或可观察的 A 区再进入，无法保证自动识别并报警；实际间距仍需用门占用记录验收。

红、绿、黄分项各用 32 位非回绕计数，达到最大值时饱和并提示。总数采用三个分项零扩展后的 34 位求和，避免总数与分项独立更新失配。计数只在已完成帧产生的单拍 `count_event` 时增加。

同色连续两球的正常过程为：

```text
门空3帧 → 红球1在A确认 → 红球1到D，红数+1
        → 红球1停留，计数保持 → 门空3帧
        → 红球2在A确认 → 红球2到D，红数再+1
```

间距需要按帧验证。对单调匀速运动，若门宽为 WG、最大帧间位移为 V、球之间边缘间隙为 S，`S > WG + 4V` 可作为保证至少 3 个采样空帧的保守起点，最终以门占用记录验收。不能把这个例子直接当作实际吞吐率。

## 8 帧边界和显示同步

现有 AWB 的 `tuser` 是提前帧通知，实际工程引用的是 `user_source/hdl_source/awb.v`。原 `video_in` 用这个脉冲复位跨域 FIFO，必须保持独立提前通知路径。应用内部另以首个 valid 生成像素对齐的 SOF。

坐标和打包相位只随 valid 推进。RGB、valid、SOF、EOL、EOF 经过每一级时同拍延迟；不要把 AWB 消隐期的 tlast 直接解释为有效行末。帧统计必须包含最后四个像素，RAM 写入完成后才能启动读扫描。

投影扫描至少需要 1280 个时钟，不能从原模块“帧末至少一个空拍”的契约推出扫描一定赶得上下一个 early。扫描、候选、计数和 OSD 数值转换在旁路完成，不阻塞摄像头像素输入。完成结果通过带 frame_id 的快照原子发布，显示只在随后帧首锁存完整快照；未完成时保留上一份。

模式、阈值切换或清零时递增 `config_epoch`。采集 bank、原始门占用、候选、跟踪/计数输入及待发布结果都携带采集时的同一代号；消费者仅接受当前代，切换前晚到的结果只能释放旧 bank，不能更新状态、推进空门确认或触发计数。同拍清零/切换优先于旧帧完成事件，显示清除旧目标并等待新配置结果。这样旧扫描即使跨过配置切换也不会重新激活已清掉的门状态。

正常设计目标是统计与标记带来可测量的约 1～2 帧延迟，具体取决于扫描完成与帧首的相位；DDR 和 HDMI 的额外显示延迟需实测。框对应历史测量，快速移动时可能有位置滞后。第一版不承诺框与当前像素零帧差。

扫描消费者若未在 bank 重用前结束，置 overrun、丢弃该统计帧并阻塞计数；不背压、不丢摄像头视频。错误帧不当作“空门帧”。停止来帧时，门状态不能按时间自动释放；最后一份显示快照不能视为新的检测结果。

显示层先叠 ROI/门线，再画框与十字，最后叠状态文字。坐标加边框留白时使用饱和裁剪，避免左上角减法下溢。动态数字在帧间用小型顺序二进制转十进制过程准备，像素路径只查字模，不做逐像素除法。

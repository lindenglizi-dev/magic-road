# 小球旋转：RTL结构Python模型

双击 `启动RTL旋转模拟.cmd`，或在本目录运行：

```powershell
python rotation_rtl_model.py
python rotation_rtl_model.py --headless --compare --frames 720
python test_rotation_rtl_model.py
```

这是从RGB实际提取结果的**整数数据通路、双bank所有权和帧事件模型**，用于在编写RTL前验证结构。它不是Verilog仿真，不模拟每个像素有效/空闲周期、RAM端口冲突或安路布线时序，也没有修改bit或操作开发板。

原来的 `rotation.py` 保留，`--compare` 会同时运行它，按同一源帧记录浮点算法对照。两个检测器只接收RGB和采集时间，演示真值只用于渲染输入及离线误差报告。

## 对应的硬件结构

1. 复用 `pipeline.py` 的颜色分割、4×4颜色组件和目标关联。
2. 采集最近已完成追踪结果附近的256×256区域。横坐标4像素对齐，纵坐标2像素对齐；窗口只在SOF选定。
3. 四像素通路可并行计算整数灰度 `(R+2G+B)>>2`；两行合并得到2×2均值，四点求和后加2再右移2位。
4. 存入128×128、8位灰度双bank。每bank16384字节，两bank合计32768字节。Python的调试阶段图副本不属于硬件缓存预算。
5. 同帧实测球框与bank匹配后，以框中心估计球心、短边一半估计半径。在约0.85倍半径内部统计256级灰度直方图，取低中位数，阈值为 `median*115>>8`，约0.449倍。
6. 四连通黑点组件使用512项队列；计算面积、宽高、填充率及偏心距离，必须恰好留下一个合格标记。质心通过32轮整数恢复除法计算为Q4坐标。
7. Q4相对向量经过16轮迭代CORDIC，输出u16相位：65536代表一圈。CORDIC内部使用26位有符号数，其中包括额外小数保护位。
8. s48累计相位、最多32项历史记录、整数最小二乘和96轮恢复除法，输出有符号 `RPM×10`。相对时间右移10位，单位为1024个103.52MHz时钟，约9.89微秒。
9. 顺/逆转计数使用32位饱和计数器，8度方向迟滞；饱和置标志。其他计划寄存器越界会使模型抛错，不能靠Python大整数掩盖。

与原浮点算法的主要差异：2×2灰度降采样、框中心替代最小包围圆中心、四连通替代八连通、整数阈值、Q4质心、CORDIC、整数最小二乘。原算法的合成误差不能直接视为本模型或实板精度。

## 帧匹配和延迟

每次采集记录 `{frame_id, epoch, capture_ticks, window_origin, window_source_frame}`。源帧时间是64位103.52MHz时钟计数，不使用处理完成时间计算RPM。

PRED预测位置只用于决定后续采集窗口。测角时使用同一源帧的**实测**球框。首次找到球后，需要等待窗口设置及后续帧采集，因此启动时无旋转输出是正常现象。

bank在marker_done前始终占用。轮到复用时仍忙则丢弃本次采集并记录 `BANK OVERRUN`，不会覆盖旧bank。缺失采集仍允许原颜色检测继续运行。旋转结果按源帧顺序发布，清零会丢弃旧epoch的所有未完成事件。

模型采用以下**暂定服务时间**做缓冲压力检查：

- 图像行在输入帧周期内均匀到达；这不是对当前MIPI有效信号时序的测量。
- 颜色结果在ROI末行后延迟1,035,271个时钟，这是已有颜色模型最坏测试量级，用作设计压力参数，并非保证的统一硬件延迟。
- 黑点处理按直方图/整窗扫描、每节点24拍、质心和CORDIC/窗口算术预算估算。该预算不是已实现FSM的逐拍结果。
- 实例化时可通过 `color_cycles`、`marker_cycles` 注入更长服务时间；测试包含故意超时的bank压力案例。

因此，本模型可以验证“给定服务时间下会不会覆盖bank、错配源帧或错误累加”，不能证明实际RTL达到60fps或通过RAM端口/时序检查。

视频使用当前RGB叠加最近已完成结果，HUD显示SRC、窗口来源帧和bank；移动时会有统计延迟引起的框位置差。CSV中的角度与原始源帧严格对应，不能拿叠加位置差当作测角误差。

## 场景与无效条件

- 单球、一个哑光偏心黑点、固定轴大致朝向摄像头；不测任意倾斜轴/自由滚动的真实三维转速。
- 球直径80～192像素，建议黑点直径至少10～12像素，放在距球心约0.4～0.7倍半径处。
- 球体必须完整位于原检测ROI和当前采集窗口；框长短边比例不超过1.25。
- 原有颜色分割也必须成功。灰度自适应不能恢复已经被颜色检测漏掉的球。
- `NO MARKER`、`MULTIPLE MARKERS`、`WINDOW MISS`、`BALL CLIPPED`、帧标签错配、队列溢出和bank忙均无新角度，RPM显示为缺失。
- 至少4个有效点、跨度至少0.1秒才能输出RPM，正常平滑窗口约0.3秒。绝对RPM小于2时显示STOP。
- 默认120RPM是必须满足的先验上界。短缺口还须满足不超过0.25秒且最大可能相位变化小于150度；120RPM时缺口须短于约0.208秒。真实超速可能混叠，不能仅靠两帧自动排除。
- 长缺口/跳变只重建参考，不补造圈数，PARTIAL保持到清零。计圈和NET均从首次有效相位开始，启动等待期间不追补。

## 输入与操作

```powershell
python rotation_rtl_model.py --source "D:/videos/marked_ball.mp4" --headless --frames 180 --compare --output output/rotation_rtl_replay
python rotation_rtl_model.py --source 0 --record
```

`--source 0`为电脑可访问的摄像头，不会直接读取FPGA的SC520 MIPI。视频按时间戳/FPS读取，外部输入等比例缩放并填边到1280×720。摄像头使用读取时的单调时间；驱动缓冲延迟尚未标定。

交互：空格暂停，C清零，Q或Esc退出。默认演示无限循环；headless默认720帧。录制文件按固定FPS播放，实际Python处理速度单独记录，不能把视频标称60fps当成软件处理吞吐或实板性能。

## 输出与检查

默认 `output/rotation_rtl/`：

- `rtl_rotation_input.mp4`：纯RGB输入，首个12秒演示为30RPM顺转→停止→45RPM逆转→60RPM顺转，同时平移并短暂隐藏黑点。
- `rtl_rotation_result.mp4`：带窗口、实测球框、黑点和旋转结果的视频。
- `rtl_rotation_trace.csv`：源帧/窗口帧号、采集和完成时间、bank、Q4质心、相位、RPM、圈数、阈值、无效原因；`--compare`追加同帧浮点算法结果。
- `01_input.png`、`02_cached_gray.png`、`03_marker_mask.png`、`04_output.png`、`last_display_frame.png`：实际阶段图。
- `summary.json`：实际误差、有效帧、拒绝原因、处理耗时及范围说明。

`test_rotation_rtl_model.py`检查整数除法/CORDIC、变间隔相位、三色正反转、纯平移、短长遮挡、无标记/双标记、亮度突变、bank超时、清零、帧号错配、窗口脱离、队列溢出、停转反转计圈、灰度存储和计数饱和。结果写入 `output/rotation_rtl_tests/test_report.json`。

下一步RTL需另外验证同步RAM读写冲突、直方图同bin更新、真实有效/空闲周期、所有截止时间，以及安路综合后的资源与完整时序；本次没有替代这些检查。

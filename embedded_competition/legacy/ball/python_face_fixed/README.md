# 人脸启动门禁：Python 定点模型

本目录独立于 `python_face`。保留旧 Python 门禁、小球模型、全部 RTL 和 bit，不覆盖上板工程。
当前是整数算法基准、ROM 导出和计算周期预算，没有编写或验证新增人脸 RTL。

## 运行

本机已有 Python / NumPy / OpenCV，无新增依赖。在本目录运行：

```powershell
python fixed_face.py
python verify_model.py
python gate_demo.py --headless
python gate_demo.py --headless --mode track --frames 240
```

`fixed_face.py` 显式重新导出 ROM；`verify_model.py` 重新导出、加载 ROM，并运行数值验证。
`gate_demo.py` 从 ROM 加载整数检测器，通过带计算延迟的门禁驱动原小球模型；去掉 `--headless` 可以看到窗口，Q 退出。
不自动启动用户摄像头。录像固定 24 fps，只表示播放速度。

## 已冻结的数值契约

完整规则以 `contract.json` 为准。它是本次实现契约，修改后需同时验证实现与重新导出 ROM，不是热配置接口。

- 输入 1280×720 RGB888。引导区是半开坐标 `[512,232,768,488)`；四像素硬件输入的 lane0 对应最高24位。
- 对每个 4×4 RGB 块求三个通道的整数和，计算 `(77*Rsum+150*Gsum+29*Bsum+2048)>>12`，得到 64×64 uint8 灰度。
- 尺度固定为 64、58、53、48、44、40、36、33、30、27、24。每级均由原始64图直接重采样，使用中心对齐 Q8 坐标、双线性 Q16 权重、正数半入舍入。规范窗固定24×24，步长1。
- XML 的25级、2913弱分类器、6383个矩形全部保留，无倾斜特征。矩形权重仅为 `(-1,2)`、`(-1,3)`、`(-1,2,2)`。
- 节点：有符号16位、14位小数。叶值：有符号18位、12位小数。阶段阈值：有符号18位、12位小数。阶段累加器26位。参数舍入采用最近值、半数远离零；溢出报错，禁止静默截断或饱和。
- 普通积分图20位，逻辑零边界不占物理RAM。矩形特征按22位有符号数检查；比较左侧移14位，至少36位有符号宽度。
- 归一化区域是规范窗内部22×22=484点。普通和由积分图四角读取，平方和从冻结灰度串行重读；不建立平方积分图RAM。
- `D=484*sum_sq-sum*sum` 的两个乘积与结果检查34位范围；`D<=484*484*100` 拒绝低对比窗口。根号用17次迭代无符号整数开方，结果向下取整。
- 弱分类器比较为 `feature*16384 < node_q*floor_sqrt(D)`，相等走右叶；阶段分数小于阈值才拒绝。
- OpenCV 读取阶段阈值时的 float32 `1e-5` 修正在导出量化前执行。实际检测阶段不执行浮点模型。
- 坐标映回原ROI时使用正数最近值、半数向上。候选用两两等价关系与并查集合并，eps=1/5用整数交叉乘实现；保留支持数至少6的组，并抑制内部小框。原始候选最多128个，超限整张样本无效，禁止解锁。

## ROM 与后续 RTL 输入

`rom/stumps.mem`：2913行，每行30位十六进制字符，即120bit；位域见 contract。
`rom/stages.mem`：25行，每行10位十六进制字符，即40bit。阶段的起始弱分类器索引由之前阶段数量累加得到。
节点阈值和叶值存二进制补码；所有保留位必须为零。`rom/manifest.json` 保存 XML、契约、两份ROM的SHA256和实际量化误差；检测器检查这些校验后才加载ROM。
原模型 Intel 许可证完整保留在 `rom/LICENSE_OpenCV.txt`，原始 XML 仍在上级 `python_face/assets`。

`reports/vectors` 提供64×64灰度、20位积分图的 `.mem`，以及独立标量回放的逐弱分类器CSV；包含完整通过25级的正窗口和拒绝窗口。
CSV记录特征、D、整数根号、阈值、分支、叶值、阶段累加和窗口累计周期，可作为后续RTL testbench向量。

## 验证如何分层

1. ROM重新加载后与原始模型逐字段比较；验证舍入、溢出、1004个整数开方输入、候选合并边界、重复/过期样本及复位。
2. 定点和同规则浮点参考使用相同ROI、尺度和灰度像素，逐窗口比较拒绝级、弱分类器分支、原始候选及最终人脸框，隔离量化误差。
3. 额外对照 OpenCV 原灰度和定点灰度的检测结果，记录灰度及重采样误差。OpenCV自身搜索调度与舍入不完全相同，其输出不作为定点逐位相等的声称。
4. 独立标量实现用循环、直接灰度平方和与 `math.isqrt` 复核批量整数实现，并导出可回放向量。
5. 门禁用源帧号、epoch、busy和预计完成时间调度。抓帧保守按一个完整60fps视频帧计时，忙时跳过新抓帧；完成3张不同采集帧后才在帧起点启用小球。解锁后停止人脸任务，原计数器先等3个空门帧。

NumPy批量处理仅加快主机验证；不代表硬件有那么多并行端口。Python的中间数组不计作建议的FPGA RAM。
测试仅用同一张已授权公共领域照片的受控变换及合成负例，没有评估多个人、侧脸、遮挡或真实摄像头序列的准确率。

## 周期与资源预算的含义

`contract.json/cycle_schedule` 冻结的是待RTL实现的串行调度假设：同步RAM请求/返回、矩形差分及寄存、乘法/累加、阶段判断均有明确预算。假定没有RAM仲裁等待。
归一化每点3拍，普通积分角点每个2拍，根号17拍；每弱分类器是ROM3拍＋每矩形12拍＋比较累加6拍。
候选聚类含实际并查集父节点访问成本，有限迭代平均坐标和嵌套抑制也计入周期。
独立标量回放验证若干窗口的算术与周期总和；全图计数由实际经过的窗口、弱分类器和阶段数量累计。
最坏上界按所有窗口通过全部级联、最多128候选的最深父节点访问核算。它与样例平均耗时不同。
103.520 MHz来自原小球实现报告，仅作预算换算；新增RTL是否能达到该频率尚未证明。

双灰度缓冲约4块ERAM20K、普通积分图4块、候选120bit模型ROM18块，小计26块；阶段参数、候选记录和外围控制另算。
现有已发布 `ball_motion_20261019.bit` 对应的历史实现报告为71/108块，单按该主存储预算合计97/108。当前目录相对该发布快照已有其他小球修改；这个数字不能当作当前源码或新方案的综合结果，也不证明LUT、DSP、布线和时序一定满足。
没有共享或移除小球存储器，没有改DDR/HDMI。

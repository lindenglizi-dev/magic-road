# 构建与查看说明

参考环境：Tang Dynasty 6.2.168116、PH1P35MDG324 速度等级 3；Vivado 2025.2 用于 RTL 仿真；Python 3.13，上位机依赖见 pc_app/requirements.txt。

## 上位机

运行根目录安装环境.cmd，安装完成后运行启动上位机.cmd。随包不含 .venv，不依赖原开发电脑的 Python 路径。

## 已完成的实现结果

本次位流和完整报告位于 output 与 docs/implementation_20261102。比赛包还带 implementation/checked.db。在 TD 的 Tcl Console 执行 source {解压目录/implementation/view_results.tcl}，然后从 Tools → Chip Viewer 查看芯片。查看脚本只载入已有结果并生成时序查看报告，不执行布局、布线、bitgen 或下载。

数据库中保留原构建路径。源码工程是经过注释和路径整理的交付版，已有结果不是在该交付目录重新运行产生。查看数据库不会自动将原生 Flow Runs 树绑定到新目录；需要查看时序时使用该脚本生成的报告。GitHub 包不含数据库，查看 docs 中的报告和截图即可。

## 从源码重新构建

设置 TD_EXEC 指向 td_commands_prompt.exe，VIVADO_BIN 指向 Vivado 的 bin 目录，然后在根目录执行 python scripts/build_all.py。入口沿用此前移植的相对路径流水线，依次进行仿真、综合、布局布线、双视图时序和独立检查；任何失败停止。本次打包未再次完整执行此耗时流程。

重新构建结果写入 build，位流写入 output/rebuilt/ball_algorithm_rebuilt.bit，保留随包发布的位流。需要另一次重建时使用新的副本。不要将一次运行的中间估值或旧回执用作新结果签核。

实际布局、布线参数见 docs/implementation_20261102/reports 中的 applied_place_params.rpt 和 actual_route_params.rpt；完整构建与检查入口为 scripts/build_all.py。

RTL 仿真：python scripts/run_tests.py。上位机离线回归：python pc_app/tests/test_combined_views.py。数据初始化文件（mem、DDR ROM txt、配置 dat 等）必须保留。工具、许可证及第三方声明按原交付要求处理。

## 文件校验

运行 python scripts/verify_package.py 核对发布文件。仓库沿用按原始字节保存文件的 Git 属性，避免检出时自动转换换行；发布文件、位流及数据库均按原始字节校验。

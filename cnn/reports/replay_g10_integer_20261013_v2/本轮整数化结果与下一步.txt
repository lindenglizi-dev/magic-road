RoadYOLO：真实权重整数化结果与下一步
日期：2026-10-13；本地保存，不提交、不推送。

一、结论

已完成真实监督 replay-G10 权重的完整 Python 整数前向、训练集定标、INT8 参数导出、ROM 物理文件与开发验证。
实现可作为后续 QAT / RTL 对拍的数值起点，但本轮“直接量化（PTQ）”精度不合格，不能作为可用演示模型烧录。
这不是再次训练失败：本轮未训练、未启用 CUDA，原 FP32 权重完全未变。失败的是未经量化训练的直接转换方案。
没有修改生产 RTL、时序约束、原始标签、数据划分或正式验收门槛，没有生成或烧录新位流。

二、已完成内容

1. 复用固定运算图：67 卷积、61 SiLU、12 残差、7 拆分、15 拼接、3 池化、2 最近邻上采样，保留 S4/S8/S16 三头。
2. 只在既有86张训练图上重新观测完整图中间值；17张开发验证图不参与定标。
3. 残差、拼接、拆分、上采样和池化通过等价尺度组对齐；不添加额外硬件重定标单元。
4. INT8 权重按输出通道，INT32 偏置；INT64 精确乘加参考，检查 signed33 部分和安全界及最终 INT32 溢出。
   pre 重定标 → INT16 Q7.8 → SiLU表 → post重定标 → INT8；预测头直接输出 INT16 Q7.8。
   残差按 signed9 加法后饱和，池化 halo 填 -128，RNE、解码、Top128/每类32框/NMS沿用原契约。
5. 导出真实参数140,522字节，物理填充后143,360字节；160位字、14组×4 lane，共56个初始化文件。
   package/numeric_test.bin 与 numeric_test_padded.bin 沿用既有 schema2 消费工具的历史文件名；内容是本次真实权重PTQ包，不是随机权重。
   manifest 明确标识 TRAINED_PTQ_DIAGNOSTIC_NOT_QAT_NOT_BOARD_QUALIFIED。文件完整不代表板卡资源或ROM上电验证已通过。
6. 保存一张真实训练图的所有逻辑中间张量及67层累加/激活前张量到 golden_train0.npz，供后续逐层对拍。

三、验证结果

13项单元测试通过：普通卷积、PW、DW、分组卷积与已有标量黄金模型一致；负数/溢出/残差饱和/池化负值边界；
并验证损坏的字段形状、类型、层偏移、尺度、物理布局和lane文件会被拒绝。
四张训练图：新完整运算图与原FP32模型在预先沿用的 atol=1e-3、rtol=1e-5 下通过，实际误差见 calibration.json。
真实训练图0：独立 PyTorch FP64 卷积核复核全部67层，共6,918,336个累加值，逐项完全一致。
FP64仅用于独立验证：输入、权重、偏置均为整数，绝对和界小于2^32，因此其整数运算精确；正式整数参考路径不依赖浮点卷积。
参数包重新读取后的三个预测头逐项一致；v1和v2的数值结果一致，v2完善了硬件格式与损坏输入检查。
四个新增Python文件AST和尾部空白检查通过。git diff --check在本环境返回“must be run in a work tree”，未冒充通过；分支仍为 work/roadyolo。
最初包测试因系统临时目录权限失败，改为工程内测试目录后通过；未放宽测试断言。负例目录保留，不做批量删除。

四、同一17张开发验证图结果（均为百分数）

                    Precision@0.5   Recall@0.5    AP50       AP50:95
FP32 person              74.42          34.78     47.50       15.09
PTQ  person              33.33          23.91     16.24        5.05
FP32 vehicle             68.33          47.13     50.82       19.37
PTQ  vehicle             13.60          42.53      7.10        1.75

@0.5 是分数阈值0.5；TP匹配IoU也固定0.5。AP使用既有完整分数序列，不是只计算分数>=0.5的框。
两类平均AP50下降37.48个百分点，远超过原1个百分点量化损失门槛。标签、ignore、输入字节、后处理口径与FP32基线逐项核对一致。
这只是17张开发验证，不是正式验收，也未运行独立测试。未通过时不再浪费时间跑旧256图来包装这一版PTQ。
CPU单张整数前向约1.1秒，仅用于参考验证，不能换算成FPGA FPS；没有新的资源、时序或板测通过证据。

五、定位到什么程度

四张训练图的权重量化单独消融和逐层误差表见 layer_diagnosis.json。
图0前三个卷积的归一化RMSE：
                     只量化权重        完整整数路径
stem                      约0.01             约0.08
down2 DW                  约0.02             约0.43
down2 PW                  约0.05             约0.70

仅量化权重的误差明显低于完整整数路径；结合卷积累加独立逐项一致，证据指向激活定标/整数近似误差在网络中累积，
而非当前检查范围内的卷积、通道顺序或存储包读错。
本次对齐组使用 max(abs)/127；第一层步长约0.2503，典型激活只能获得很少刻度。为了不截断极端值牺牲了大部分小值的表示精度。
这不是“INT8必然不可用”的证明，也不能只凭这四张图断言所有损失的唯一原因；必须通过训练集定标改进和部署一致QAT进一步验证。

六、接下来按完赛优先的最小路线

1. 固定这份完整整数参考与对拍输入，不再追加FP32轮数或重复蒸馏。
2. 仅用86张训练图做一次有界的激活定标改进：按尺度组最小化量化重建误差，记录裁剪比例，仍保持INT8对称零点0和所有残差/拼接对齐。
   不通过反复试17张验证图来挑阈值或放宽指标；先检查前三层和三个头在训练图上的误差是否实质降低。
3. 补齐部署一致的QAT前向：真实权重/偏置量化、两次RNE重定标、SiLU表、残差饱和、对齐拼接、INT16预测头。
   现有 prepare_experimental_qat 是不完整路径，继续保持原训练入口的保护，不能把它当作完整QAT直接启动。
   启动QAT前先固定权重做前向对拍，必须与本整数参考逐层一致；不一致先修数值，不进入训练。
4. 对拍通过后才从原监督 replay-G10 建独立短QAT实验，首批上限100次参数更新，每段保存、保留原温度保护。
   不从这份整数输出反推或覆盖FP32原权重；训练时间用前10次实际更新测速；不承诺一次即可恢复精度。
5. QAT导出后在同17图比较；有恢复再做旧256图回归。仍严重退化则停止扩大训练并明确上板精度风险，不伪装通过。
6. 硬件工作可以先使用本轮明确标为诊断用的参数包与黄金张量，验证单层/多层数值、读写顺序和调度；
   用作验证不等于选为最终演示模型。最终QAT权重冻结后仍需重新生成全部关联向量、检查资源/时序/完整DDR闭环及板测。
7. 25号截止、22号功能冻结目标不变；没有完整纯FPGA检测闭环不能以局部模块或PC外算冒充完赛。

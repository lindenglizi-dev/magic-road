结论
----
逐行 diff 只有 o_dst_age_upper_ms 的组合输出 mux 改动，没有其他 RTL 文本差异。该改动修复了计划第五节的遥测歧义：没有 active 表、快照无效、epoch 不符或时间顺序非法时，年龄输出不再伪装为 0 ms，而统一输出 UINT64_MAX（64'hFFFFFFFFFFFFFFFF）作为 unknown sentinel。未发现由该改动引入的新语义缺陷或接口变化。

精确差异与逐项判定
------------------
1. 新版第 326--333 行仅把 age 输出条件改为：
   - !flag_active_present_dst -> UINT64_MAX；
   - !i_dst_time_valid -> UINT64_MAX；
   - active epoch != i_dst_time_epoch -> UINT64_MAX；
   - !flag_timestamp_order_valid -> UINT64_MAX；
   - 其余合法输入继续输出 65-bit age upper 的低64位，若 bit64=1 则饱和为 UINT64_MAX。

2. flag_timestamp_order_valid 的定义未变，仍是 `capture<=completion && completion<=now`。因此 capture 在未来、completion 在未来、或 capture>completion 都落入 unknown sentinel，不会显示为 0 年龄。

3. 合法 age 算术未变：先以 65 bit 计算 `{0,now}-{0,capture}`，再加 65'd4。合法时间顺序下 subtraction 不会下溢；若 64-bit 年龄加4产生 carry，bit64=1，输出继续饱和为 UINT64_MAX。正常未溢出值保持逐位相同。

4. o_dst_draw_valid 逻辑没有改动，仍分别要求 nonempty active、time_valid、epoch/model/status/count 合法、timestamp order 合法和 age upper 合法。sentinel 只是遥测表达，不会把任何原本不可绘制状态变成可绘制。

5. model/status 不符但时间快照、epoch、时间顺序均合法时，age 仍报告可计算的真实年龄；draw 仍为0。这与本次明确要求的 unknown 条件集合一致，没有额外扩大遥测无效范围。

6. 改动不触及时钟、复位、同步器、request/ack、source/pending/active 所有权、RAM、计数、端口宽度或时序状态，因此之前 CDC 状态语义不受影响。新增的三个 OR 条件只位于组合 telemetry 输出锥。

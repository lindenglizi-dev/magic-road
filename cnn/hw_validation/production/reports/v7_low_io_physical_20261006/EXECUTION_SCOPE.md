# RoadYOLO 低 I O 物理验证执行边界

本轮只验证冻结最小计算链在 PH1P35MDG324、速度等级 −3、100 MHz 下的诊断物理实现，不是生产交付。总顶层 I/O 目标不超过 64 位，采用窄口装载动态操作数、控制和完整 SiLU 表，再读取真实缓存结果。

## 执行顺序

1. 冻结四个内部源文件、依赖、表与数值参考的哈希，保持原核及接口不变。
2. 固定测试壳协议和展开 I/O 位数，先做最小 Python 语义参考，再实现壳和 testbench。
3. 基础、尾组、边界、最终故障、复位及部分装载回归；逐项比较真实输出，不以 checksum 替代。
4. 审查现存 374 条严格诊断中的位宽、计数、驱动及组合环风险。保留原始门禁与新壳门禁，不改规则。
5. 功能和语义核查允许诊断后，运行 TD 综合、布局布线及适用 setup、hold、recovery、removal、覆盖率和未约束报告。
6. 核对实际 RAM、DSP、缓存和动态输入路径；分列装载、核心、导出周期及不重叠周期分类。

## 停止条件

需要改内部核、内部接口、数值或复位契约、II、动态系数、严格门禁或时序例外时，停止相关分支，集中说明具体决策。测试壳本身的问题可在独立目录内最小修正并回归，失败证据保留。

## 本地工具边界

复用已安装 ModelSim 官方 PH1P 模型及安路 TD，不请求远程环境。readable-verilog-generator 负责严格 RTL 检查与接口周期图；引用的 readable-python-generator、readable-script-generator 当前未在可用技能清单中，相关 Python 和构建脚本只记录真实自检／工具执行，不能声明其专用技能门禁通过。

最终报告沿用工程内 Markdown 产物；write-page 技能仅用于文字组织与核实，不创建云端 Page。Ponytail 用于复用现有参考与最小测试壳，不省略本轮指定的护栏和验证。

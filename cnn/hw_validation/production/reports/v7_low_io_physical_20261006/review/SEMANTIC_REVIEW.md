# 冻结最小计算链语义与482周期独立复核

## 结论

冻结四源未修改。人工逐段检查和重新运行的 ModelSim 回归未发现已证实的位宽截断、多驱动、组合环、first/last错位、复位旧事务泄漏或缓存提前发布缺陷；这只构成功能语义复核，不关闭严格门禁，也不代替TD物理时序。

当前需要由低 I/O 壳强制执行四个边界：每位置最多24组、首组必须带 `first`、末组必须带 `last`、完整装载1024项表后才允许一次四位置 RUN。本轮只证明一次 RUN/复位；不把未测的连续多 RUN 解释为通过。冻结MAC内部没有组计数器，链在组间MAC空闲时也可能接受表装载，因此这些边界不能交给冻结核自行发现。

## 位宽与协议核查

- `cnt_position` 的2位加一是四位置模4自然回绕，正是冻结契约；VG122在源码421行报告数学结果需要3位，但这里没有丢失合法身份。
- `cnt_channel` 只在 `cnt_channel != 2` 时加一，因此仅发生0→1或1→2；源码434行的VG122同样由值域证明安全。默认分支把异常3当作gamma仍是状态损坏保护，不是合法输入路径。
- `scaled_product` 两个操作数都是 `signed [31:0]`，固定非负因子仍由真实寄存操作数进入乘法，结果完整承载为 `signed [63:0]`。round输出在INT8上下界比较前通过 `signed [15:0]` 重新解释；负值、正值和低8位位型关系正确。
- round核从 `signed [63:0]` 恢复符号后，用有符号64位常量比较 `-32768/+32767`，没有发现无符号比较污染。
- 缓存写基址只取0、3、6、9；`+1/+2` 最大为11。三个数据写入后只在gamma提交边界同时发布三位valid。缓存实体不复位，但复位异步清除全部valid及响应valid，所以旧数据不可见；这解释VG021而不是把它当成旧事务泄漏。
- 没有发现同一寄存器或线网的多驱动，也没有发现组合反馈环。SiLU的统一推进由输出槽可用性控制，pending在同时收发时保持，3位计数覆盖当前最多六级在途容量。
- MAC对 `first/last` 只做协议消费：`first`选择偏置，`last`决定终态；它没有内部组数上限检查。低I/O壳必须维护1..24的组计数并拒绝错误次序，不能宣称核支持无限归约。

## 374条严格诊断的真实分类

严格状态保持：`delivery_ready=false`、374 errors、0 strict warnings。公共门禁为：compile/profile/testbench通过；ast/readability/comment/naming失败；toolchain在该门禁运行中为not_requested。单独的ModelSim证据见后文。

| 分类 | 数量 | 判断 |
|---|---:|---|
| 排版、注释、命名、区域、字面量及结构规范 | 210 | 真实交付门禁问题，但不是本次发现的功能错误；不放宽、不改冻结核 |
| VG122计数加一 | 2 | 值域证明合法：模4位置回绕、受限通道递增 |
| 确定超过检查器组合复杂度预算 | 11 | VG145七项、VG146四项；是结构/收敛风险，不能当作已测时序违例 |
| 源闭包缺失或检查器未能解析 | 151 | VG146外部接口66、VG147外部接口66、VG146存储表达式4、VG153子模块输出15；不能据此声称无驱动 |

原报告虽传入三个 `external-interface-source`，但公共结果仍记录 `files=1/modules=1`，所以对子模块输出和跨层操作锥的151项结论不完整。它们仍阻塞严格交付，但物理时序只能由本轮TD网表和STA回答。

四个可确定VG146超预算目标是缓存响应数据enable（7次操作）、缓存故障D（5）、缓存故障enable（4）和缓存valid enable（6）。七个VG145集中在MAC门控ready/valid和下一状态组合源数。这些是本轮布局布线后应重点查看的路径，不构成预先宣判失败。

## 原基础482周期分解

新增监视器作为ModelSim第二顶层，只层级读取原测试平台和冻结DUT，不驱动任何信号。重新编译0 error/0 warning；运行得到原厂RAM模型2条既有 `INIT_FILE` 越界告警、0 error，同时保留：

```text
REVIEW_MONITOR base16_start=1033 base16_end=1515 endpoint_difference=482 responses=12
TB_PASS_CHAIN mac=9 pre=27 silu=27 post=27 read=27 atomic_hidden=18 reset=6 directed=1 errors=0
```

采用半开区间 `[start,end)`，每拍只归入一个类别：

| 类别 | 周期 | 定义与等待组成 |
|---|---:|---|
| MAC | 84 | 四位置各21：首组接收到次组接收11，末组接收到链终态握手10。MAC valid在前一边沿已可见，下一边沿由链采样，不代表MAC内部延迟变化 |
| 前重定标 | 132 | 十二通道各11：边界交接、PREPARE、PRE_SEND及round等待；round从发送到可消费为9边沿 |
| SiLU | 84 | 十二通道各7：前round端点到SiLU输出端点，包含输入发送及流水等待 |
| 后重定标 | 120 | 十二通道各10：SiLU输出端点到后round端点，包含操作数登记、发送及9边沿round |
| 原子提交 | 12 | 四位置各3：末通道post端点到gamma提交端点 |
| 位置切换 | 3 | 前三个gamma提交端点到下一位置首输入各1 |
| 缓存读回 | 47 | 最后gamma提交端点到第十二个响应消费端点；请求后一拍响应，原TB每4拍发一个请求 |
| 合计 | **482** | 类别互斥，无重叠重复相加 |

用原状态编码对 `[1033,1515)` 的独立计数为：ST_MAC 134、PREPARE 12、PRE_SEND 12、PRE_WAIT 108、SILU_SEND 12、SILU_WAIT 72、POST_SEND 12、POST_WAIT 108、三个COMMIT状态各4，总计482。事件边界分解与状态计数相互闭合。

这里的“前/后重定标周期”包含控制登记和等待，不等同于每拍都在做新算术；当前串行单上下文是吞吐损失的主体。预装载1024次表写不在482内，窄口壳的新装载和导出周期必须单列。

## 监视器门禁与证据边界

新增监视器在ModelSim中编译和执行通过。严格检查器对这种无端口、跨第二顶层层级引用的监视器返回 `only single module sources are currently supported`，并连带产生120 errors；因此监视器自身 `delivery_ready=false`，失败报告已保留，没有用仿真通过替代严格门禁。

本报告没有修改冻结内部核，也没有建议改变II、数值、复位或接口。下一步物理实现应优先查看缓存响应门控、MAC输入门控和FSM下一状态路径；如果TD证明这些是最差路径，再单独提出是否允许内部修正。

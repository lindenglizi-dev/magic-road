1 概述

    本文描述了静态时序分析(Static Timing Analysis)涉及的基本概念、命令及原理，介绍了
TangDynasty®（以下简称 TD 软件）软件时序工具支持的时序约束命令，详细阐述了命令的参数、使用
和示例。另外针对典型的场景进行了时序约束的分析与示例。


2 时序约束基本概念

    本节介绍静态时序分析(Static Timing Analysis)涉及的基本概念。


2.1 主时钟(Primary Clock)

    主时钟是指通过外部输入引脚进入 FPGA 内部的时钟。

    该时钟进入到 FPGA 内部后，TD 综合时会产生相对应的网表名字，该网表名字表示设计中的所有该
时钟的扇出对象都从该点开始时序分析。这个点是主时钟的源点，它定义了 TD 时序分析工具中的时钟
延迟和不确定性时使用的时间零点位置。

    主时钟的对象是外部输入管脚，其中包含 FPGA 内部的硬核单元输出管脚，比如 serdes 的恢复时
钟、内部振荡器时钟等。


2.2 虚拟时钟(Virtual Clock)

    虚拟时钟是指在物理上未连接到 FPGA 任何网表对象的时钟。

    一般情况下虚拟时钟用于指定输入和输出 I/O 延迟的约束。比如，输入 FPGA 的 I/O 的时钟没有实
际存在于 FPGA 中；不修改内部时钟特性，只改变 I/O 的延迟，限制相关的 I/O 指定不同的延迟。


2.3 生成时钟(Generate Clock)

    生成时钟在 FPGA 内部通常由 PLL、某些用户逻辑或硬核时钟单元电路产生的。

    生成时钟是由主时钟派生的。使用 create_generation_clock 命令进行生成时钟的约束，描述生成
时钟如何转换的主时钟，不仅仅是描述其周期或者波形。

    主时钟与生成时钟之间的关系如下：

   整数分频

   整数倍频

   小数倍频，一般由 PLL 完成

2.4 时钟组(Clock Groups)

    时钟组是将用户指定的时钟按照时钟域划分为不同的小组，分好时钟组后时序工具将不分析时钟
组与组之间的时序路径。

    TD 时序分析工具默认情况下会对设计中所有时钟之间的路径进行时序分析，如果使用了时钟组或
无效路径进行了约束，将不分析时钟组间和无效路径的相关路径。


2.5 时钟延迟(Clock Latency)

    板上时钟源经过 PCB 板子和 FPGA 器件内部的走线传输，时钟到达目的单元后会有一个确定的延迟，
这个延迟称为时钟延时。该延迟可以分为两个部分，一个是源端延迟，另一个是网络延迟。

    源端延迟指在 FPGA 器件外，时钟源进入到 FPGA 源点前的传输延迟，这部分延迟与 PCB 设计相关，
需要用 set_clock_latency 命令进行约束。

    网络延迟指时钟在 FPGA 内部走线带来的延迟。TD 时序分析工具会自动分析计算该延迟，布线后可
以得到一个精确的值。对于生成时钟，包含其本身的网络延迟和上级时钟的网络延迟两部分。


2.6 时钟不确定性(Clock Uncertainty)

    使用 set_clock_uncertainty 命令可以根据需要为不同的 PVT 的芯片定义时钟的不确定性。从时
序的角度来看，这是一种为设计的时序增加额外裕量的方法。主时钟的不确定性不会传播到下游生成的
时钟。


2.7 输入延迟(Input Delay)

    set_input_delay 命令指定相对于设计上的时钟沿在输入端口上的输入路径延迟。输入延迟表示数
据从外部芯片通过电路板传播到 FPGA 的输入引脚和参考板时钟的相位差。输入延迟取决于发送时钟沿
和数据的相对相位。

2.8 输出延迟(Output Delay)

    set_output_delay 命令指定相对于设计上的时钟沿在输出端口的输出路径延迟。此延迟表示数据
从 FPGA 的输出引脚通过板子传播到另一个设备和参考板时钟的相位差。

    输出延迟值可以为正或为负，正负只表示相对时钟沿的位移方向，具体取决于 FPGA 外部的时钟和
数据相对相位。


2.9 多周期路径(Multicycle Paths)

    通常情况下，两个同步的寄存器进行 Timing Check 时，组合逻辑的延迟必须在一个时钟周期内到
达，才能满足 setup 的时序要求。在某些情况下，从一个寄存器输出到另外一个寄存器的数据端可以允
许不止一个周期的时间，而且又不影响逻辑的功能。此时，我们可以将这样的路径约束为 Multicycle
Path。

    多周期路径的约束允许用户根据设计时钟波形来修改原来确定的建立和保持关系。默认情况下，TD
时序分析工具执行单周期分析。这种分析可能过于严格，不适用于某些逻辑路径。典型的例子是组合逻
辑路径，需要多个时钟周期才能使数据稳定在端点上。


2.10 无效路径(False Paths)

    false Path 是在进行综合分析时，不希望综合工具进行分析的那些路径。可从下面两种角度进行
分类：

   从逻辑上考虑，与电路正常工作不相关的那些路径，比如测试逻辑，静态或准静态逻辑。

   从时序上考虑，在综合时不需要分析的那些路径，比如并不存在真实逻辑关系的跨越异步时钟域的
    路径。

    建立 false path 的方法有两种方式实现:

   set_false_path 约束在涉及到特定节点时使用；

   set_clock_groups 约束在涉及到时钟域时使用。

    在具体实现过程中，系统将自动识别经过用户指定的这一段路径相关的所有完整路径，并在时序分
析和优化时将其忽略。通过提前设定合理的 false path，可以指导软件将优化的主要目标放在真正关
键的路径上。

   添加了双重同步器逻辑的时钟域交叉点

    本节介绍了获取对象的各种方式，包括时钟、节点、输入管脚、输出管脚等对象。

    本节涉及的对象获取指令如表 3-1 所示，后文将对每条指令的选项和使用进行详细介绍。

                             表 3-1 对象获取命令表

             命令                                 描述
          all_clocks                     返回设计中的所有时钟
          all_inputs                返回设计中的所有输入和双向端口
          all_outputs               返回设计中的所有输出和双向端口
      all_registers                     返回设计中的所有寄存器
          get_ports           返回设计中的用户指定的输入、输出和双向端口
          get_cells                    返回设计中的指定单元实例
           get_nets                      返回设计中的指定线网
           get_regs                     返回设计中的指定寄存器
           get_pins                返回设计中的端口或单元的指定引脚
          get_clocks                   返回设计中用户指定的时钟



    时序电路中包括 cell、reg、pin、net 和 port 在内的多种节点，在与时钟约束和时序路径约束嵌
套使用的过程中需要根据实际应用情况选择合适的节点。它们之间的相互关系如下：

   cell 一般指在代码中实例化的模块（inst），或者是综合后网表中的 LUT、RAM、DSP 以及 PLL 等；

   reg 指模块中的寄存器；

                                               ；

   net 即 pin 与 pin 之间的连线；

   port 在顶层文件中声明的输入输出端口，即 FPGA 外部的芯片进行通信的管脚。

3.1.8 get_nets

   命令参数：

   get_nets [-hierarchical] [-hier] [-nocase] [-nowarn] [-o] <filter>

   参数释义：

   -hierarchical 或-hier:表示层次化搜索，将在每一层次的模块中匹配对应名称（在 TD 中用“/”
来区分层级）

   -nocase：表示不区分大小写

   -nowarn：表示没有匹配成功时也不给出警告

   -o：表示返回转译后的名字，TD5.6 版本之后新加功能，必选项。

   <filter>：被匹配的目标字符串名称

   使用说明：

   返回连接到端口或引脚的实例。支持输入多字段，格式如下：get_nets { A* B* C* }。在一个实
际的设计中，系统中的模块（module）之间会有层次化的结构，上下层模块可能嵌套使用，用“/”来
表示它们之间的关系。如 get_cells 所述，使用“/”来描述打平状态下的模块之间的调用关系，如 B/Z。

   TD 中的 nets 可以简化分为以下三类（以下三类按命名优先级排序）：

1. 与输入输出 port 相连的 net，由输入输出 port 命名；

2. 与寄存器的输出 Q 端相连的 net，由寄存器的名字命名（与源文件中 reg 类型的变量名对应）。此
   时 net 和 cell 一样具有层级结构，具体寻找模式请见下文。

3. 由用户在 verilog 中定义的 wire 型 net，由 wire 名命名。

   要注意的是，以上三类 net 中，除了顶层模块的输入输出相连以及与寄存器输出相连的 net，其
他 net 都有可能在 RTL 和 gate 的综合过程中被优化而不再存在，而在优化过程中也可能产生大量源文
件中没有的信号，所以不推荐试图用这些名字来搜索 net。

   在以上三类 net 中，第 2 类 net 由于与寄存器（每个 reg 都可以看成一个 cell）相关，所以和 cell
一样具有层级结构，隶属于某一层 module。

3.2.2 参数释义

    -name {<clock name>}

    用于指定时钟名字，该名字将用于时序分析和其它时序约束命令中的使用。该参数不能省略，否则
报错。

    -period <time ns>

                        ，数值为正，数字格式是保留小数点后三位。
    用于指定时钟的周期，时间单位为纳秒（ns）

    -waveform {<rise time ns> <fall time ns>}

   用于指定时钟第一个上升沿与第一个下降沿的时间点，可以指定不同相位或者不同占空比，时间单

4 静态时序分析原理

  本节介绍静态时序分析(Static Timing Analysis)涉及的基本原理。


4.1 基本时序概念

4.1.1 建立时间(Setup time)

  数据信号必须在时钟沿之前稳定的最小时间称为建立时间(Setup time)，通常简写为 Tsu。


4.1.2 保持时间(Hold time)

  数据信号必须在时钟沿之后稳定的最小时间称为保持时间(Hold time)，通常简写为 Th。


4.1.3 恢复时间(Recovery time)

  异步信号变为非有效状态和下一个时钟沿之间存在的最短时间称为恢复时间(Recovery time)。


4.1.4 移除时间(Removal time)

  在有效时钟边沿和异步信号释放之间的时间称为移除时间(Removal time)。


4.1.5 源时钟(Source clock)/发送时钟(Launch clock)

  发起数据的时钟称为源时钟(Source clock)，也称为发送时钟(Launch clock)。


4.1.6 目的时钟(Destination clock)/捕获时钟(Capture clock)

  捕获数据的时钟称为目的时钟(Destination clock)，也称为捕获时钟(Capture clock)。


4.1.7 发送沿(Launch edge)

  源时钟发送数据的时钟沿称为发送沿(Launch edge)。


4.1.8 捕获沿(Capture edge)

  目的时钟捕获数据的时钟沿称为捕获沿(Capture edge)。


4.1.9 到达时间(Arrival time)

  数据从发送到捕获之前所经过的延时称为到达时间(Arrival time)。

SWUG200                    www.anlogic.com                     40

2024.09
                                                                                    TangDynasty®时序约束用户手册

4.1.10 要求时间(Required time)

         数据发送后能被安全捕获的最差时间点称为要求时间(Required time)。


4.1.11 建立检查(Setup check)

         经时序分析工具验证的建立时间检查称为建立检查(Setup check)。


4.1.12 保持检查(Hold check)

         经时序分析工具验证的保持时间检查称为保持检查(Hold check)。


4.1.13 恢复检查(Recovery check)

         异步复位信号经时序分析工具验证的建立时间检查称为恢复检查(Recovery check)。


4.1.14 移除检查(Removal check)

         异步复位信号经时序分析工具验证的保持时间检查称为移除检查(Removal check)。


4.1.15 时序裕量(Timing Slack)

         在进行建立检查/恢复检查和保持检查/移除检查后，得到的数字称为时序裕量(Timing Slack)。当
时序裕量大于等于零时，时序才满足要求。

4.3 时序路径分析与计算

4.3.1 概述

    时序路径的计算是静态时序分析(Static Timing Analysis)的核心内容，静态时序分析的目的在
于验证 FPGA 加载位流后，其时序行为的可预测性。由于受到制造 FPGA 器件的工艺材料和使用 FPGA 的
环境变化因素的影响，在静态时序分析时会对多种场景的延迟模型进行考量。一般情况下要考虑以下四
种情况：慢速角点(Slow Corner)中的最大延迟分析；慢速角点(Slow Corner)中的最小延迟分析；快速
角点(Fast Corner)中的最大延迟分析；快速角点(Fast Corner)中的最小延迟分析。


SWUG200                               www.anlogic.com                     43

2024.09
                                                                        TangDynasty®时序约束用户手册
   在执行建立检查和恢复检查时，参考角点的最大延迟进行分析，才能按照最恶劣的情况进行时序路
径的分析。在慢速角点(Slow Corner)中，源时钟路径参考 Slow max，数据路径参考 Slow max，目的时
钟路径参考 Slow min。在快速角点(Fast Corner)中，源时钟路径参考 Fast max，数据路径参考 Fast
max，目的时钟路径参考 Fast min。

   在保持检查和移除检查时，参考角点的最小延迟进行分析，才能按照最恶劣的情况进行时序路径的
分析。在慢速角点(Slow Corner)中，源时钟路径参考 Slow min，数据路径参考 Slow min，目的时钟路
径参考 Slow max。在快速角点(Fast Corner)中，源时钟路径参考 Fast min，数据路径参考 Fast min，
目的时钟路径参考 Fast max。

5.3 时序例外约束

5.3.1 伪路径（false path）约束

    伪路径的约束可以减少时序分析工具的运行时间。当从时序分析中删除伪路径时，TD 不需要对这
些路径进行分析或者优化，同时提高结果质量（QOR），如果一些伪路径存在时序违例，TD 可能会尝试
修复这些路径，而不是在真正的功能路径上工作。

    示例一：删除从复位端口到所有寄存器的时序路径

    set_false_path –from [get_port reset] -to [all_registers]

    示例二：约束两个异步时钟路径

    set_false_path -from [get_clocks async_clk1] -to [get_clocks async_clk2]

    set_false_path -from [get_clocks async_clk2] -to [get_clocks async_clk1]

5.3.3 最大/最下延迟（Max/Min delay）约束

   对于那些从 FPGA 管脚进入或输出都不经过任何时序元件的纯组合逻辑路径可以用 set_max_delay
/ set_min_delay 来约束。

   比如约束所有端口输入到输出的最大延迟 40ns,最小延迟 10ns，示例：

   set_max_delay 40 -from [all_inputs] -to [all_outputs]

   set_min_delay 10 -from [all_inputs] -to [all_outputs]

   异步 fifo 中跨时钟域寄存器的走线延迟约束，set_max_delay 命令+ datapath_only 进行约束。示
例详情见 5.3.2 小节。

   当使用寄存器跨时钟同步时，set_max_delay 命令通常用于定义跨时钟域的时序约束。假设两个寄
存器（REG1 和 REG2）由不同的时钟驱动，并且 REG2 的输入连接在 REG1 的输出，且此连接的延迟限制
为最大 1ns，示例：

   set_max_delay -from [get_regs REG1] -to [get_regs REG2 ] -datapath_only 1

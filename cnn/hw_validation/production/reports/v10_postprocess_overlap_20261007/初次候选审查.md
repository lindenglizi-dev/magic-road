# 初次候选审查（问题必须在验证前关闭）

这是新候选源码的只读检查，不是冻结算术核的修改请求，也不是通过报告。

1. `road_postprocess_stream` 结果队列同时发生“新整组入队”和“队首的非末路进入前重定标”时，入队分支原先没有清掉队首已消费的 lane bit。这会重复送 alpha/beta。实现者需在该收发组合保持队首载荷、只清消费位；新增定向测试覆盖，不由最终饱和值巧合掩盖重复。
2. 新包装器原先只用 SiLU 局部 pending 判断表装载许可，而前级、后级和结果队列也可能在途。必须使用全链空闲条件约束整表重载，并在未装满 1024 项时禁止接收/启动计算。新增部分装载及各级在途换表反压测试。
3. Python 首版 SiLU 参考在地址 1024 时错误夹到 1023。原 RTL 在该上端点明确输出 2047。参考已修正为读取冻结 LUT，并单列上端点分支；保留首版运行记录，不能以首版自检没有触及该值宣布全域一致。
4. 初版将前系数按最终 channel mod 3 选取，仅对 3 对齐的整组起始通道成立。候选接口冻结为对齐 base + 显式 lane mask，实际系数取 serializer lane；DW floor(channel/3)*3 + onehot、PW group*3 +111。禁止静默允许不对齐 base 而选错系数。
5. 增加全链换表围栏后，不能因为外部尚未握手的 `table_valid` 持续为高就停止已经入队的旧数据，否则“必须空队列才能换表”和“等待换表禁止队列排空”形成死锁。应停止新整组接收，继续排空旧令牌，空链后才接受表地址零。定向测试必须保持换表请求直到 ready，而非只脉冲一拍。

以上问题需以修正后的源码哈希、定向回归及完整 DW/PW 对拍关闭。原版结果、失败日志留存，不覆盖 v9。

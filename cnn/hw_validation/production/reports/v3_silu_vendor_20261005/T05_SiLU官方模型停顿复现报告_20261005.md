# T05 SiLU 官方模型停顿复现报告

日期：2026-10-05  
范围：完整 `silu_shared_unit`、官方加密 `PH1P_LOGIC_ERAM`、官方 `PH1P_PHY_GSR`、ModelSim 功能仿真。未修改生产 RTL，未运行 TD、SDF、综合、布局布线、训练、位流或 Flash。

## 结论

生产 RTL 的停顿错位故障已确定复现。无反压时 9/9 事务通过；中央查表区连续输入 `0/4/8/12`（地址 `512/513/514/515`，表值 `0/2/4/6`）后，只冻结 1 个上升沿，第二个事务 `raw=4, address=513` 即从期望值 `2` 错为后续地址 514 的值 `4`。16、32、64 拍反压得到相同错位；各次仍为 accepted=9、received=9，说明本用例是数值错位，不是丢失或重复。

逐拍根因：冻结前控制地址 513 与 RAM 数据 2 对齐；冻结时控制仍停在 513，但生产 RTL 的 RAM `CEA=1`，RAM 输出前进到地址 514 的数据 4；恢复后该数据被当成地址 513 的响应发送。

协调代理隔离候选仅把 `CEA` 接到 `flag_pipeline_enable`。在独立 `candidate_work` 库中，0/1/16/32/64 拍全部 9/9 通过；既有 65,536 输入黄金 testbench 通过（latency=5、II=1、1024 表项），其中包含三拍停顿、pending 排空后重载、运行中复位取消及再次完整装表；另有固定 seed 42 的 4,096 输入随机反压通过，accepted=received=4096、冻结 1,353 拍、最长连续冻结 7 拍。

这只证明候选在本次官方功能模型覆盖内有效，不是生产合入、物理 ERAM 映射、时序、硅片或板级签核。

## 覆盖与边界

- 完整表装载：每次 1024 项；未装完时输入关闭；pending 非零时重载关闭；排空后重载开放。
- 查表与旁路：中央 A/B/C/D、负尾 `-2048`、地址 0 的 `-2047`、地址 1023 的 `2044`、地址 1024 常量路径的 `2046`、正尾 `2048`。
- 原版反压：0、1、16、32、64 拍；候选同矩阵全部复跑。
- 候选数值：全域 65,536 输入；随机反压为中央域 `[-2048, 2047]` 的 4,096 输入，seed 42。
- DUT 没有 tag 端口，因此不能验证 tag；testbench 只能用外部事务序号检查顺序与守恒。
- 官方模型新优化时保留 2 个 `vopt-2697` 告警，来自 `ph1p_logic_eram.v:165` 的 `INIT_FILE` 越界 part-select；未静默忽略，也未解释为硬件保证。

## 最小修复建议

候选 `CEA=flag_pipeline_enable` 与故障根因一致，并在本批官方模型功能测试中通过。合法装表仅在 pending 为零时开放，此时输出 valid 为零、pipeline enable 为一；随机 testbench 也断言了每个表握手时 RAM enable 为一。是否合入仍应由主任务完成严格 RTL 门禁，并在需要时另做 TD 映射与时序验证。

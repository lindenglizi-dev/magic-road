# RoadYOLO T02/T03 时钟与复位只读诊断

日期：2026-10-05  
角色：`review`  
范围：冻结的 `round_internal_baseline_20261005/pr.db`、四份输入 RTL、原始时序报告及本轮只读导出。未修改生产 RTL、SDC、ADC 或工程配置；未重新综合、布局、布线、仿真、训练、bitgen、下载或写 Flash。

## 1. 结论

1. `99.56%` 仍不能提升为全覆盖结论。安装版 SWUG201 只把该字段定义为 STA coverage，没有公开本报告的分母或未覆盖对象清单；不能用 `2953` 个端点、`6452` 条路径或一个 dummy node 反推缺失数量。
2. 原始同次 route 会话中的 `check.timing` 报告 `probe_clk` 为 1 个 local clock，并同时报告 1 个 generated clock 无 master；从完全相同的 `pr.db` 重新导入后，default 与 verbose `check_timing` 都变成这两项为 0。物理网表只有 `i_clk PAD -> 1 个 GCLK -> 4 个自动 SCLK`，没有独立 RTL 生成时钟。该差异是 TD 报告上下文相关，不能称为已修复，也没有证据支持改 SDC。
3. `_al_n1_syn_76.ofb` 是常量 1 LUT 的输出。其 net `_al_n1_syn_75` 只连接两个 `PH1P_PHY_SHIFTERHARDCON.depth` 静态配置端，不进入 round 的有效数据、valid、tag、fault 或推进控制锥。按 SWUG201 对 const-LUT/config 类 dummy 的说明，此项可解释为静态配置节点，不需要 false path；若 TD 技术支持认为 `depth` 应纳入时序图，再重新分类。
4. `SYN-5084` 来源明确：`flag_source_active` 声明初值为 0，异步低有效功能复位分支赋值为 1。TD 明确忽略初值 0，网表把该寄存器实现为异步 SET。完整探针批次依赖至少一次真实功能复位；本轮没有证明“不经过外部复位也可自主启动”，不得只为消告警机械改复位值。
5. `reg_reset_release_reg_syn_3.asr` 不是可按名字解释的“第三级”。综合网表把 RTL 的第一拍 `reg_reset_meta` 与第二拍 `reg_reset_release` 打包进同一个双寄存器 `PH1P_PHY_LSLICE`：`QB=reg_reset_meta`，`QA=core i_rstn`，两者共享 `.asr(i_rstn_dup_1)`。
6. 唯一全局 removal 仍是外部 `i_rstn -> 共享 ASR`，slack `-1.376 ns`。同步器级间 setup/hold 为 `+9.610/+0.108 ns`；同步释放根到 641 个功能寄存器异步端的最差 recovery/removal 为 `+4.264/+0.156 ns`，均为正。

### 时钟物理拓扑

```text
i_clk PAD (i_clk_syn_2)
  -> i_clk_dup_1
  -> PH1P_PHY_GCLK i_clk_dup_1_created_gclkinst
  -> i_clk_syn_3
  -> 4 x PH1P_PHY_SCLK_V2 (s_0_l, s_0_r, s_1_l, s_1_r)
  -> sequential endpoints
```

`check.timing` 的原会话告警只给出逻辑名 `probe_clk`，没有指向一个独立 local/generated clock 实例。重导入同库后该告警消失，因此不能据此创建 generated clock 或 master 关系。

## 4. SYN-5084 启动语义

- 源码声明：`road_round_internal_probe_core.v:95`，`flag_source_active = 1'd0`。
- 异步复位行为：同文件 `:264-268`，复位时写 `1'd1`，随后只在推进时于固定批次末尾清零。
- TD 日志：`SYN-5084` 明确写“Ignore the initialization value '0'”。
- 路由网表：`routed_netlist.v:4868-4895` 使用 `REGA_REGSET_ASYNC("SET")`，证明实际实现遵循复位值 1，而非声明初值 0。

处置：当前探针功能语义要求真实复位激活批次，因此不应把复位值改成 0。若未来希望无外部复位自主启动，需单独定义器件上电寄存器语义、时钟稳定条件和批次起点，并重新做功能与物理验证；本轮没有这项证据。

## 5. T03 精确复位拓扑与路径分类

RTL 语义：

```text
external i_rstn (async low)
  -> reg_reset_meta      (第一拍，async assert, sync deassert)
  -> reg_reset_release   (第二拍，async assert, sync deassert)
  -> core i_rstn
  -> 641 个功能寄存器 ASR 端
```

综合网表映射：

| 逻辑对象 | 同一物理实例中的端口 | 网表证据 |
| --- | --- | --- |
| 外部 `i_rstn` | `.asr(i_rstn_dup_1)` | `routed_netlist.v:29608-29610` |
| 第一拍 `reg_reset_meta` | `D=.imb(1'b1)`, `Q=.oqb(reg_reset_meta)` | `:29611-29614` |
| 第二拍 `reg_reset_release` / `core i_rstn` | `D=.ima(reg_reset_meta)`, `Q=.oqa(core i_rstn)` | `:29611-29614` |

因此综合网名 `reg_reset_release_reg_syn_3.asr` 是双寄存器 slice 的共享异步端，不能凭 `_syn_3` 称为第三拍，也不能说它只属于第一拍或第二拍。

| 检查范围 | 端点数 | 最差结果 | 决定 |
| --- | ---: | --- | --- |
| 外部 `i_rstn` -> 共享 ASR | 1 | recovery `+9.991 ns`；removal `-1.376 ns` | 唯一未关闭项 |
| 第一拍 QB -> 第二拍 D/IMA | 1 | setup `+9.610 ns`；hold `+0.108 ns` | 必须保留检查，当前通过 |
| 第二拍 QA -> 功能 ASR | 641 | recovery `+4.264 ns`；removal `+0.156 ns` | 必须保留检查，当前通过 |

注：`reset_release_to_function.rpt` 的集合共 642 个端点，包含 1 个级间 D 端和 641 个功能 ASR；本表按路径类型拆开，未把级间 hold 当作功能 removal。

## 6. 最小例外候选（未实施）

SWUG105/200 说明 `set_false_path -hold` 只作用于 hold/removal，`-setup` 只作用于 setup/recovery。若板级复位契约与安路支持共同确认，可在导入 routed DB 的验证脚本中试验以下最小对象集合：

```tcl
set_false_path -hold \
  -from [get_ports {i_rstn}] \
  -to [get_pins -hier {road_round_reset_gen_Inst_release/reg_reset_release_reg_syn_3.asr}]
```

该候选只意图忽略“外部异步释放 -> 同步器共享 ASR”的 removal，不忽略：

- 外部入口 recovery；
- 第一拍到第二拍的数据 setup/hold；
- 第二拍同步释放根到 641 个功能寄存器的 recovery/removal；
- 任何普通寄存器到寄存器 setup/min。

但它目前不能直接进入生产 SDC，原因如下：

1. `.asr` 是两个逻辑同步级共享的物理端，例外会覆盖两级的外部异步 removal，而不是“只覆盖第一级”；该物理语义需安路确认。
2. 该综合网名可能随综合变化，且 `build.tcl` 在 gate 优化前、legalize 后各读取一次 SDC；需确认对象在生产约束读取阶段可稳定解析。
3. 需要板级确认 `i_rstn` 来源、有效低最短脉宽、上电时是否必然断言、时钟何时稳定，以及复位释放后至少两个有效上升沿的保证。
4. 未取得以上确认前，保留当前 `-1.376 ns` 为未关闭边界，不扩大到 `i_rstn -> 全设计` 的 false path。

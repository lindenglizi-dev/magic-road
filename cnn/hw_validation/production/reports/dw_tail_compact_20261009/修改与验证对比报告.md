# 退休结果银行与 DW 行尾两项修改：实际验证报告

## 1. 未通过项先说明

1. **B（DW 行尾两组候选）未通过 100 MHz 内部时序。** 主覆盖违例报告有 5 个内部 setup 失败端点：4 个预处理 tag→累加数据寄存器使能，最差 −0.528 ns；另 1 个故障状态→DW 缓存写使能，−0.449 ns。专项功能复位分发还报告 4 条 setup 负路径，最差 −0.082 ns；它们与上述 4 个累加寄存器终点重合，不应相加成 9 个不同端点。
2. A/B 外部窄口 setup/hold 和原始复位入口 removal 仍未签核。诊断 SDC、自动引脚未变；不能改输入延迟或加例外把结过。果写成通
3. 严格交付门未闭合。新增验证通过不抹除原记录，当前代码仍非生产交付。
4. 本次未接真实 QAT 包、全图 DDR 或板测，不能证明整网 5 FPS 或识别精度。
5. 三套新构建均不再出现旧 HDL-5314 多驱动告警，但 SYN-5025 全部置零对象尚未逐项定位，未放行；门级同向量数值仿真也未完成。不能将结构证据称为完整门级等价。

**阶段决策：保留 A 为本轮内部时序通过的诊断参考；B 保留功能通过但物理失败的候选，不提升为基线、不覆盖旧目录。**

## 2. 实际改了什么、在哪里

### A：结果缓存写法修复

目录 `../retirement_lane_banks_20261009/`。只修改其 `rtl/road_dynamic_postprocess.v`：

- 原 `reg_retire_data[0:7]` 是 8×48 bit，以动态 lane 做局部 16 bit 写。
- 新 `reg_retire_alpha/beta/gamma[0:7]` 是三组 8×16 bit；按固定 lane 分支写完整数组元素，输出按原 emit lane 选银行。
- POST 饱和表达式提取为有符号 16 bit 线，比较界限和结果不变。
- 两段静态 if/else-if 留在原 POST 优先 / RAW 延后控制内；同拍 done 与数据、单写事务、顺序退休、384 bit 总容量、故障与复位取消不变。
- 无新增数据清零、缓存深度、流水拍、端口或系数功能。MAC、重定标、SiLU 算术文件与冻结版逐字节相同。

### B：仅 DW 单点行尾压实

本目录 `rtl/down2_dynamic_tile_runner.v`，后处理核与 A 字节一致：

- 三空间点仍使用 21-union 的 G3；PW 仍 G2。
- 行尾只有一个空间点，将 3×3 的 9 tap 压实为 G0 八项、G1 最后一项。mask=FF/01；first=G0、last=G1，偏置仅一次。
- G0 地址为固定展开常量；G1 是 (2,2)。没有新运行时除法，也没有仅提前 last 却继续稀疏地址的错误捷径。
- 保持控制状态、内部接口、原 MAC 的 II、标记、系数、故障、复位和存储边界。本轮未混入 PW 预取、跨任务 MAC 重叠或缩网。

外部负路径按主覆盖报告独立分类：A runtime setup/hold/removal 为 1/20/3，A layer 为 17/38/4；B layer 为 16/54/2。B 主报告 77 条负路径=5 内部 setup+72 外部，不把 77 条都称为外部。

### B 为什么失败、目前能证明到什么程度

最差路径从 `u_pre/u_round/result_tag_o_reg[1]` 经 lane/队列/完成条件到 `reg_pre_acc_reg[6,7,12,13].cea`，Slow −40°C。有 5 级 LUT；最后的 `mux79_syn_2[14]` 使能网扇出 40，单段网延迟 4.933 ns，终点与逻辑源距离较大。该路径中没有 DW 新增行尾地址运算，不能误诊为乘法或 SiLU 算术变慢。

B 与 A 后处理源码完全一致，但 B 新增选择逻辑及布局布线改变后，原有控制使能锥失去余量。这是本实现的物理脆弱点证据，不证明每个 181 Slice 都直接造成那 4.933 ns，也不保证换 seed 就可靠。另有 `flag_fatal→DW 缓存 WE` 的 −0.449 ns 及功能复位→同类使能端的 −0.082 ns，需要分别处理。

对同一 `pre_acc[7]` 控制锥复核：A slack +1.954 ns，数据延迟 7.873 ns（cell 1.481、net 6.392）；B slack −0.528 ns，数据延迟 10.270 ns（cell 1.513、net 8.757）。两者均 5 级 LUT，主要差异为网延迟增加 2.365 ns，而不是逻辑级数增加。此 +1.954 是该同向路径的 A 余量，不是 A 全设计最差 +0.475。

本轮没有切算术流水、增加拍数、复制复位同步器、改故障响应或改约束来绕过失败。以上失败报告、数据库和候选原样保留。

### 退休数据银行的实现证据与未证明项

A runtime 网表三个银行分别见 `gate_netlist.v` 20460/20849/21238 行附近：独立 PH1P RAM 控制器、动态写地址、非恒定 WE，W_WIDTH=16。A 层壳三个银行分别见 137756/138015/138421 行附近，按每 bank 8 bit hard-RAM 部分及 8 个 MSLICE 数据行映射，覆盖完整逻辑 16 bit。B 自身网表也保留三个银行，源码与 A 相同。三套新构建均无 HDL-5314。

这证明原局部写的实现疑点已通过静态银行结构得到改善，并且动态数据路径仍在；**不等于门级逐项数值等价**。SYN-5025 仍出现：A runtime 有 9 个显式未连接诊断输出，但不能用它们解释 generic warning 的全部对象；A/B 层壳未提供逐对象置零清单，故保持未定位、未豁免。

现有黄金 TB 使用 RTL 层并行接口，而物理顶层是串行低 I/O 壳，尚无已验证 PH1P 原语门级仿真流程；本轮门级同向量仿真标为 `not_run`。实际成立的证据为绑定哈希的 RTL 数值回归、当前候选真实网表/数据库及银行结构核查，不能宣布生产数据通路全部闭合。

## 6. 严格门、失败记录与下一步

相同七文件 RTL 范围：原始 3909 error/20 strict warning，A 4020/20，B 4049/20；不是历史包含壳和 TB 的整目录统计。最终 RTL 编译检查 PASS、AST 解析错误 0；格式 AST/readability/comment/naming/profile 仍 FAIL。静态 `read_without_driver` 对三个银行仍有未确认记录，不能删掉或当作自动豁免。

额外 TB 严格门也实跑：A 两文件 1442 error、B 三文件 1647 error；其解析器报 `only single module sources are currently supported`（这些 TB 实际为单模块），以及 task/报告格式等静态规范问题。真实 ModelSim 编译/执行已通过，但不能把它改写成严格 TB 门通过。RTL 门的 toolchain 字段 `not_requested` 与实际 TD/ModelSim 流程分别保留，不造出“八项全部通过”。

保存首次失败：case 空 default 检查器失败、ModelSim 沙箱 PE 启动限制、WaveDrom 临时路径限制、基线检查跨目录扫描失败、汇总脚本错误要求 B 的 A-only 覆盖标记；修正仅作用于新目录，实际重跑，不伪造 PASS 标记。

建议按冻结指南继续：先采用 A 的诊断参考，B 暂存失败分支；进入真实通道参数与代表层（PW 192→96 最大归约、DW stride1、Stem、2/5 原始预测头），避免继续只打磨这个小块。若要推进 B，需独立批准**后处理控制使能分发、DW 写使能故障门控及功能复位耦合**的最小修复范围，保持 II/数值/握手并重跑实际顶层；不能夹带 MAC 跨任务重叠或新时序例外。

# RoadYOLO 后处理流水修改与验证报告

本批已实现双重定标流水和有序结果缓冲。相同 DW→缓存→PW 小块从 20,633 降到 3,331 个核心周期，逐项数值保持一致。实际层顶层及独立动态系数链均完成 PH1P35MDG324、速度等级 −3、100 MHz 的布局布线；内部时序通过，外部诊断接口及严格交付门仍未通过。

本报告只对应 `dynamic_overlap_20261008` 独立候选。固定测试系数不是模型 QAT 参数；没有整网 DDR 执行、识别精度、上板或 5 FPS 验收结论。

## 当前未通过的问题及原因

| 区域 | 实际问题 | 原因和处理边界 |
|---|---|---|
| 实际层测试壳外部输出 | 16 个 setup 失败端点，最差 −1.224 ns | 最差从壳内 `cnt_export` 到 `o_tx_data`；零输入输出延迟只是诊断假设，不是真实外设契约。不能据此批量切分已通过的内部算术链。 |
| 实际层测试壳外部输入 | 32 个 hold 失败端点，最差 −1.400 ns | 来自 `i_rx_data`，进入装载寄存器或 SiLU 表写端点；需要实际发送端和板级时序，不填虚构延迟。 |
| 实际层原始复位入口 | 2 个 removal 失败端点，最差 −0.392 ns | `i_rstn` 到释放同步器 ASR；内部释放分发与原始入口分别报告，未新增 false path。 |
| 独立动态链外部输出 | 2 个 setup 失败端点，最差 −0.247 ns | 分别到 `o_tx_valid` 和 `o_tx_data[0]`，不是动态乘法内部路径。 |
| 严格 RTL 交付门 | 5,541 条错误、22 条严格警告，未闭合 | 最终版端口声明已可解析，检查器因此能发现更多原先未展开的诊断；数量增加不意味着新增了同数量的功能错误。实际仿真、布局布线通过不覆盖这些规则，不豁免。 |
| SYN-5025 置零告警 | 两套综合各有 1 条通用告警，工具未列出全部对象 | 动态链壳有 9 个明确未连接的诊断输出，属预期；实际算子和RAM保留有证据，但不能凭资源数量证明所有未枚举置零对象无害。保留未闭合状态。 |
| 真实模型与整网 | 尚未接入真实量化参数、DDR 全图调度 | 本批解决后处理串行化，不把小块速度比例外推为整网实测 FPS。 |

这些问题不等于“内部还有几十处算术错误”。实际层 50 条负时序记录对应 50 个不同端点，均属上表外部接口或原始复位入口；内部负时序记录为零。严格规则的诊断次数也不是独立功能缺陷数量。

严格门禁具体分类：4,944 项质量 finding 中，位宽语义 72、组合反馈 2、格式风格 2,519、其他 2,351；没有精确规则报告多驱动或计数语义错误，但 124 条“读而未发现驱动”仍在其他类待核实，不能偷换成“所有驱动都已证明正确”。不同检查阶段还有独立错误统计，不能将 4,944 与 5,541 简单相加。

新核的 14 条位宽告警全部落在计数加减及环形指针加一：入口上限2用2位，退休/元数据上限8用4位，算术在途上限不超过8×3=24用5位；加减只由真实入/出握手触发；3位地址指针7→0是有意模8。功能满载和反压检查验证了容量边界，但这些解释不改严格失败状态。两条组合反馈分别指向新核 `check_lane` 与旧runner `lane_index` 的固定次数 for 循环变量；不能把循环变量告警直接宣称为真实门级反馈，也没有用人工解释豁免它。

八项门禁中，compile通过；ast、readability、comment、naming、profile失败；门禁内testbench/toolchain标为not_requested。后两者的真实ModelSim回归及安路TD实现证据另外交付，不伪装成该门禁中的通过记录。本批不批量重写历史格式，也未改全局技能。

## 修改位置和固定结构

主要源码位于本目录的 `rtl/`：

| 文件 | 修改内容 |
|---|---|
| `road_dynamic_postprocess.v` | 新建双实例 PRE/POST 重定标、复用原 SiLU，加入完整批次入口、退休记录、元数据同步和有序故障提交。 |
| `road_down2_dynamic_adapter.v` | 接入新核的真实队列、活动、握手计数；删除旧单批 pending 与全零活动计数。层接口和测试系数不变。 |
| `down2_dynamic_tile_runner.v` | 从冻结基线原样复制；MAC 任务、DW 空间点分组、存储布局和层间屏障不变。 |
| `road_dynamic_requant.v`、`road_round_shift.v`、`silu_shared_unit.v`、`road_mac_probe.v` | 字节级保持冻结源，不修改算术接口、舍入、饱和、复位和 II。 |

数据路线为：

```text
完整三路批次 ─→ 2批入口 ─→ 已寄存的三路串行选择 ─→ PRE重定标
       │                                               │
       │                          RAW INT16 ─────────────┤
       │                                               │
       └→ 预留8批退休记录 ←─ POST重定标 ←─ 寄存边界 ←─ SiLU
                    │                                8项身份FIFO
                    └→ 完整批次检查 → 按批次及lane顺序逐项输出
```

两个重定标实例的数值行为不变，各保持无停顿算术 II=1；不是共用一个乘法器轮流做 PRE 和 POST。SiLU 仍只有一个实例，不新增通用算子、DDR 或外设协议。

### 接口及握手规则

- 完整批次只在 `i_input_valid && o_input_ready` 时接纳，三个累加数、三路 PRE 系数与移位、POST 系数与移位、mode、mask、tag 一起快照。外部 tag 是不透明数据，重复 tag 不会共用退休记录。
- 入口恰为 2 批；直到该批最后一个有效 lane **真正被 PRE 接受**才释放入口，不在装入选择寄存器时提前释放。
- 接纳批次同时预留 8 批退休记录之一，结果完成不再申请容量。新入口因容量阻塞不能反过来阻断既有结果写回。
- SiLU 无 tag 接口，其身份 FIFO 只随真实 PRE→SiLU 和 SiLU→POST 缓冲握手推进，不按固定拍数移位。自然流量最高占用 6，人工容量边界刺激覆盖到 8；后二者不能混为自然吞吐证据。
- 只有一个结果写口；POST 优先，冲突时 RAW 在 PRE 输出处保持有效和数据，等待下一拍，不丢弃 RAW。
- 同批所有有效 lane 完成且无故障后才公开第一项；低 lane 优先。输出反压期间 data/tag/type 不变，只在真实输出握手时推进。
- 满队列允许在同拍释放后下一拍再接纳，不增加组合容量穿透。标量算术 II=1 不代表完整三路批次每拍都能接纳。
- 检测到关联批次故障后立即禁止新批次接纳；已接纳旧批仍能运算并完整退休。故障记录到达退休头后才公开 sticky fault，并清空年轻控制记录。故障批没有部分数值输出。
- 复位立即取消所有旧事务，ready/valid 禁止传输；释放后必须重新握手装满 1,024 项 SiLU 表。数据阵列不作巨大复位清零，控制 valid/count 保证先写后读。
- 新增的队列、活动、接受诊断输出仅用于本候选和适配器；未增加算术核参数端口。适配器 `o_meta_count` 为待退休批数，核的 `o_meta_count` 才是 SiLU FIFO 占用。

## 数值与协议验证

Python 参考与旧结果：330 批、604 项、全部 7 种非空 mask 逐项一致。ModelSim 真实编译及执行通过。

核心回归覆盖连续输入、随机气泡、长反压、入口 2 和退休 8 满载、重复 tag、系数和 mode 切换、RAW/POST 同拍冲突、6 类输入故障、运行期末 lane POST 故障及 8 类复位位置。

末 lane 故障测试在旧批输出尚被阻塞、故障批和年轻批已接纳的状态下注入：旧批 3 项均正确退休；故障批和年轻批零输出；故障公开顺序正确。SiLU FIFO 的 8 项边界刺激属于人工诊断，并紧接复位，不用该刺激证明被人为丢弃的结果无损。

真实小块分别使用原固定夹具与有意义的非零偏置压力夹具，包含左上、内部、右下 tile 和反压/复位恢复；两组共 14 个场景通过。每场景比较：

| 项目 | 数量 |
|---|---:|
| INT32 MAC 输出 | 640 |
| PRE、SiLU、POST 各级 | 各 640，总计 1,920 |
| 有序缓存提交 | 640，唯一且无重复 |
| 最终 PW 输出导出 | 384 |
| DW MAC组／批次 | 384／256 |
| PW MAC组／批次 | 256／128 |

非零压力夹具与原权重、原测试量化保持同一部署测试契约，不通过改预重定标尺度制造“更快”。完成时所有队列和结果 reservation 清空。

## 实测周期及损失位置

计时窗口从实际任务启动到完成；不含装表、数据预装载、结果导出。旧串行核和新候选用相同向量及计时口径比较：

| 场景 | 旧串行 | 新候选 | 分解 |
|---|---:|---:|---|
| 无停顿 DW＋PW | 20,633 | 3,331 | DW 2,015 ＋ PW 1,316 |
| 三种反压场景 | 不把旧空泡当新速度 | 3,545／3,532／3,564 | DW 2,148／2,157／2,148；PW 1,397／1,375／1,416 |
| SiLU 表预装载 | 单独计数 | 1,024 次写握手 | 不计入核心周期 |
| 权重、偏置和 halo 预装载 | 单独计数 | 1,864 次写握手 | 不计入核心周期 |
| 结果导出 | 单独计数 | 无停顿 384 周期 | 反压 758／723／757 周期 |

无停顿减少 17,302 周期，即 83.86%；100 MHz 下该块核心窗口为 33.31 μs。它不是一帧网络时间。

无停顿互斥端点分类合计恰为 3,331：

| 端点原因 | 周期 | 占比 |
|---|---:|---:|
| MAC结果等待及DW结果展开阶段 | 1,794 | 53.86% |
| 缓存准备与输入等待 | 512 | 15.37% |
| 实际结果提交优先计数 | 640 | 19.21% |
| MAC组发射优先计数 | 333 | 10.00% |
| 层尾排空 | 51 | 1.53% |
| 其他 | 1 | 0.03% |
| 写回反压及容量等待 | 0 | 0% |

这里的“结果等待阶段”不是全部可删除的浪费：该阶段里 PRE/SiLU/POST 可能还在有效工作。优先级为写回阻塞→容量等待→提交→MAC 发射→输入/缓存等待→结果等待与展开→排空→其他，各拍只记一次。

另报非互斥活动量：PRE 2,883、SiLU 1,984、POST 2,883 周期；至少两个后处理阶段同时活动 3,059 周期。**它们不能相加当总周期，也不能再加到互斥端点总周期上。**

无停顿入口／退休／SiLU 高水位为 2／6／3；反压为 2／8／3，容量等待 15／11／16 个优先分类周期。未增加跨任务 MAC 重叠。

## 实际综合范围和内部时序

两个独立诊断顶层均为 38 个 I/O 位，完成安路 TD 6.2.168116 综合、布局布线，数据库和四角点 Max/Min 报告保留在 `physical/`。

| 范围 | Slice | LUT6 | 寄存器 | DSP | ERAM | I/O |
|---|---:|---:|---:|---:|---:|---:|
| 实际层壳，含 MAC、输入存储、DW/PW缓存、新调度和固定测试系数链 | 6,896 | 6,326 | 4,329 | 24 | 1 | 38 |
| 独立动态系数链壳，不含MAC或层存储 | 2,731 | 2,229 | 2,366 | 6 | 1 | 38 |

第一行确实包含新调度器，不是沿用旧壳资源；固定系数 65,536 和 16,777,216 的运算可合法折叠，不能据此宣称通用动态重定标没有 DSP 成本。第二行单独验证动态系数成本，不能把两行直接相加当整机资源。1 ERAM为 SiLU 表，其余小块存储采用实际综合得到的分布式/寄存结构，不声称已经映射为完整网络的 DDR/tile RAM。

资源不作未经证实的壳与核心拆分，均标为“含验证壳”。本小块资源在器件上放得下；整网权重 ROM、视频主链和 DDR 客户并未包含。

实际层内部最差 setup +0.244 ns，hold +0.028 ns，recovery +2.966 ns，removal +0.036 ns；setup最差从调度器 `cnt_mac_group` 到 MAC 的 `mult13.xa[3]`，表明下一次供数修改也必须重跑实际时序。独立动态链内部 setup +0.312 ns、hold +0.021 ns、recovery +5.728 ns、removal +0.084 ns，setup最差从 `flag_fatal` 经全链冻结控制到 POST 舍入核寄存器使能；没有用层固定系数通过替代动态链证据。

所有内部/外部划分保留 DSP、ERAM 端点。TD报告显示 Routed、100%覆盖，Slow/Fast 的 Max/Min 分析有效；每端点保留一条最差路径，角点统计中的出现/未出现只反映导出路径，不能当成每个角点四种检查的独立完整矩阵。覆盖率、角点细分、未约束/忽略对象和 SYN-5025 置零解释，以 `physical/physical_summary.json` 及实际日志为准。外部接口和原始复位入口未签核，不增加时序例外，也没有为其改造内部核。

## 逐层预算和下一项优化

`layer_cycle_budget.json` 对冻结 67 层逐层列出 24-MAC 理想工作下界、标量后处理工作下界及证据状态。只有 down2 DW/PW 两种形状有本批真实小块周期；另外 65 层明确标为未测，禁止用 6.19 倍小块加速比例统一缩放整网。

512×288 固定图中，两种已测层各有 576 个完整 tile；仅在逐 tile 重复本次固定测试、忽略 DDR、预装载、导出和跨 tile 开销的条件下，投影为 1,918,656 周期。该数值不是两层 DDR 实测，也不是整网预算。67 层理想工作下界合计 10,546,560 周期仍是下界，不证明小于 2,000 万周期的真实调度已实现。

本轮不缩网、不继续调整 SiLU、不修改 MAC 算术或 II。下一项最有价值的单变量是 **MAC 任务周转与层供数空泡**：先把 1,794 个等待/展开分类拍进一步分成不可避免的 MAC 尾流水、结果握手和可省的调度空拍，再只选择一处供数/周转修改，用同向量小块和实际层顶层重新对拍、实现。不能直接删掉全部 1,794 拍，也不扩大成通用加速器重写。

模型精度、真实动态参数的层集成、其他代表层、全图 DDR 调度仍是后续独立工作。任何修改算术接口、数值、复位、II、真实外设协议或时序例外的需要，都应先集中说明再决定。

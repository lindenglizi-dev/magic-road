# down2 全部 576 tile：完整层验证与后续步骤

日期：2026-10-10。优先完整功能，不同时修改算术核、II、时序约束或训练网络。

## 结论和仍未完成部分

**已完成第一步的全层数值验证：576 个 tile 连续执行，完整输出张量、地址覆盖、重复／漏写和实际边缘 padding 均通过。**

这里的 tile 调度由 testbench 驱动冻结 RTL 核，输入／输出记分牌为仿真存储；**不是已经实现全层自主 DMA 控制器，不是实际 DDR 闭环**。Stem→down2 的硬件交接、真实量化参数、完整 CNN、视频集成及板测 FPS 均未完成。没有将三 tile 的旧测试复制成 576 次相同输入：输入是完整 144×256×16 张量，各位置实际 halo 不同。

## 验证对象与实际结果

输入 144×256×16、DW 输出 72×128×16、PW 输出 72×128×24，冻结图顺序为 DW→pre→SiLU→post→PW→pre→SiLU→post。每个 tile 为 4×4 输出，18×32=576。

|---|---:|---:|
| 完成 tile | 576 | 576 |
| DW 实际写回项 | 147,456 | 147,456 |
| PW 实际写回项 | 221,184 | 221,184 |
| 实际输出缓存导出字节 | 221,184 | 221,184 |
| MAC / pre / SiLU / post 各阶段比较项 | 每阶段 368,640 | 每阶段 368,640 |
| 数值差异、重复、漏写 | 均 0 | 均 0 |
| 部分 halo 启动被正确拒绝 | 576 次 | 576 次 |
| 单 tile 核心周期 | 1,687 | 2,245–2,505 |
| 全层核心周期 | 971,712 | 1,374,843 |

| halo 预装载接受项 | 746,496 | 746,496 |
| 导出窗口周期 | 221,184 | 572,494 |

另有一次性 SiLU 表 1,024 项、权重／偏置／量化参数 652 项。每 tile 只重装 halo，不重装权重或表。无停顿仿真总时钟为 1,944,534，含上述装载、运行、导出以及 testbench 控制空拍；不能将该窗口当作未来 DDR 控制器的吞吐。

每次仿真均通过真实缓存读口导出整张张量并落盘；Python 将 `18×32×4×4×24` 分块布局逆变换回 `72×128×24 HWC`，与整图黄金值逐项一致。DW/PW 的真实 commit tag 对应全图逻辑地址，独立记分牌保证各项恰好一次。**这些是逻辑布局证据，实际 DDR 的地址单位、物理容量、返回归属和可见性尚未验证。**

当前系数沿 `dynamic_stress`，完整 INT32 bias、逐通道非二次幂 multiplier、两次 RNE、SiLU 和 INT8 饱和均保留。完整输出包含 21 种不同 INT8 值；不仅比最终饱和值，还逐项比较累加和中间阶段。测试参数不是部署 QAT 参数，不能据此声称模型准确率或量化精度通过。

## padding 为什么不是四边全补零

实际输入索引为 `tile_y*8 + halo_y - 1`、`tile_x*8 + halo_x - 1`。全图最大采样位置为 y=143、x=255，仍在输入内；padding=1 的右／下补零位置并未被 stride 2 的有效窗口使用。

| 角落 tile | 真实越界补零字节 |
|---|---:|
| 左上 | 272 |
| 右上 | 144，仅上边 |
| 左下 | 144，仅左边 |
| 右下 | 0 |
| 全层合计 | 7,184 |

Python 从整张补零数组切 halo；testbench 从冻结分块布局独立寻址并判断越界。两者逐字节一致，整图参考与局部窗口计算也逐项一致。未对右边／下边的合法最后一行、列错误补零。

## 门禁与失败记录

- **更正默认扫描的证据边界**：最初门禁只报 2 条 task 注释位置，但默认排除了 testbench，设计 RTL 扫描为 0 文件／0 模块；其 compile/ast 等 passed 不能解释为该测试台已经静态通过。显式加入 `--include-testbench` 并提供真实核接口来源后，完整扫描 1 文件，最终记录为 **412 条 error、0 strict warning**。
- 其中 262 条 VG004 缩进、53 条 VG025 命名；VG000 报 `only single module sources are currently supported`，但测试台真实仅一个模块，解析器未正确展开当前无端口测试台结构（模块数为 0），后续多个语义检查也记 error。不能把未展开的语义检查当作已证明安全，也不能把 412 条静态记录解释成 412 处已定位算术错误。给无端口声明补合法空括号并未解决，不扩大改检查器范围。
- 最终八项状态：compile、ast、readability、comment、naming、profile 均 failed；testbench passed；toolchain not_requested。实际 ModelSim 编译、完整执行通过单列。原始 48 条、默认排除下的 2 条以及显式全扫描 412 条均保留，计数口径不同，不混为核错误增长。
- `write-spec` 对空端口 testbench 明确拒绝 `ports must be non-empty`，保留真实失败；不伪造端口。人工规格和技能配置的 WaveDrom 图已提供。
- 第一次 ModelSim 启动遇到沙箱原生 DLL 加载 `WinError 623`；在批准的本地工具运行范围重试后通过。规格调用的工作目录边界问题修正为本验证根目录，随后暴露真实空端口限制。
- 明确空接未使用的观察输出后，未连接端口警告已消除。原厂 ERAM 模型 `INIT_FILE` 定义的 2 条越界选择警告仍保留；本测试通过装表口重新装满，不以此宣称 bitstream 初始化通过。
- Python／脚本专用技能当前未提供；本轮用真实 Python 执行、断言、输入哈希和完整 RTL 对拍验证，不声称通过不存在的 Python／脚本技能门禁。
- 冻结依赖 33 项前后哈希一致；旧核严格诊断状态没有因本轮测试而改变。

## 后续按这个顺序执行

1. **Stem→down2**：建立 Stem 3×3/s2、3→16 的输入窗口调度，复用当前 MAC 和通用动态后处理，不修改算术核。27 个乘积为 4 组，每组最多 8 项；16 输出通道的最后三路组只允许一条有效路。先对拍一个关联小块，再覆盖 Stem 全部 2,304 个 tile，并把实际 Stem INT8 输出按冻结分块布局交给已验证 down2。禁止在两层交界重复执行 `pixel−128`；测试量化尺度和参数版本必须明确相接。
2. **实际 DDR 搬运仿真**：读取本工程真实控制器与桥接接口，接入 tile 装载／输出写回，分别验证 AR/AW/W 接受、读返回归属、背压和取消后的排空。确认写后读可见性再发布可消费张量；不编造 B 响应或固定等待若干拍。仿真存储不能冒充厂商控制器或板测。
3. **固定网络闭环**：沿 67 卷积冻结图扩展固定调度、必要非卷积、预测 INT16 头、真实量化包和 FPGA 解码/NMS。测试参数结果与真实模型结果分别验收。
4. **官方主链与展示**：在独立集成工程接摄像头、ISP、DDR、HDMI；先仿真帧身份与画框切表，再在设备具备及对应授权后板测视频稳定性、有效检测 FPS 和结果年龄。

下一项是 **Stem→down2 的真实数据交接**，不是继续扩展 CRC 探针，也不回到仅测三个算子小向量。实际 DDR 和板测尚缺的证据不能由本次全层仿真替代。

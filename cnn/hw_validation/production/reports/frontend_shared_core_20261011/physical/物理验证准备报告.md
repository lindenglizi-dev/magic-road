日期：2026-10-11。状态：`PREPARED_WAITING_FUNCTIONAL_REGRESSION`，尚未执行 TD。

## 范围

- 顶层是实际功能接口 `road_frontend_shared_core`，不是旧窄口壳；源闭包为 Stem scheduler、新提取 down2 scheduler、唯一 `road_mac_probe`、唯一 `road_dynamic_postprocess`、其动态重定标/舍入及唯一 SiLU ERAM。
- 器件 PH1P35MDG324、速度等级 -3、100 MHz；只综合、布局布线和报告，不生成位流，不修改生产或旧 baseline。
- 不增加 false path、multicycle、max/min delay。`frontend.sdc` 对功能 I/O 使用原已批准的零延迟隔离诊断假设；`frontend.adc` 留空，由 TD 自动引脚。二者均不构成外部板级签核。

## I/O 门槛

源码端口统计为输入 82 bit（含时钟）、输出 61 bit、合计 143 bit。该值超过历史 64-bit 窄口目标，但未超过同器件旧实际报告 `shell_route.area` 给出的 160 I/O 容量。余量仅 17 bit，因此本次允许实际顶层 P&R，但必须明确：功能接口没有达到 64-bit 目标，也没有真实板协议、板级引脚或外设延迟签核。

## 运行与证据

等待协调者确认功能回归通过后，在本目录执行：

```powershell
.\run_td.ps1 -Execute
```

不带 `-Execute` 只做 hash、I/O、单实例、工程源清单、无位流和无时序例外预检。TD 失败时保留 `td.log`、日期日志、`td_launcher.log` 和 `td.command.json`，不清理失败目录。

资源从 `frontend_route.area` 与 `frontend_route_ram.rpt` 提取；层次表必须各保留一行 `road_mac_probe`、`road_dynamic_postprocess`、`silu_shared_unit`，全局 ERAM 必须为 1。该检查证明本次实际顶层的算术链保留，不能借旧壳资源数替代。

全内部时序由 `internal_all_checks.timing` 提取：`get_regs -hier *` 同时作为 from/to，`ep_num 100000`、每端点 1 条，解析 `Check Type` 的 setup、hold、recovery、removal 数量和各自最差 slack。`all_endpoints*.timing` 用于覆盖率和 ignored 交叉检查；诊断输入、诊断输出、raw reset、DSP、SiLU ERAM 另行报告，不能混作内部 reg-to-reg 结论。

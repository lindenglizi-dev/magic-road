# RoadYOLO 单计算链前端：执行与对比报告

日期：2026-10-11；本地分支 `work/roadyolo`。当前状态：功能完成、实际布局布线完成，但100 MHz内部setup与严格交付门未通过。功能检查点为 `1f72a86b`。最新入口为本文件及 `status.json`，不能把历史壳的资源套在本设计上。

## 1. 本次在整网中的位置

这次将上一阶段 TB 中的两套算术链合并为实际 RTL 的唯一算术链。覆盖冻结网络最前面的 3/67 个卷积：Stem 普通卷积、down2 的 DW 和 PW；不是完成整个 CNN。

```text
公共装表/参数/halo口 → owner选择 → Stem调度器 ─┐
                             → down2调度器 ─┤
                                           ↓
                                    唯一24MAC / signed33
                                           ↓
                             唯一动态重定标→SiLU→重定标
                                           ↓
                          当前调度器真实tile缓存→公共导出口
```

owner 只能在调度器空闲、算术排空、完整结果已导出时改变。两个调度器不同时运行，不引入跨任务 MAC 重叠。整帧中间张量仍由 TB 承接，不伪装成已经实现的 DDR。

代码位置：

- `rtl/road_frontend_shared_core.v`：新增选择、准入和唯一算术链连接，公共功能接口 142 bit（82入、60出）。不是64-bit窄口壳，也不是可直接上板的接口。
- `rtl/road_down2_tile_scheduler.v`：从冻结 runner 机械提取调度与缓存，移出算术实例；提取证明见 `rtl/extraction.json`。
- 复用旧 `stem_down2_handoff_20261011/rtl/road_stem_tile_scheduler.v` 和 `board_selftest_20261010/core/`，未修改。
- `tests/tb_frontend_shared.v`：真实 Stem 导出喂给 down2；控制专项见 `tb_shared_core_control.v`。
- `physical_attempt2/`：本次修复后的实际顶层物理实现。`physical/` 为失败停止记录，不覆盖。

### 内部失败端点的完整分类

`physical_completion/failed_endpoint_inventory.json`来自全量含ignored报告，按(check type, endpoint)去重保留最差路径；原3617条负路径有3609个唯一检查端点对。内部只有setup失败，共52个唯一端点；工具reg→reg统计51个，完整集合额外包括1个分布式RAM写使能。相同端点在不同路径/角点重复出现不累计成新端点。

## 6. 下一项最有价值的单变量工作

下一批按单变量执行，不再盲目更换全局布局参数：

1. 冻结本阶段：先在新候选只修改Stem权重地址生成。当前合法输出组基址只有channel=0/3/6/9/12/15；将`(channel+lane)*27`限定为精确宽度的预译码/基址，不增加新算术接口。先枚举16通道×27项和全部尾lane，证明权重地址/掩码一致，再跑同一完整向量；核心周期必须保持11,883,456。最后重跑同一实际顶层，目标同时减少35个最差端点及2个索引DSP，不预先宣称收益。
2. Stem候选稳定后，另做down2的credit控制单变量修复，分别验证3个激活CE和4个输出计数端点；PW权重9端点与PP队列WE1端点按各自锥处理。若修复必须改变算术接口、数值、复位或II，停止该分支并提出决定，不改冻结算术核。
3. 内部时序闭合后再优化Stem的“每任务等全部后处理完成”：复用已有输出预留做有限在途调度，该等待占Stem核心62.2%。另测吞吐收益，不与地址修复混算。外部真实接口/复位条件尚未签核，不编造延迟或新增例外。

主线后续仍是同一模型包ROM参数→共享实际计算→其余真实层/固定图→DDR闭环→FPGA解码NMS/显示。匹配厂商DDR模型和写读屏障未确认处保留明确阻塞，不继续用控制器启动来冒充数据搬运通过。真实QAT参数、整网时序/资源、5 FPS、精度、上板仍未完成。

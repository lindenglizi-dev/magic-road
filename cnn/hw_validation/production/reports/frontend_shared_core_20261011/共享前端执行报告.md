# RoadYOLO 单计算链前端：执行与对比报告

日期：2026-10-11；本地分支 `work/roadyolo`。当前状态：功能完成，修复后的实际布局布线运行中；严格交付门未通过。最新入口为本文件及 `status.json`，不能把历史壳的资源套在本设计上。

## 1. 本次在整网中的位置

这次将上一阶段 TB 中的两套算术链合并为实际 RTL 的唯一算术链。覆盖冻结网络最前面的 3/67 个卷积：Stem 普通卷积、down2 的 DW 和 PW；不是完成整个 CNN。

```text
公共装表/参数/halo口 → owner选择 → Stem调度器 ─┐
                             → down2调度器 ─┤
                                           ↓
                                    唯一24MAC / signed33
                                           ↓
                             唯一动态重定标→SiLU→重定标
                                           ↓
                          当前调度器真实tile缓存→公共导出口
```

owner 只能在调度器空闲、算术排空、完整结果已导出时改变。两个调度器不同时运行，不引入跨任务 MAC 重叠。整帧中间张量仍由 TB 承接，不伪装成已经实现的 DDR。

代码位置：

- `rtl/road_frontend_shared_core.v`：新增选择、准入和唯一算术链连接，公共功能接口 142 bit（82入、60出）。不是64-bit窄口壳，也不是可直接上板的接口。
- `rtl/road_down2_tile_scheduler.v`：从冻结 runner 机械提取调度与缓存，移出算术实例；提取证明见 `rtl/extraction.json`。
- 复用旧 `stem_down2_handoff_20261011/rtl/road_stem_tile_scheduler.v` 和 `board_selftest_20261010/core/`，未修改。
- `tests/tb_frontend_shared.v`：真实 Stem 导出喂给 down2；控制专项见 `tb_shared_core_control.v`。
- `physical_attempt2/`：本次修复后的实际顶层物理实现。`physical/` 为失败停止记录，不覆盖。

## 6. 下一项最有价值的单变量工作

先按实际内部失败端点定位共享选择和调度路径；不以改变外部输入延迟掩盖内部问题。如果内部物理基线可用，优先将Stem的“每任务等全部后处理完成”改为复用已有输出预留的有限在途调度：该等待占Stem核心62.2%，收益比扩展CRC探针更直接。先做同向量小块对照，再重跑本共享实际顶层；不改MAC II或数值核，不同时缩网。

主线后续仍是同一模型包ROM参数→共享实际计算→其余真实层/固定图→DDR闭环→FPGA解码NMS/显示。匹配厂商DDR模型和写读屏障未确认处保留明确阻塞，不继续用控制器启动来冒充数据搬运通过。真实QAT参数、整网时序/资源、5 FPS、精度、上板仍未完成。

本阶段遵循readable-verilog-generator保留完整门禁/规格/周期图及失败证据；按ponytail复用冻结算子，只新增必要共享接线和测试，没有新增通用总线、队列框架或训练分支。

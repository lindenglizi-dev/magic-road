# RoadYOLO DW 四槽重叠调度验证报告

日期：2026-10-09。范围：`down2.dw.conv` 的16通道3×3 stride2 DW，接16→24 PW，输出4×4 tile。输入、权重、偏置和量化参数均动态装载，但仍是冻结测试参数，不是真实部署 QAT 参数。

当前结论：数值及调度回归通过，小块核心从2607降至1687周期；实际顶层已完成布局布线，实现网表两套压力参数的6个tile、2304个导出字节全部一致。但有5个内部 RAM 写使能 setup 失败，不能替换已冻结物理基线。外部接口及严格交付门也未通过。最终状态见本目录 `status.json`。

## 本轮修改与不变部分

仅修改 [DW 调度器](rtl/down2_dynamic_tile_runner.v)。其余七份功能 RTL 与 `baseline/` 逐字节一致，包括 signed33 MAC、重定标、SiLU、适配器和38位验证壳。外部端口、算术 II、数值、偏置一次、first/last、三路原子故障和复位取消契约不变。

复用现有4×9位描述符环，DW 末组接受后继续发下一任务。已有96位 active 结果槽新增9位身份，后处理的位置、通道及系数来自该身份，不再依赖已前进的发射计数器。四项 MAC credit 与一项 active 各有所有权，不能把它们说成“总共只能有四个未完成任务”。

数据路径为：片上输入和权重 → 24 MAC及四 credit → 有序结果与描述符 → DW active 三空间点逐标量退休 → 原共享后处理 → DW缓存 → PW → 输出缓存。旧 active 末标量接受与下一结果弹出可同拍，新结果优先装入。

模块接口及实测周期图见 [规范](rtl/down2_dynamic_tile_runner_spec.md) 和 [周期图](dw_task_overlap.svg)。runner 的 `o_load_ready` 在复位时可能为高，上游不得据此传输；未修改的顶层壳在两级同步释放完成前屏蔽外部 ready/valid。释放后仍须重装1024项表及全部数据和参数。

1687周期按100 MHz目标换算为16.87微秒；当前时序未通过，不能当作硬件实测。它也只是已经预装数据的小块，不是视频帧处理时间。端点定义、源向量及计时窗口保持一致，不把故障提前退出计入收益。

当前无停顿 DW 的互斥占用为：存储准备384 + MAC接受384 + 发射容量等待288 + 排空39 = 1095。PW为：存储准备1 + MAC接受256 + 发射容量等待288 + 排空46 + DONE 1 = 592。

原来独立等待 MAC 结果、再串行发送 DW 标量的状态已被重叠调度替代，工作没有凭空消失。DW仍有128次MAC结果、256次前重定标、SiLU、后重定标及提交；其后处理忙周期并集1078，至少两级同时忙1044。PW对应并集576、重叠554。这些忙周期不能再加到核心端点上。

DW四 credit 满占652周期，退休队列满占616周期，即使没有外部反压，后处理容量仍限制发射。DW标量从后处理接受至最终提交仍固定30周期；这不是吞吐 II。MAC末组至结果弹出现在为7至51周期，变长部分来自排队和 active 容量，不是 MAC 算术延迟变长。

预装载另计：表1024次接受、跨度1024；数据及参数1948次接受、跨度1953，包含原有5个探测气泡。无停顿导出384次接受、跨度384。不得把窄口装载速度、核心运行或结果导出混为一个窗口。完整逐拍分类见 [analysis.json](analysis.json)。

## 数值与协议证据

最终 `simulation_attempt3/` 四套参数均完成 case0至15，共64个完整小块。每块逐项比较 MAC、前重定标、SiLU、后重定标和提交的640个值，再比较384个导出字节。向量包含边缘、内部和右下角。

覆盖连续任务、随机气泡、DW及PW各256拍长提交反压、四 credit 满、同拍 push/pop、active替换、系数随通道切换、DW五位置复位及完整恢复、原PW复位场景、末组故障、故障后年轻所有权保持和公共复位清零。逐拍检查描述符计数等于MAC预留计数，DW切PW和DONE均要求全部所有权排空。

第二个DW故障定向用例同时存在旧active、PP输出valid和commit_ready；故障弹出当拍禁止PP接受、提交及DW缓存写，计数不增。此前只检查首任务故障不足以覆盖这个冲突，最终回归已补齐。

Python所有权模型通过12次运行，只支持调度守恒，不提供数值或物理证明。窄口 RTL 回归与实现网表回归均对两套压力参数各运行三个tile，各逐字节检查2304个导出字节，均通过，核心计数保持1687。最终回执分别在 `shell_rtl_attempt2/receipt.json` 和 `shell_routed_attempt2/receipt.json`。实现网表不标注SDF，不能替代以下静态时序结论。

## 实际资源和时序

所有量值来自本次实际报告。寄存器最差setup为 `flag_fatal` 至后重定标 `reg_half[10].cea`，705扇出、94%延迟来自布线；DSP输入仅余0.010 ns，也不能称余量充足。

全量内部的5个失败均为 `reg_load_addr[10]` 至DW权重分布式RAM写使能，端点分别为 `ramread0_syn_1637/1757/1657/1777/1737.we`，slack为−0.268、−0.176、−0.154、−0.107、−0.062 ns。最差路径经过装载范围/类型、顺序及故障译码，7级逻辑，总数据延迟9.968 ns，其中布线8.222 ns，占83%。这说明寄存器子集通过不能代替全部内部存储端点通过。

外部另有15个setup、50个hold、3个removal失败。自动引脚与零诊断I/O延迟不是实际板级契约；未修改输入延迟来掩盖问题。全局WNS为setup −1.294 ns、hold −1.557 ns。同步器级间及内部功能复位分发未发现负路径，外部复位入口removal仍失败。

TD报告STA覆盖率100%，Slow/Fast均检查，但 `check_timing_verbose.rpt` 的时钟定义提示及DSP模式dummy节点继续保留。时钟摘要仅列一个100 MHz主时钟，不能据此删除工具提示。`PHY-5089`跳过异常外部hold路径的实现提示也保留，未作为豁免。`report_route_status`未生成预期独立文件，相关命令及DRC输出在完整TD日志，不宣称该独立报告存在。

`SYN-5025`未忽略：当前顶层展开查询得到6项 `state_next` 残余网，均PINS=0、DRIVER=0，没有发现带负载未驱动网。这个查询不是全部映射原语引脚的形式证明；有效乘积、偏置和缓存路径还由全量RTL数值回归及实际综合网表保留支持，不能把警告笼统宣布全部清零。

## 严格门禁与失败记录

严格门禁仍不闭合，未放宽检查器。候选设计的compile通过，ast有19项格式器错误但parse errors为0；readability、comment、naming、profile失败，testbench/toolchain在该静态命令中未请求。实际ModelSim与TD运行证据另存，不改写静态门的状态。

设计在初检为5025 errors、20 strict warnings；最终为5008 errors、37 strict warnings，见 `gate_candidate_attempt3/gate.json`。最终测试门为1228 errors、1 strict warning，覆盖两个TB，其数量与只检查一个旧TB不能直接比较。

语义风险优先保留：VG085涉及整数循环和宽度比较；新active末点表达式完整宽度为2位，规则截取了`1'b1 == count`片段，不能直接当作实际回绕。VG097仍有三元式、数组拼接及厂商RAM端口无法确定宽度的记录，不能称已闭合。VG110/113涉及未清数据阵列，当前靠有效位、完整重装和复位回归防止旧数据使用。VG153中的循环变量、子模块返回及保留字段需与实际驱动结合解释，不按总诊断条数等同真实功能bug。双语头、命名、注释、排版单列，不在本轮批量重写。

失败记录原样保留：第一次规格生成沙箱读路径失败，第二次源文件不在规格生成工作区；第三次使用相同源码副本后成功。补强TB第一轮背压构造使故障堵在旧结果后而超时，且循环变量复用漏跑4个复位检查点；最终改用独立检查点变量，并对case集合0至15做硬断言。初次实现网表仿真达到300秒脚本上限，被终止后出现RPC EOF；随后保持全部数据、RTL和通过条件，以既有600秒工具上限重跑成功。增加的仅是进度日志，不是放宽数值或时序验收。

## 整网预算与下一步

`layer_budget.json`逐层保留67个卷积记录。只有down2这对真实形状小块有本轮实测。按当前4×4分块投影，完整down2各需576个tile，DW核心630720周期、PW340992周期，总971712周期；不含DDR及权重输入、跨tile存储周转和模型真实参数。

旧15419489周期是带乐观假设的协议下界，不是本轮整网测量。不能把本轮两个投影与其余65层下界混加，再宣称达到每帧2000万周期或5 FPS。其他通道、stride1 DW、Stem及非卷积算子仍需真实调度证据。

下一项最小修复是DW权重装载写使能边界：先分离范围/顺序检查与写使能，评估一项寄存写入的数据、地址、使能同步；必须继续保持接受顺序、可连续装载、最后写入可见后启动、复位取消及错误时不发布。若需要改变接口或复位契约，先请求决定。先冻结本次失败实现，不改算术流水、不扩大队列、不缩网。

该5端点闭合后，主线转向冻结图其他真实PW/DW层与DDR周转；不继续凭感觉微调通用加速器。本次未训练、未改生产工程、未生成位流、未上板、未写Flash。1608项历史冻结文件的前后哈希检查未变；当前源码、输入回执、约束、数据库、日志和失败记录另由 `evidence_hashes.json` 冻结。

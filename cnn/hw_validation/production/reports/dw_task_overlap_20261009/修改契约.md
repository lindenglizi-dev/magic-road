# DW 四槽调度候选修改契约

唯一功能改动：将DW发射与已有active三点结果退休解耦，复用已有4×9任务标签环。
MAC到result pop的credit最多4，另有原本已有的一个active triplet存储，不把两者
混称为总共只能有4个未提交任务。新增9位active身份，不新增数据FIFO。

数值参考仍使用上一阶段四套冻结向量。schedule_reference.py先行核查身份、首组
预留、末组完成、同拍push/pop、active替换、随机反压、复位取消和故障顺序；它不是
真实周期预测，也不重复实现算术。候选只编辑rtl/down2_dynamic_tile_runner.v。

保留八份功能模块中的其余七份，端口、II、signed33/INT32故障、RNE、量化参数、
SiLU、bias once和运行时重装表语义不变。DW各组仍STORAGE→SEND，第三组仍仅5个
有效并集lane，结果仍按物理通道one-hot逐空间点送后处理。

任务first实际接受时压标签，末组接受后推进issuer；结果仅在active空或最后标量
同时接受时弹出。新结果身份、数据、lane计数同步更新，新结果替换优先于旧结果清空。
参数、mask和写地址来自active元数据；禁止使用已经前进的issuer计数。

故障到达时停止新发射，故障接受取消整块发布，不向后处理发送该任务或年轻结果；
已接受所有权不软复用，必须公共复位。复位异步取消，释放后按原协议重装1024项表。
DW→PW仍要求256次最终提交且标签/active/MAC结果及预留排空，保留最后写后首读边界。

先原始严格门禁和AST风险审查，再候选回归与严格门禁，之后相同38位壳和原约束/策略
完成PH1P35MDG324速度3、100MHz实际布局布线。严格门禁若仍失败，物理仅作原批准
范围内的隔离诊断，不能称生产交付。无位流、训练、上板、Flash或时序例外。

# v12 缓存单写口：阶段结果与下一步

日期：2026-10-08。结论先行：**本次缓存候选的功能回归、100 MHz 全内部报告路径时序通过；整机、外部接口与严格交付仍未通过。**

## 1. 在整体项目中的位置

当前完成的是批准框架阶段 A 的这一次局部修复：down2 4×4 DW16→PW16/24 小块，包含窄口验证壳、固定测试系数、原 MAC/RNE/SiLU。不是 67 层 CNN、不是正式量化模型，也不是整网 5 FPS。

后续顺序不变：A 内部控制时序 → B DW 同通道三空间点及 PW 预取 → C 动态量化参数与 INT16 预测 → D 固定网络图及 DDR → FPGA 解码/NMS/显示。训练分支未启动。

## 2. 这次只改了什么

保留 v11 ack-local 全部源码、数据库及失败报告，在本独立目录修改 DW 缓存的写口表达。把预装载与 DW 计算提交统一为一个显式写口，保持旧同拍写回优先级；物理地址为 8 位，但先检查原完整地址，非法地址不能截断写入。故障对 ready 的即时阻断未删除，未给 fault 加一拍延迟。

算术核、后处理、壳、SDC、当前 II、数值、复位与固定系数保持原样。核心周期未增加。当前源码：[down2_overlap_tile_runner.v](rtl/down2_overlap_tile_runner.v)，SHA256 `4e7d63a513f04a129ee0dbff42f6958454fdd5cbe2c8f0216c176fa29cae5717`。

旧失败的四条路径从后处理 flag_fatal，经装载接受和缓存控制到 RAM CEB。原最差数据延迟 9.757 ns，其中布线 7.949 ns（82%）、7 级 LUT、最大扇出 48。本次改变缓存写口结构，而非修改乘法器或增加时序例外。新物理实现消除了内部负裕量；不能把所有资源减少都归于单独某个表达式，因为同一改动也改变综合映射和布局。

## 4. 功能与周期证据

Icarus 12、Verilog-2001、现有 PH1P ERAM 行为模型；这是 RTL 仿真，不替代硅片 RAM 验证。ModelSim 旧启动故障保留，未冒称本轮 ModelSim 通过。

原四个小块案例均通过，完整案例每级 640 项对拍；7 个 ack X/Z、MAC 原子溢出、复位取消、MAC_WAIT table-valid 高电平 1,280 次接受均通过。增强检查逐拍比较旧/新缓存写事件共 1,537 次（769 装载、768 提交），地址和数据一致；写入时完整地址不超 255、提交元数据 known、DW channel 不超 15。另覆盖地址 256、X 地址、复位不写、IDLE 表故障禁止装载。

任意人为强制内部 tag[15]=X 时，旧 if/else 与新布尔写使能并不等价；本结论限定为真实状态机可达、元数据已知的协议事务，不宣称任意四态内部形式等价。

主代理独立重新编译和运行增强 TB，exit 0，见 [root_recheck.log](verification/regression_candidate/root_recheck.log)，SHA256 `e507a397ea1e66d480950650b291f298f6f991b6d63ecaf11b552ed6c34cc15c`。仿真副本与物理 RTL 的 SHA256 一致。

关键网表窄核对：24 个 MAC lane 的激活/权重端仍为动态网络；96 位 bias 完整传入；唯一 SiLU ERAM 的地址、输入和写使能动态保留；缓存写数据、地址及使能未被常量折叠。它不等于 SYN-5025 全对象归因。六源/约束/数据库绑定见 [source_manifest.json](gates/source_manifest.json)。本轮旧 RTL、数据库、失败报告与约束复核匹配原哈希；没有单独的时间戳式 before/after receipt，不冒称已建立全历史冻结审计。

接口周期图已用既有 WaveDrom 3.6.1 渲染：[缓存单写口接口片段](spec/waveforms/down2_overlap_tile_runner_cache_write.svg)。主代理修正初稿中的 IDLE/ready 不一致，明确用竖线省略计算间隔；没有改 RTL。渲染器首次自检因沙箱临时目录权限失败，随后在本候选临时目录隔离运行，自检和渲染 exit 0；此文档结果不改变严格 gate 未通过状态。

一次完整预装载窗口 2,894 周期（1,024 表项、1,864 张量/参数写）；核心 5,433；384 个结果导出本次 448–449 周期，由外部 ready 相位决定。三个窗口分开，不以导出速度冒充核吞吐。

核心无停顿仍为 MAC 调度占用 5,376、排空等待 56、完成 1，总计 5,433。单 G2 任务 STORAGE 2、SEND 2、WAIT 10，共 14；任务首/末接受间隔 2，末接受到确认 10，确认到下一首接受 2。pre 4,096、SiLU 2,560、post 3,712、写回 640 是**重叠活动计数，不可相加为总周期**。本次不改变任务周转和 MAC 接口。

## 5. 仍未通过的具体问题

- 外部接口未签核：全局 setup −1.725 ns 的 15 端点全部到诊断输出；41 条 hold 全部从诊断输入（含 9 个 ERAM 数据端），另 2 条原始 i_rstn removal，最差 −0.366 ns。零 I/O 延迟只是隔离诊断假设，不是板级契约。不能称整机时序通过，也不能编造延迟让它变绿。
- 严格交付失败：runner 1,177 条、六源闭包 3,833 条；作用域不同不能相加。compile passed；ast/readability/comment/naming/profile failed；原 gate testbench/toolchain not_requested，独立仿真/TD 实测分别留证。旧失败不覆盖。
- 新增宽度诊断包含原 11 位地址与 9 位 expected 的无符号比较再次出现；Verilog 会零扩展，范围检查和逐拍测试已覆盖本次可达写口，但并未把该规则改成通过。另有组合预算、格式/注释项，不能把全部严格失败统称为格式问题。
- SYN-5025 的 warning 字符串集合与旧版一致，不等于所有未驱动端点均已完成逐项归因；关键数据通路映射证据另存，未把 warning 直接豁免。check_timing 原有时钟定义和 DSP mode dummy-node 告警继续保留。
- `shell_route_status.rpt` 本次控制台未生成；exit 0 不代表每一条辅助命令均产生预期文件，不宣称完整 DRC/route-status 签核。
- 真实模型量化参数、完整网络 DDR 与解码/NMS 未接入。26 DSP 是固定测试系数成本，不能代表动态量化链。没有新精度、板测或整网 FPS。

## 6. 下一项最有价值的动作

转入已批准阶段 B：在独立候选中将已通过 Python 的 DW 同通道三相邻空间点排布接入现有 MAC，并同步三路写地址/有效 mask；不继续微调 SiLU，不增加通用加速器或跨任务 MAC context。先 s2/4×4 的 9×9 halo、G3、行尾缺路、padding、故障和反压，再用同批 DW/PW 向量测完整端点周期并重跑实际顶层布局布线。

成功条件：acc/pre/SiLU/post/实际写地址逐项一致；任务数和输入组数减少有 RTL 周期证据；含新调度的全内部时序通过。Python 的 256→128 任务和 512→384 输入组只是排布证据，不能预先写成实测加速。之后更新逐层预算，与 100 MHz/5 FPS 的 20,000,000 周期上限比较，再决定 PW 周转或 H24，不无限拖延缩网决策。

本轮按 readable-verilog-generator 保留接口、功能、严格诊断与实际实现边界；按 Ponytail 原则只改必要缓存写口，未做无关审计或格式重写。

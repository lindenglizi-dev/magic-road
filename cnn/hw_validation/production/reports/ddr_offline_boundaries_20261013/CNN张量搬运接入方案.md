# CNN 张量搬运接入方案

## 结论与实施位置

继续复用现有单请求桥和 Stem 到 down2 的搬运测试，不新增通用 DMA。先做独占 DDR 闭环，再做视频并发。**旧桥目前不能直接作为实板 CNN 搬运桥**：写完成确认没有真实信号来源，且 AW/W、最早读返回规则仍需与实际控制器统一。不能接常量 1 或等待固定拍数来绕过。

本轮不改生产。下一次实际接入也应放在新的独立验证目录，引用冻结计算核；不要修改本目录或旧板测位流。现有相关资产：

| 资产 | 位置 | 用途与限制 |
|---|---|---|
| 单请求条件桥 | `cnn/hw_validation/ddr/paxi_single_outstanding_bridge.v` | 单拍地址、mask、owner/epoch、背压、取消与排空；依赖外部 commit |
| 完整张量离线交接 | `production/reports/ddr_tensor_handoff_20261011/` | 实际 Stem 输出写入条件内存，再读回供 down2；驱动仍在 TB，不是可综合 DMA |
| 实际 DDR 独占诊断 | `production/reports/ddr_display_cdc_20261013/` | 实际厂商 IP 与 HDMI 测试位流；板上读回仍待做，不包含 CNN |
| 冻结图与布局 | `production/graph_artifacts/graph.json` | 张量基址和 tile 布局；仍保留 `byte_unverified_do_not_enable_dma` 历史限制标记 |

表内后三个短路径均相对 `cnn/hw_validation/`。所有历史性能数据仅属于原报告对应的版本。

## 最小接口对应

| 边界 | 保留接口与行为 | 接入要求 |
|---|---|---|
| 计算侧请求 | `i_req_valid/o_req_ready`、write、byte_addr32、data128、mask16、epoch32、owner32 | 每请求恰好 16 字节；发送端在接受前保持完整载荷；不另建宽描述符总线 |
| 地址 | byte 地址完整范围检查后转 `[25:1]` | 128 位一拍，native 地址加 8；不得先截断高位再检查范围 |
| 写地址和数据 | 真实 `paxi_awready` 与 `paxi_wready` 分别接受 | 不能复用生产包装层由 AWREADY 冒充 WREADY 的通路 |
| WLAST | 单拍适配层 `paxi_wlast = bridge_wvalid` | 与最新独占诊断一致；不推广为 burst 合同 |
| 读返回 | 转发真实 RVALID、RLAST、RDATA | 原桥无返回反压口，但厂商 IP 有 RREADY；独占、预留一个完整返回槽时才可固定 RREADY 为 1 |
| 最早返回 | 原桥只在 READ_RETURN 接收 | AR 接受同拍 RVALID 会触发旧桥故障；需真实最小延迟证据，或另立最小适配候选，不假定零延迟支持 |
| 接受通知 | `o_paxi_accepted_valid` 与 owner/epoch | 只证明读地址或完整写请求被接受，不证明写入可见 |
| 完成通知 | `i_commit_confirmed` | **目前无合法实板接源。** 固定为 0 时写和已取消写都等待；因此不能宣称实板搬运可运行 |
| 结果 | result valid/ready，write、committed、epoch、owner、read_data | 消费以前保持稳定；cancel 是上下游共同放弃结果的 flush |
| 故障和排空 | protocol_fault、drain_done、late_discard、cancelled_drain | 排空前禁止复用 owner/返回槽；不靠超时强行释放 |

定位依据：`ddr2/ddr2.v` 28–42 行实际有 WLAST/RREADY，95–100 行说明地址单位；`ph1p35_324_ddr_wrapper.v` 74–75 行与 `mc_to_user_interface.v` 48–58 行是后续必须绕开或在独立候选中修正的 ready 路径。上述文件位于 `user_source/hdl_source/` 下；本轮未修改。

## 先统一控制器语义

1. **AW/W 时序**：旧桥先 AW，接受后下一拍 W；最新诊断同时呈现 AW/W、独立接受。二者不同，不能用后者通过代替前者的厂商兼容证据。核对 PH1P 实际资料和板测，不套用任意 AXI 时序。
2. **写可见性**：当前生成 IP 顶层没有向应用导出写完成事件，内部 BVALID/BRESP 被丢弃。即使以后导出 BVALID，也必须先确认其与读可见性的关系，不能把名字当作保证。选择有依据的完成事件或排序屏障后，才连接 commit；不依赖固定等待。
3. **复位**：桥硬复位只在控制器也协调清空时释放所有权。局部取消是排空，不是单边复位。失去终结事件时保持占用并报故障，不把问题转移给下一帧。

本轮离线条件端点会显式提供写可见事件，因此能验证桥如何消费该事件，不能证明真实控制器会产生它。

## 输入槽与搬运顺序

输入为 `512×288×3 = 442368 = 0x6c000` 字节，两个输入槽分别为 `0x03400000` 与 `0x03480000`，各分配 `0x80000` 字节。无需改为整片片上存储。

| 状态转换 | 唯一允许条件 |
|---|---|
| FREE → CAPTURING | SOF 到达且有空槽；否则整帧跳过 |
| CAPTURING → READY | 完整 442368 字节全部成功、无溢出，且全部写具备已验证的可见性保证 |
| READY → READING | 描述符被计算侧接收；epoch、source_frame_id、timestamp、slot/base 保持配对 |
| READING → FREE | 最后一个输入读响应已被消费，且该槽没有其他在途引用；不是最后 AR 发出，也不是描述符确认 |
| 任意取消 → FREE | 停止未呈现的请求，已呈现请求继续握手，已接受请求全部排空；不发布残帧 |

有效输入需要 `27648` 个 16 字节传输，输入槽未使用的尾部不是图像。特征张量遵循图中的 `tile4x4_hwc`、little endian、无隐含 channel padding；不把输入 NHWC 直接当特征 tile 布局。

第一条独占闭环选择已有 **Stem 输出 → DDR → down2 DW/PW**：Stem 589824 字节，对应 36864 次单拍写与同数读；复用已有逐项黄金值，不增加 CRC 探针或新神经网络。首轮先确定读回完全一致，再记录吞吐。模拟端点的周期不得标成真实 DDR 带宽。

独占闭环确认之后才接三客户视频仲裁：视频读/写优先，CNN 连续最多 16 个传输单元后重仲裁，每次读必须登记客户及预留容量。当前全局单请求桥不是已完成的三客户仲裁器。

## 地址区间的证据边界

实际配置为 25 位 native 地址、16 位物理数据单位，对应 64 MiB **逻辑地址跨度**。这不是已实测容量。

视频四个 base 为 native `0 / 7000000 / 14000000 / 21000000`。若每帧恰为 1280×720×4 字节，则最高视频末地址为 45686400 字节，小于 CNN 起始 54525952 字节，间隔 8839552 字节。生产地址计数器没有在本轮证明独立的满帧硬边界，所以该算术不等于异常输入下的绝对防越界证明，也不授权现在进行视频并发写。

边界向量覆盖逻辑地址进位、图中存储首末块及邻块，不把 IPUG035 的 PH1A DDR3/DDR4 图示冒充 PH1P DDR2 的实测 bank/row 映射。

## 下一步实际执行顺序

1. 用户方便时先运行已交付的独占 DDR 诊断，记录预期值、实读值、状态、3 次复位及 10 分钟稳定性；旧绿色 TEST 是计算自检，不替代 DDR 读回。
2. 依据结果和厂商规则关闭 AW/W、R 最早返回、写可见性三项具体接口缺口。若必须改变旧桥接口或完成语义，提出一个集中决定，再做独立候选，不改冻结资产。
3. 接入上述 Stem → DDR → down2 独占闭环，逐字节核对并记录实际等待。
4. 最后接入视频优先仲裁和输入槽。当前不需要现场标注视频，也不需要 DDR 芯片内部电路图。

总结：软件侧地址、mask 和所有权验证可先做完；真正阻止实板 CNN 搬运的不是缺少通用 DMA，而是少数尚未证实的控制器完成与时序规则。先补这一层，不扩展无关结构。

# Stem → down2 完整张量交接：滚动状态与结论

## 1. 当前抓手

**完整功能仿真通过；不是可直接上板的完整 CNN。**

本轮从“down2完整层读取独立测试输入”推进到：原始RGB实际经过Stem算术链，真实缓存读口导出的中间张量，再输入完整down2。正常和反压两种模式均完成，差异、重复和漏写均为0。

仍未通过/未完成：新Stem调度器严格门禁555项，TB严格门禁415项；新调度器没有TD综合/布局布线证据；两段共享一个算术核的可综合顶层、实际DDR搬运、真实QAT参数和完整网络未完成。不得用旧壳资源代替新调度器资源。

## 2. 代码和实际数据路径

- `rtl/road_stem_tile_scheduler.v`：本轮新增固定Stem调度器，算术算子外置。无UART、AXI、DDR或通用指令系统。
- `tests/tb_stem_down2.v`：沿用完整down2验证，新增真实Stem交接。
- `tests/stem_driver.vh`：Stem输入、算术级对拍和实际导出记分牌。
- `run.py`：确定性整数参考、严格门禁、规格生成、ModelSim执行、完整输出复核和旧文件哈希检查。

```
288×512 RGB888
  → 新Stem固定调度器 + 冻结MAC/重定标/SiLU
  → 实际256字节/tile缓存读口 ×2304
  → testbench中间存储，589824字节
  → 按全图坐标提取9×9×16 halo
  → 冻结down2 DW→PW ×576
  → 实际384字节/tile缓存读口
  → 221184字节完整输出
```

期望Stem文件只用于比较；没有预先写入下游输入存储。下游每个有效输入必须来自Stem真实导出。此处的中间存储是**仿真存储**，并非DDR实现。TB分别实例化两套算术链、先后运行，不能据此报告部署资源；最终单核互斥复用接线仍需做。

## 3. 冻结数值与布局

| 项目 | 规格 |
|---|---|
| Stem | 3×3/s2/p1，3→16；输出144×256×16 |
| down2 | DW 3×3/s2/p1，16通道；PW 16→24；输出72×128×24 |
| 局部布局 | tile4×4 HWC，不填充通道 |
| Stem halo | 9×9×3，243项；有效RGB在RTL仅执行一次pixel−128；padding直接写算子零 |
| Stem归约 | OIHW顺序27乘积，四组；末输入掩码0x07；输出尾batch掩码001 |
| 算术 | 沿用signed33 MAC、末组INT32、RNE、饱和、完整1024项SiLU运行时装表 |
| 参数 | TEST_ONLY，固定种子43；复用已有动态重定标接口，不是部署QAT参数 |

Stem post使用16777191/2^28，保留78种实际输出值；这只是非平凡功能向量的尺度，不是从训练模型导出的部署尺度。down2直接消费该INT8张量，不再中心化。全图整数卷积与2304个局部Stem窗口比较差异0。

每个Stem tile在缺最后1项halo时尝试启动，每个down2 tile在缺最后1项halo时尝试启动，共2880次均未进入busy。边界padding实际装载Stem2697字节、down27184字节。反压模式包含可复现气泡及长反压，检查MAC输入、写回和导出负载保持。

## 5. 周期与较差部分

以下是RTL功能仿真的忙周期，**不是已签核100MHz后的板测FPS**。

| 窗口 | normal | stalls |
|---|---:|---:|
| Stem核心 | 10911744（4736/tile） | 13199941 |
| down2核心 | 971712（1687/tile） | 1373436 |
| 两段核心合计 | 11883456 | 14573377 |
| Stem导出窗口 | 592128 | 1522227 |
| down2导出窗口 | 221184 | 572549 |
| 完整TB端点总周期 | 14023618 | 17995003 |

预装载另计：Stem halo559872、参数482、表1024次；down2 halo746496、参数652、表1024次。Stem导出窗口每tile含256次传输和1拍窗口开销；down2导出计数为原核export busy窗口，因此二者窗口定义明确列出，不用于虚构加速。完整端点计数还包括复位、拒绝部分装载的测试脉冲和驱动周转，不能声称都属于硬件必要开销。

normal核心互斥分类如下，按从上到下优先级归类，不重复相加：

| 分类 | Stem | down2 |
|---|---:|---:|
| 提交端反压 | 0 | 0 |
| 预约/后处理入口阻塞 | 0 | 562176 |
| 实际写回接受 | 589824 | 143424 |
| MAC输入组接受 | 884736 | 127872 |
| 操作数准备/发射 | 884736 | 112320 |
| MAC结果等待 | 1548288 | 0 |
| 后处理退休等待 | 6782976 | 25344 |
| 状态周转 | 221184 | 576 |
| 合计 | 10911744 | 971712 |

Stem后处理等待约占62.16%，原因是当前每batch必须等全部通道真实写回后再发下一batch，刻意没有新增跨任务重叠。此项不是SiLU本身固定需要6782976拍，也不是全部空闲；等待窗口内可能有正在运行的流水。down2存在流水重叠，提交优先分类会遮住同时发生的MAC接受，不能将表内MAC栏当全部MAC忙周期。

**5FPS仍未证明。** 100MHz下整网预算20000000周期，当前仅前两段核心已用11883456，剩8116544供其余网络及搬运/后处理，预算压力明确。完整功能优先按用户顺序继续；后续最有价值的单变量优化是复用已有的有界结果预约/退休机制，减少Stem等待整batch退休的周转，而不是增加MAC路数或盲目缩网。本轮不实施该优化、不改变算术II。

## 7. 失败记录与下一步

| 记录 | 原因 | 最小处理 |
|---|---|---|

| specifications/及后续失败目录 | 端口数断言错误、沙箱WinError5、子目录workspace边界 | 修文档脚本及工作目录，未改RTL |

下一步按既定顺序做实际DDR接口搬运仿真，不扩展CRC探针：

1. 只读核对当前PAXI桥和官方控制器真实端口、地址单位、读返回顺序、AW/W约束和写后读可见性，输出明确接口表。
2. 将本轮实际Stem输出/下游halo地址流接入最小有界搬运适配，先验证单客户；不未经证明地并发接视频。
3. 同一张量做DDR写→读→down2闭环，注入独立ready背压，检查地址覆盖、响应归属和取消后晚返回。
4. 写完成/读可见性没有证据时停止相关发布分支，集中提出缺失接口决定；不用固定等几拍代替。
5. 单客户完整闭环后再做视频并发和可综合共享核顶层；真实资源/时序单独跑，最后才是上板。

本轮没有训练、修改生产工程、综合新壳、生成位流、上板或写Flash。

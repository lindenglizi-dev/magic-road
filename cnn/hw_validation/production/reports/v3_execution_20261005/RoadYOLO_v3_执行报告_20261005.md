## T05：完整 SiLU 官方 RAM 停顿故障与最小实验修复

使用官方 PH1P ERAM 加密模型和 GSR，实际运行完整 SiLU，不使用手写 RAM 替身。校正测试台在装载接受沿的采样之后：原版无停顿 9/9 正确；停顿 1 拍发生中央区错位，raw=4 期望 2，实际 4。失败日志、逐拍 CSV 和 WLF 保留。ModelSim 进程退出 0 不能覆盖测试台明确的 FAIL。

根因：输出反压时控制流水冻结，但 RAM 的 CEA 恒为 1，RAM 输出继续推进；恢复后旧控制配上新查表值。仅在独立候选副本修改一处：

```verilog
.cea(flag_pipeline_enable),
```

原版 SHA-256 `ee9beb80decb4f276b9ff81214c22f044a71ac1ffc8c72beb1378e6ddb07a7ed`；候选 `5f357b493c7b3f941d9fa954a0ce5ec09091e466b641474360d2f64d0e42c938`。不改变接口、表值、数值契约或增加流水级。合法装载须 pending 排空；此时 output_valid=0，pipeline_enable=1，因此 RAM 随流水冻结并不阻止合法装载。具体动态检查及最终覆盖范围以官方回归报告为准。

候选路径：[silu_shared_unit.v](../v3_silu_stall_candidate_20261005/silu_shared_unit.v)。原生产 SiLU 未合入修复。修改计划：[repair_plan.md](../v3_silu_stall_candidate_20261005/repair_plan.md)。

相同契约和官方静态接口下重跑完整严格检查：原版 174 条，候选 242 条；增量来自 VG146 +31、VG147 +37 的控制锥检查。不能把数值修复称为严格门禁改进，且未经分类不能称这些诊断全是假阳性。原始结果见 [gate_comparison.json](../v3_silu_stall_candidate_20261005/gate_comparison.json)。生成了接口核对后的规格及 WaveDrom 周期图，但没有凭它们宣布 RAM 映射或时序通过。

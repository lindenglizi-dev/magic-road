# RoadYOLO 最小计算链前置验证报告

日期：2026-10-06，Asia/Shanghai。

## 未通过问题和本批结论

最小计算链尚未跑通，原因不是本批出现SiLU数值不匹配，而是发现已有MAC与部署契约的部分和溢出行为冲突。依照v7“遇到量化契约冲突停止相关步骤”的要求，暂停步骤三联合RTL接入及其后的物理优化，先完成不受影响的步骤一、二及旧MAC定向复现。

本批没有改变生产、训练、SiLU、复位、时序例外或验收门槛，没有位流、上板或Flash操作。工程仍不是Git仓库，无分支或提交。readable-verilog-generator用于区分功能与交付证据；ponytail原则用于复用现有参考、向量格式和测试台，没有另建硬件框架。

## v7建议的合理性

先做1×1、16输入通道、3输出通道、2×2空间位置的最小链，逐级比较真实表结果，并将装表与运行耗时分开统计，是合理的。先不接DDR和视频，能避免把多个控制问题叠加。II=11的探针确实不能承担每拍24 MAC的性能假设。

人工表、真实表、不同strict对象计数和不同路径范围必须继续分开。本批不做SiLU地址压缩、控制复制或同步复位改造，因为没有相应新增关键路径支持。

## 已执行内容

### 基线和量化契约

冻结了旧MAC、MAC测试台及Python参考、round、最小CEA SiLU、部署契约、真实表、人工表生成器和SiLU诊断SDC的独立快照；工具和输入哈希见 [baseline_manifest.json](baseline_manifest.json)。旧报告保持不变，旧SDC仅作为SiLU历史基线，不能用于联合链签核。

量化单位、输入/权重scale、zero-point、bias单位、两次M乘法、移位、最近偶数舍入、饱和与异常要求见 [量化与接口契约](QUANTIZATION_CONTRACT.md) 和 [测试参数](test_parameters.json)。这些是明确标记的测试参数，不是训练模型参数。

### 逐级 Python 参考

使用固定seed=42，生成基础16通道及13通道尾组用例，各12个输出。导出每组24乘积、12 pair、6 quad、3 dot、带偏置累加值、SiLU前完整乘积、未饱和舍入结果、INT16输入、查表地址、真实SiLU输出、后乘积、后舍入、INT8值及写回地址。

执行结果：

- 基础用例192个有效MAC，尾组156个有效MAC；各有8个输入组、12个输出地址。
- 两组bias仅加入一次，按独立完整点积核对全部通道结果；普通用例也与冻结旧MAC参考一致。
- 尾组无效lane故意填非零极值，mask为0x1f，不能以零填充掩盖掩码错误。
- 对冻结真实SiLU表进行65,536输入Python检查，逐项等于冻结黄金文件；这不是新增RTL全域通过记录。
- 6个正负半值最近偶数用例、4个饱和边界和4类非法参数拒绝通过。INT8负端饱和属于独立重定标边界测试；不能声称这些输入经真实SiLU仍能到达负端饱和。
- 前后量化比例用有理数断言一致，shift=63、非法乘数和超INT32输入明确拒绝。

入口为 [reference.py](reference.py)，机器可读逐级结果为 [stage_vectors.json](stage_vectors.json)，最终执行日志为 [reference_final.log](reference_final.log)。没有专用readable-python/script技能可用，Python只通过实际自检，不声称通过专用严格门。

### 旧 RTL 对拍和冲突复现

复用原 `tb_road_mac_probe`，Icarus使用Verilog-2001编译，未改测试台或DUT。基础及尾组分别实际出现 `PASS cases=8 errors=0 reset=1`，证明这些普通输入的MAC中间值和结果匹配，不证明后续round、SiLU或特征写回已经连通。

原测试台会断言非末组后的接受间隔为11拍，终态后的下一接受间隔为16拍（包括它施加的3拍结果背压），accept到terminal valid为9拍。本次两套8组向量通过这些实际断言，所以II=11仍是本版本MAC基线；没有测出II改善。未施加背压的terminal间隔仍未在本批独立测量，不将减去3得到的13拍当新实测。

日志：[基础MAC RTL](base_mac_rtl.log)、[尾组MAC RTL](tail_mac_rtl.log)。仿真结束时间包含启动和额外复位测试，不作为最小链端到端周期。

具体冲突反例：

| 项目 | 第一个输出通道数值 |
|---|---:|
| 偏置 | 2,147,483,643 |
| 第一组点积 | +8 |
| 第一组部分和 | 2,147,483,651，超出INT32但在signed33内 |
| 第二组点积 | −8 |
| 最终完整结果 | 2,147,483,643，在INT32内 |

旧Python参考在第一组就返回fault与三路全零。将该第一组送入原RTL，实际 `PASS cases=1 errors=0 reset=1`，核对到相同的提前故障和全零终态。此PASS是旧行为成功复现，不是部署契约通过。反例及源码依据分别见 [counterexample_legacy.txt](counterexample_legacy.txt)、[counterexample_rtl.log](counterexample_rtl.log)、MAC快照第940/949/958及1030行附近。

部署契约明确写有“partial_overflow: do not fault solely because a partial sum temporarily exceeds int32”；因此不能靠避开极值用例或修改期望值来宣布相容。

## 失败留痕

首次MAC编译使用多一级相对路径，Icarus退出1，找不到源码而未展开DUT；改用已核实绝对路径后编译、执行退出0。哈希清单首次把Python缓存目录作为文件读取，退出1；改为只取文件后重跑退出0，原失败日志 [reference_frozen_run.log](reference_frozen_run.log) 保留。两项都是诊断命令/脚本问题，不计为数值通过或硬件失败。命令与退出状态见 [commands.json](commands.json)。

## 需要决定和随后执行内容

建议保持已冻结部署契约，允许在独立验证目录建立signed33跨组累加、末组才检查INT32的MAC候选；旧核不覆盖。三路原子故障、偏置仅一次、first/last、反压和复位取消需重新对拍，并保留旧核提前故障负例。改动不默认改善II，必须分别测量。

确认该语义选择后，继续真正接通requant乘法、round、真实SiLU、输出重定标及片上写读回；随后按v7测全过程周期并重新物理实现。在这之前不声称12个输出已经由硬件整链生成、不声称5 FPS、也不扩大到DDR、视频或完整网络。

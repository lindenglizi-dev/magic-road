五、按位置归类的差距与最小处理路径

G1 / 高优先 / 缺证据：accepted → visible 的依据缺口。
位置：F/rtl/road_paxi_mailbox.v:335-341、415-418；F/rtl/road_stem_ddr_sequence.v:203-208、324-339。
当前写响应驱动地址/张量阶段前进；这对独占诊断是一项可实测假设，但正式数据发布需要 NORMAL 模式下匹配 IP 的先写后读保证。
F/physical/ddr2/src/rtl/top/ph1p_ddrmc_top.v:339-341 的内部 BRESP/BVALID 未导出，BREADY=1；不能自行接出 B 就称“物理写完成”。
最小处理：保留 accepted 语义；由 C8 在现有服务上采用厂商确认的顺序/屏障，不写第二桥，不固定等 N 拍。
影响：输入槽 READY、Stem→DW、PW→CSP 读取和地址重用。真实 DDR 全帧测试可提供实例证据，不单独替代通用接口保证。

G2 / 高优先 / 缺证据：受控端点提前落实写，排除了关键 RAW 反例。
位置：F/tests/tb_frontend_ddr_tensor.v:208-230 在源请求接受时立即修改内存，:252-260 才延后返回响应。
因此随机请求/响应背压没有验证“写 accepted 之后内存尚未对后续读可见”的情况。
最小补证建议（由 C8 决定并实施）：沿用同一个端点，用一个受控延迟写效果负例把 accepted 和可见时刻分开，并断言当前服务是否依赖 RAW 保证；不要新建桥或另跑整套无关探针。
逻辑反例：写 X 接受 → 成功回执 → 读 X 接受 → 若允许读绕过未生效写则读出旧 X。此为尚未排除的调度假设，不是已复现匹配厂商 IP 的错误。
若厂商明确保证该场景 RAW 顺序，则应把该保证写入匹配端点合约，而非保留不允许的反例调度冒充硬件行为。

G3 / 高优先 / 缺证据：最终 PW 写后无 DDR 消费者核验。
位置：F/rtl/road_stem_ddr_sequence.v:229、317-322、329-339；F/tests/tb_frontend_ddr_tensor.v:215-245。
黄金比较在输出组装后、写 DDR 前；读取地址只选 RGB 和 Stem，未读 PW 区。完整 PW 受控内存写值虽已检查，真实板端最终 PW 回读仍未覆盖。
最小处理：下一消费者优先从现有 PW 区读取并逐项对拍，或在现有序列器加一次有限 PW 读回；二者选最贴近主线的一种，不增加 CRC 子工程。
即使本版板上显示 PASS，也不能把“最终 PW 内容被读回验证”勾为通过。

G4 / 条件成立：AW/W 的范围是匹配 PAXI，不是任意标准 AXI。
位置：F/rtl/road_paxi_mailbox.v:184-190、326-341。
常规无故障期间保持 VALID/载荷至 READY；AW 接受后一拍呈现 W，符合手册 AW 先行且 W 最多落后两拍的示例模式。
仍需确认“两拍”限定首次呈现还是实际接受，以及 WREADY 长背压时允许的保持规则。不得据图示推广为任意 AW/W 乱序或任意控制器均可用。
超时/PHY 故障分支会终止等待并撤销请求；这是 fail-stop 边界，不是正常背压期间的继续服务承诺。

G5 / 已证明：当前全字 mask 与 native 地址一致；扩大接口时有明确新前提。
位置：F/rtl/road_paxi_mailbox.v:98-100、188、200；F/rtl/road_stem_ddr_sequence.v:121-123、322、329、336-337。
128-bit 完整写使用 16'h0000，高有效屏蔽，即 0=写入。不能用标准 AXI 常见“1=字节写使能”的解释接入。
native=byte_address>>1；一个 16 B beat 的 native 步长为 8；mailbox 要求 native[2:0]=0。
RGB byte[0x03400000,0x0346c000)，Stem byte[0x03500000,0x03590000)，PW byte[0x03600000,0x03636000)，三者互不重叠且位于 52–64 MiB 内。
厂商 ROW_COL_BANK 映射为 row=native[24:12]、bank=native[4:3]、column={native[11:5],native[2:0]}，不能将 native 错当简单字节地址。
最小集成规则：一张权威字节地址表；仅在一个边界转换一次；先在宽地址检查范围/长度，再截成 25 位 native，避免高位先被截掉后范围检查误通过。
当前诊断三块互不重叠，不等于已经证明与生产视频环形 bank 不重叠；视频仍须单独核对。

G6 / 条件成立：单客户的返回归属和容量预留。
位置：F/rtl/road_paxi_mailbox.v:58-70、123、178、192-205、242-258、365-377。
唯一 busy 请求、单拍结果保持和 ack 释放提供隐式 owner，AR 接受同拍返回已经处理；旧 C9 对早返回的缺口不能套在这个实现上。
但 F/rtl/road_stem_ddr_sequence.v:131 的 reg_write_owner 只是 RGB/Stem/PW 张量写阶段，不是视频/CNN 客户 ID；toggle 是握手相位，不是可独立取消的持久 epoch。
最小集成规则：在统一服务接受请求时锁存客户/代次并预留返回容量，直到消费或确认排空才释放；不得把两个客户的 PAXI 输出直接并联。

G7 / 条件成立：共同硬复位；缺证据：独立取消与 late-return drain。
位置：F/rtl/road_stem_ddr_board_top.v:83-84、98-131、145-146、169-170；F/rtl/road_paxi_mailbox.v:209-215、263-289、402-406。
共同复位断言会取消本地旧事务，各域两级同步释放；释放不同拍不等于允许单侧独立复位。复位恢复后重新写输入、重新装表/参数。
F/tests/tb_frontend_ddr_tensor.v:175-185、189-207、360-378 同时复位序列器和受控端点并清空模拟内存；真实 DRAM 不会因为该复位自动清零。
因此该回归没有保留控制器旧队列来检验晚返回，也不能证明 DDR 继续运行时单独复位 CNN 安全。
最小集成规则：独立取消只停止新事务；保持已呈现请求至接受；已接受读仍排空并按旧 owner/epoch 丢弃；写的重用屏障由真实退休/顺序保证定义。不得用清空本地 busy 代替排空。

G8 / 条件成立：超时故障闭锁；不得视为不中断视频的恢复机制。
位置：F/rtl/road_paxi_mailbox.v:327-341、356-377、389-399、430-445；F/rtl/road_stem_ddr_sequence.v:396-417。
例如 AW 已接受而 W 超时，诊断会闭锁，但控制器可能仍保留未配完的写请求；当前没有 drain。读超时也没有清除控制器晚返回的证据。
当前实验停止且只允许共同复位，因此不要为此新增通用取消框架；接视频前必须集中设计故障作用域，不能为 CNN 重试擅自复位仍承载视频的 DDR。

七、视频多客户接入时才需要的新工作，不在本次另写

1. 继续单一 C8 DDR 服务入口；AW/W 在配对完成前归同一客户，读接受时保存 owner/epoch 并预留返回槽。
2. 视频优先；CNN 连续授予至多 16 个规定传输单元后重新仲裁。先明确授予单位，不能把 AW 和 W 当两个可任意抢占的完整事务。
3. 统一字节区域表覆盖视频、RGB 双槽、特征和后处理；验证地址转换、长度、容量末端与 bank 边界，复用前满足可见/退休契约。
4. 输入 READY 的发布与最后写 accepted 分开；READING 的释放与最后输入读响应消费绑定；旧代次晚返不能污染新槽。
5. 只对共享故障采用共同硬复位；CNN 取消与视频继续运行是新契约，需一次集中决定，不能把当前诊断 reset 当成已有实现。
上述属于未来接入条件，不应倒算成当前专用诊断链“本来就应该有”的功能缺陷。

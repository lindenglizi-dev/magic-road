## 三 改动后的逐拍契约

以last在时钟沿前完成握手为c0：A0输入→c1乘积→c2 pair→c3 quad→c4 dot→c5 signed33归约及末组INT32故障安全终态→c6保持型输出→c7最早ACK。相较原c9发布/c10ACK，省3拍，不删任何算术级。

输出保持寄存器仍存在；在ready=0期间valid/data/fault保持。输入在last接受后仍关闭，终态真正握手后才重开。stage0没有直接接外部端口，因此它下一拍清零不会清除待收结果。单任务归约最大24组/每路192个有效乘积不变；不扩大成无限归约或跨任务多上下文。

偏置只在first替代历史一次；A5内部signed33反馈、signed34候选、末组INT32检查不变。任一路最终溢出仍一次发布三路零值和fault；非末组暂时INT32超界仍可恢复。低有效异步断言与壳内原同步释放完全保留。

### 互斥周期分解与活动计数

无停顿完整核心：512 STORAGE + 640 SEND + 1792 WAIT + 256 DW_POST + 56 drain + 1 done = **3257**。原WAIT为2560，其余互斥类别不变，恰好省256任务×3=768。

无停顿PW-only：128 STORAGE + 256 SEND + 896 WAIT + 29 drain + 1 done = **1310**。

各模块活动计数完整case0为MAC3200、pre2690、SiLU1920、post2561、writeback640；这些周期互相重叠，不能加起来作为总周期。完整预装载2894拍（1024表项、1864输入/权重/偏置写入及控制）、核心3257、导出449拍/384项分别统计，不用窄口传输替代核吞吐。SiLU仍复位后重新装满1024项，不依赖位流初始化。

## 七 更新预算与下一步——不要把暂不缩网变成拖延

67层同一冻结图：条件H48预算50,741,754→**42,628,794**，减少8,112,960拍。各层按实际DW打包任务和PW任务数每任务减3，任务总数2,704,320。真实测量只覆盖本down2/s2小块；stride1、高通道PW及旧层尾模型仍为假设。

同样假设下H24为**32,347,194拍**，156,114,432 MAC、96,900权重、2,141偏置。H24仍未实现、未训练、未测精度，且预算也高于20M。因此**仅取消延迟或仅缩头都不能据此承诺5FPS**。两份预算均未计完整DDR、非卷积、NMS、动态量化和逐tile DMA，不能换算成实测FPS。

当前下一项单变量优化可先定位**PW ACK→下一first的2拍**：只检查能否在等待终态期间准备下一任务首组，保留单归约与结果确认规则。每任务最多再省1拍，按现任务数最多约1,386,432拍；收益仍有限，不能无期限循环细修。尚未实施该优化，也未授权改II或跨任务MAC重叠。

主线下一阶段应转入框架C：动态pre/post参数和INT16预测旁路的实际层验证，先拿通用参数真实成本与吞吐，再以同一个H24软件对照决定精度取舍。若要显著压到20M，则必须提出更明确的任务重叠/吞吐或模型结构决定；本报告不默许这些额外改动，不自动训练或缩网。

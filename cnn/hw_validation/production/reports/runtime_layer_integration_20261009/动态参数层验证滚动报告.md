## 动态参数如何进入小块

仍然先装1024项SiLU表及原1864次数据写入，然后装84个参数字。kind6地址0至39装pre multiplier，其中0至15为DW、16至39为PW；kind7地址0至39装pre shift，40/41装DW/PW post multiplier，42/43装DW/PW post shift。乘数范围0至INT32_MAX，移位范围0至62。

两组参数必须顺序装全；地址0可重新开始一组装载并撤销该组完成标志。只在idle写参数，计算期间参数不变。后处理接收一个batch时按原接口锁存系数和元数据，DW不同空间点仍使用同一逻辑通道的参数，PW三路使用各自通道pre参数。复位使完整标志失效，必须重新装表及参数。这里只接测试参数，不代表真实模型量化参数已准备好。

## 置零告警的具体归因

直接对重复实例执行层级查询，会使TD将同名定义内的局部网线名称当成顶层名称；`more than one Upinst`和`Could not find net`是诊断查询失败，不能拿这些查询结果关闭告警。

改为每个模块定义单独elaborate，并查询未优化网线的DRIVER_COUNT和PIN_COUNT后得到：

| 定义 | 无驱动位数 | 连接引脚数大于0的无驱动位数 |
|---|---:|---:|
| 新窄口壳 | 6 | 0 |
| 层调度器 | 412 | 0 |
| adapter | 0 | 0 |
| MAC | 0 | 0 |
| 后处理 | 63 | 0 |
| 动态requant | 0 | 0 |
| round | 1 | 0 |
| SiLU | 0 | 0 |

例子包括被展开后不再使用的循环变量check_lane、三路31位乘数选择总线的未使用高位、只取标签bits4:2时残留的其他位，以及round中不使用的half最低位。旧runtime壳的67个层级无驱动位可由壳2、后处理63、两次round各1解释。新候选8种模块定义均未发现带负载的无驱动网线，结合动态系数综合网表对拍，没有发现有效参数或RAM数据/地址/使能被错误置零的证据。

这是无驱动网线的对象归因，不是厂商逐引脚置零事件清单；后者工具未导出。SYN-5025原告警保留、不屏蔽，不修改核源码来消除纯无负载中间网线。

## 严格门禁与保留失败

同范围9文件上游原版检查器比较：基线5124条error/24条strict warning，新候选5230/24。这里是交付规则诊断，不能称为5230个编译错误；语法解析错误为0。新增计数主要涉及声明注释、嵌套控制、表达式/组合锥预算及动态存储驱动识别，不自动将语义疑点归为格式问题。

四个新参数数组均有idle装载驱动和完整性标志；地址范围及顺序有显式检查，动态位选择不等于无驱动。两处新11位地址与6位计数比较使用Verilog零扩展，两个参数输入的packed宽度分别96/18位并由三路32/6位拼接。相关数值和握手已经对拍，严格规则仍保持失败，不以人工判断抹除记录。

当前完整源码扫描：compile通过；ast、readability、comment、naming、profile失败；该纯设计闭包不含TB，testbench项目显示通过不能代表TB规范已通过；自动toolchain项为not_requested。实际ModelSim/TD证据单独留存。两份TB有独立失败报告；无端口TB的canonical规格被工具拒绝，提供人工伴随说明，不添加虚假端口。三个设计模块canonical规格和WaveDrom图已生成。

失败均保留：沙箱ModelSim启动WinError623，经非沙箱重试通过；前几次TD层级对象查询失败；目录过长导致TD/规格临时文件打开失败，改用本目录短路径后通过；参数参考导入及完整门禁路径错误已修正。没有为排除这些工具/脚本问题修改数值核、时序约束或生产工程。

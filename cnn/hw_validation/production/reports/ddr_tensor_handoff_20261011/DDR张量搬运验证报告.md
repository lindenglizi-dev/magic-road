# DDR 张量搬运阶段报告

日期：2026-10-11。当前处于“完整层与存储”的 DDR 接入阶段。**完整张量的条件端点搬运通过；真实 DDR 控制器读写闭环尚未通过。** 不训练、不改生产、不生成位流、不连接板卡或 Flash。

## 本轮实际完成

复用冻结 Stem、down2、MAC、重定标、SiLU 和旧 H1-B 单在途 PAXI 桥。仅新增测试台搬运驱动与构建、报告文件，没有新增可综合的全张量 DMA 调度器。

实际测试路径为：

```text
RGB 测试向量
  → 实际 Stem RTL，2304 tile，缓存读口导出 589824 字节
  → 冻结 PAXI 桥，36864 次 128-bit 写请求
  → 条件存储端点，明确模拟写可见事件
  → 清空原输入数组为 X，36864 次读回并逐字节对拍
  → 实际 down2 RTL，576 tile，221184 字节最终输出逐项一致
```

本轮不是“把黄金数组直接喂给 down2”：读回数据来自先前写入端点的实际 Stem 输出。原数组填 X 后，只有桥返回的数据才能重新填入。数值参数仍是冻结 TEST_ONLY 参数，不代表训练模型或部署精度。

| Stem 输出字节数 | 589824 | 589824 |

这些周期包含人工设定的条件端点延迟，**不是真实 DDR 带宽、整网周期或板上 FPS**。反压流 AW、W、AR 和结果保持观测计数分别为 109331、184962、139465、338467，已包含在上述时间窗，不再次相加。

覆盖了地址区间 `[0x03500000,0x03590000)` 的所有 16-byte 单元、字节 lane 顺序、AW/W/AR 分开握手、背压稳定性和返回 owner/epoch。576 个 down2 tile 仍覆盖边缘 padding，其中补零字节检查 7184 项。地址单位确认不等于已实测整个 DDR 容量和 bank/row 边界。

取消测试证明：没有写可见事件时，AW/W 已接受也不得完成；取消后仍不能释放，直到显式事件到来才排空并丢弃。AR 在反压时被取消，仍保持到真实接受，再等待晚返回排空。旧 H1-B 回归同时通过。未新增“仅复位桥而不复位控制器”的许可。

## 原厂接口复核结论

依据安装版本的 [IPUG034 手册](E:/Anlogic/TD_6.2.1_Engineer_6.2.168.116/doc/IPUG/IPUG034_PH1P_MIS_IP_Guide.pdf) §2.3.2.2 表 2-17 和当前生成的 `ddr2.v:93-100`：128-bit 数据、25-bit pAXI 地址、26-bit AXI 字节地址相匹配。**pAXI 的地址单位确认为 2 字节，byte_addr 右移一位、每 beat 地址加 8 正确。** 本轮 `reference.json` 是文档复核前的候选映射算术检查快照；此结论和 `status.json` 更新了其证据等级，不覆盖旧报告。

| 项目 | 当前结论 | 尚需的证据或动作 |
|---|---|---|
| 地址换算 | 原文与生成配置吻合 | 全容量和物理边界实测仍待完成 |
| AW 和 W 接受 | 应分别看真实 READY；H1 桥已分开 | 真实 IP 覆盖 W 在 AW 后 0、1、2 拍呈现及独立反压 |
| 读返回归属 | H1 全局单在途保留归属 | 当前实际配置 MC_REORDER=NORMAL，多在途顺序未证实 |
| 写完成与 RAW 可见性 | 未解决 | 不得用固定等 N 拍或 AW/W 接受替代 |
| 复位后在途排空 | 条件端点取消通过 | 真实控制器复位与晚返回仍需验证 |

当前生产包装层存在具体接线问题，但本轮保持其不变：

- `ph1p35_324_ddr_wrapper.v:63-75` 用 AWREADY 作为写数据 ready，没有将真实 WREADY 向上传递；`mc_to_user_interface.v:48-58` 据此同时出队。AWREADY=1、WREADY=0 时可能丢写数据。
- 包装层没有把 RLAST 连到 `O_mc_app_rd_data_end`。
- 真实 PAXI 有 RREADY；只是当前包装层固定为 1，冻结桥没有暴露这个反压口。旧材料“PAXI 无 READY”的说法应限定为当前包装边界。
- 加密 MC 的明文端口包含 BVALID/BRESP，但生成 `ph1p_ddrmc_top.v:339-341` 将其丢弃并固定 BREADY=1。手册没有定义这个内部事件是否意味着后续读可见，不能直接接成 `i_commit_confirmed`。

## 下一步只解决真实 DDR 闭环

1. 使用当前已编译加载的原厂文件集，补匹配 DDR2 512Mbit x16、CL7、BL8 的器件模型与最小测试顶层，先证明初始化和少量已知地址读写。器件模型须是准确料号或经确认的兼容模型，不自行编造存储行为。
2. 覆盖 AW/W 同拍、延后 1 拍、延后 2 拍、真实 WREADY 反压、同址写后读、交错读地址及 NORMAL 返回次序。可观察内部被丢弃的 BVALID，但观察结果不自动赋予其提交语义。
3. 明确写后读保证后，再做生产包装层的**独立副本**修复与可综合张量 DMA；保留当前计算核和数值契约，不扩展 CRC 或通用加速器。
4. 同一批完整 Stem→down2 数据搬到真实 IP 闭环后再谈板测；完成这一项才扩展剩余冻结网络。本轮不要求用户先提供现场标注视频。

具体待厂商确认的问题是：NORMAL 模式下同址写后读的可见性、内部 BVALID 的定义、无读 ID 时返回顺序以及复位后的在途事务处置。不是泛泛“缺数据”，也不需要以无限等待或虚假 commit 绕过。

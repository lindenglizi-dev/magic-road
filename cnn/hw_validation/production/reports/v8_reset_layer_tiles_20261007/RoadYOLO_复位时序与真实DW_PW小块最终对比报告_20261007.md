## 3. 复位候选和功能证据

PH1P 库与实际映射网表显示现有普通寄存器及 DSP 复位为低有效异步模式；库支持 ASYNC/SYNC 选择，不意味着可以批量改变核复位。

候选仅在顶层增加两级释放寄存器。内部复位为第二级输出，不把原始异步复位组合 AND 到核的复位分发路径。原始复位参与接口许可门控，立即屏蔽输入接受与输出 valid，取消旧事务。

| 事件 | 可观察行为 |
|---|---|
| 原始复位拉低 | 两级立即清零；对外 ready/valid 被屏蔽；旧事务取消 |
| 释放后第1个采样上升沿 | 首级变1，内部仍在复位 |
| 第2个采样上升沿 | 末级沿后变1，核在该沿仍采样到复位 |
| 第3个采样上升沿 | 首次允许新的输入传输 |
| 恢复后 | 新 TABLE_BEGIN，再装满1024项表，才允许计算 |

外部生产者/消费者必须丢弃被复位中断的旧协议帧。没有新增 epoch 端口，因此不能宣称可以识别外部把旧 valid 一直保持到新会话的情况。

ModelSim SE-64 2020.4 使用官方 PH1P ERAM/GSR 模型：**原14项回归通过新壳全部通过，另6项复位专测通过**。覆盖释放靠近沿 ±0.1 ns、装表中复位、原核心停顿/导出停顿中复位、重新装表与无旧结果泄漏。两个编译均 0 error/0 warning；每个仿真有2项保留的厂商 INIT_FILE part-select 警告，不依赖 bitstream 初始化。

独立周期审计核对11次正常完成 RUN 和1次复位取消。全部正常 RUN 与旧基线的端点和互斥分类逐项一致；基础核仍 **436周期**：MAC状态占用88（含3个位置间隔及1个最终观察周期）、前重定标132、SiLU84、后重定标120、提交12。这里是占用窗口，不把同拍并发事件重复加算。

TD 保留一个物理首级，自动复制末级为3个副本，扇出110/177/2255；首级只驱动这3个末级D端，没有手动复制首级。QoR `async_reg=0`，本次没有暗中增加属性。仿真通过不是亚稳态或 MTBF 证明。

## 5. 网表与严格诊断的真实边界

实际网表保留26对 DSP SIOU/DSPMULT：24路 MAC，另2个固定系数重定标实现。全部64激活位、192权重位、96偏置位都有动态引用；93个分布式RAM控制器的地址、写时钟、写使能动态，744个RAM数据单元覆盖包缓存；ERAM地址、数据和写使能也动态。RAM的固定无效内容复位不等于数据被置零。

固定系数1/3/5/1可被合法折叠；本次不增加动态系数端口，也不以此资源代表通用乘法器成本。

`check_timing` 的53个dummy逐对象记录：52个DSP `mul9_mode/mul9_signed` 实际接至对应DSPMULT，另1个是 MAC `reg_accumulator_reg[82]_syn_2.ofa` 的未用物理输出。它与旧版SiLU dummy不同，不能套用旧解释。泛化 SYN-5025 的所有实际置零对象仍缺完整工具证据，保持未闭合。

严格旧诊断按对象冻结。独立审计优先分类位宽/计数/状态/驱动语义项：链36、旧壳102、旧TB7；格式与结构项分别187/370/96；余下151/195/116仍单列未闭合。这是诊断分类，不是已证实的独立功能缺陷或自动豁免。新增层仿真检查装载地址顺序/完整性、启动许可、输出保持、计数、故障禁止发布和复位取消；不等于严格检查中的所有语义项已闭合。

## 6. 真实 down2 DW/PW 小块及周期

冻结图顺序为 **16通道DW 3×3/stride2/padding1 → BN折叠后量化/SiLU → PW 16→24 → 量化/SiLU**。输出4×4，9×9×16输入halo；中间4×4×16，最终4×4×24=384字节。所有激活/权重/偏置在运行前动态装载，不用编译期常量替代。

测试包含左上角、内部、右下角和独立PW。左上角有272个补零输入字节、368个实际补零核乘积；右下角按偶数输入尺寸和stride2的实际索引检查，halo没有越界，不人为添加不存在的下/右补零。

当前使用确定性测试量化系数：前M为1/3/5、对应shift0/2/4，后M1/shift4；未接真实QAT参数，没有模型精度结论。未新增动态系数接口。

全部4例的累加、前INT16重定标、SiLU、后INT16重定标及最终INT8逐项一致。主代理另用直接标量卷积、Fraction最近偶数舍入、旧冻结SiLU表独立验证2304条中间记录、1536个最终输出，未调用新参考实现。

## 7. 吞吐结论与下一项单变量优化

PW内两次重定标加SiLU占10368/14081=73.63%；组合占17280/27393=63.08%。当前逐通道串行处理是这个小块的主要占用，存储准备仅768周期，不能把瓶颈归因于尚未测量的DDR。

DW需256×9=2304个有效乘积，使用512组8×3阵列，即12288个物理槽，实际有效利用率 **18.75%**；输入lane利用率56.25%。另外两路输出lane使用零权重，其开mask乘法不算有用工作。PW两组16输入、3路输出都有效。两层不能按24路峰值一视同仁。

更重要的硬约束：冻结MAC **II=11**。对当前整网214465536 MAC、单个24路阵列和100 MHz，即使忽略尾lane、所有内存/激活等待，理想计算下界约 `214465536×11/(24×100000000)=0.983秒/帧`，吞吐上界约1.02 FPS。此为按当前结构推导的乐观上界，**不是整网实测**。因此当前核不能用此前II=1的89.36 ms静态预算证明5 FPS。

推荐下一项只改变一个变量：在新的独立候选中降低MAC接收II，保留signed33完整链路、192项/24组有限归约、末组INT32检查、偏置一次、first/last、三路原子故障、反压与复位取消；先用当前PW任务比较每组接受间隔、完整tile周期和物理资源。**本轮没有修改II；开始该候选需单独批准。** 以达到5 FPS为目标，理想MAC-only II也必须降到2或更低；激活串行和DDR仍需后续验证，不保证II降低即达标。

本次不继续微调SiLU、不缩网、不扩大通用加速器功能。后续仍以冻结RoadYOLO真实层/小块为任务，II候选之外的优化不混入同一次比较。

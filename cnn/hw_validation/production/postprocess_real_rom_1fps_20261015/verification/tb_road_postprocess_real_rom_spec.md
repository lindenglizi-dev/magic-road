# tb_road_postprocess_real_rom 测试台规格

无外部端口、不可综合；唯一时钟100MHz、共同低有效复位。复用原联合测试完整12096 cell→C2唯一候选RAM→C9 FINAL97流程，只把直接查表替换为冻结road_shared_lut_service及受控160-bit物理词端点。端点读取正确G10模型的7168词图像；运行前后check_inputs.py核对物理143360字节、payload和全部sigmoid1024/exp256条目及冻结RTL哈希。

端点只有一个未决读，接受地址后保持所有权至响应消费。共同cancel不能清空端点，真实service负责ST_DRAIN旧响应；共同reset才能清空。随机模式施加请求ready和返回延迟，核对请求地址及返回160-bit payload保持。mode9取消已接受读、允许新C2帧在service排空期间开始、检查恰好一次旧返回排空且完整新帧对拍；mode10共同复位已接受读；mode11仅在受控端点fault边界注入故障、检查service/C2错误及service故障只由共同复位清除。mode7保留原候选RAM响应边界的部分输出错误注入，不声称物理ROM随机故障。

原22项加上述3项组成25项受控矩阵。全部完成的帧核对FINAL97逐条内容、身份/计数、sealed后RAM写冻结、NMS互斥阶段周期及输出反压保持。空表依done计时，非空表同时报告最后接受条目。统一窗口从start接受至最后接受输出/done，ROM与adapter等待计入整个后处理2000000拍预算，功能与预算分别判定。adapter延迟明确为query接受至response握手；不是首个valid延迟。

`response_wait`是未决读期间服务侧尚无可用响应的周期，包含随机响应门延迟，不能把随机模式该计数称为reader本征延迟。正常实际ROM每次读等待8拍，adapter请求接受至响应握手30拍；C2独立服务测试的首次valid延迟29拍采用不同终点。新帧可以在旧读排空期间启动，因此同时报告consumed_words和frame_carried_drain_words，核对`accepted_words == consumed_words - frame_carried_drain_words == adapter_queries`，不会清空旧读迎合计数。

受控端点数组仅为仿真数据源，不是可综合第二ROM；没有第二候选RAM。`USE_VENDOR_ROM`编译分支完全排除该数组和受控响应进程，改为唯一冻结road_numeric_rom_reader及14组/56个PH1P ERAM lane。共同reset只接reader复位；cancel不接reader。请求和响应门只施加外部握手等待，不改reader内部等待。实际模式由PH1P_PHY_GSR共同启动，读取协调者验证过的vendor_rom闭包，并把56个lane和manifest原样复制到每个运行目录artifacts/，满足冻结reader相对初始化路径。

实际模式运行原22项及accepted-ROM cancel/reset两项，共24项；不运行仅受控端点可注入的ROM fault模式11。原mode7仍明确是候选RAM响应边界故障。已知加密厂商PH1P_LOGIC_ERAM在165行发出的112条vopt-2697 INIT_FILE越界警告完整保留，单独标记未解决；新优化必须恰好112条，0条只在日志明确记录vsim-8009载入既有优化缓存时接受。任何新警告/错误或其余数量变化均失败。实际功能通过、厂商告警未解决、静态注释门未过、物理资源/时序未测分开呈现，不把仿真当TD或整网1FPS证据。

受管write-spec拒绝真实空端口列表：`modules[0].interfaces.ports must be non-empty`。保留tb_spec.json作为意图合同，本文件为人工伴随文档，不添加虚假端口迎合工具。WaveDrom由受管renderer独立生成；规格交叉检查门仍为未通过。

# SC500 RoadYOLO 项目架构与原理详细教案

编制日期：2026 年 10 月 13 日。适用项目：lab1_sc500_road_vision。

学习目标是沿一帧道路图像，讲清系统怎样接收、识别、存储和显示，以及每个架构选择解决什么问题、付出什么代价。学完后应能解释当前 RoadYOLO 网络为什么适合继续推进，如何映射到资源有限的 FPGA，以及什么证据才足以说明系统可用。

本教案供后续对话逐课使用。20 课是内容单元，不要求一次讲完一课；每个单元可拆成数次短对话。先通俗解释，再看小例子，最后对应真实文件。原理、目标设计、局部实现和整机验收始终分别标注。

教师判断要点：同一显示帧的不同部分使用了不同的框表，可能出现框边断裂、位置突变或新旧框混用。应先收齐新结果，在下一显示帧起点统一切表。这个措施保证一帧内的框表一致，不能消除检测结果相对当前视频的时间延迟。

## 二 授课方法与完成标准

每次只讲一个可以检查的概念，通常用以下顺序：

1. 用一句话说明今天解决的问题，并连接上一课。
2. 给一个通俗类比或小型数值例子，说明类比不能覆盖的硬件细节。
3. 画必要的数据流或时序图，解释输入、输出和触发条件。
4. 回到本项目，解释为什么采用这个方案及其代价。
5. 指向一处真实代码、契约或报告；第一次只看相关函数或段落。
6. 只问一道理解题，等待学习者作答，再决定补讲或继续。

不得把“听过名词”“回答了是或否”直接当作掌握。每课完成的最低标准是能用自己的话解释一个因果关系；遇到关键误解时换一个例子复查。答案要点留给教师使用，互动授课时先不展示。

公式先配可手算例子，再给符号。第一次遇到缩写先解释中文含义。代码用于验证已经形成的认识，不以逐文件朗读替代理解。每次结尾记录“已确认理解、仍待确认、下一个问题”，保存在本教案进度区即可，不另建多套进度文件。

本轮编制教案不启动训练、仿真、综合或板卡操作。后续练习先用纸面推演和已有报告；需要执行工程任务时单独确定范围。

## 四 逐课教案

### 第 01 课 一帧图像如何成为像素流

**目标与前置**：不需要 HDL 基础。能区分一张图像、图像在内存中的表示、图像在接口上传输的过程。

**讲解顺序**：先把 1280×720 解释为像素坐标网格；再说明 RGB888 为每像素三个 8 位颜色分量；然后引入有效拍、行边界和帧边界。最后区分摄像头侧数据与经过官方 MIPI/ISP/AWB 链后供 CNN 使用的 RGB 数据。

**项目实例**：AWB96 接口一个有效拍携带四个 RGB888 像素。按现契约依次处理高 24 位到低 24 位；实际左右方向还要靠编号图和彩条确认。不要把“每有效拍四像素”说成“每时钟都一定有四个有效像素”。

**选择与代价**：流式接收便于持续视频处理，但要求准确维护顺序、坐标和帧身份。摄像头支路不能等待 CNN；保存能力和完整帧一致性是两个不同问题。两帧各取一半，即使存储速度足够，也可能拼出不存在的场景。

**图示与定位**：画“摄像头 → 官方接收/ISP/AWB → RGB 像素流”；定位 [S4] 的 Clock domains and pixel order。

**检查题**：同一辆移动的车，第 100 帧取上半图、第 101 帧取下半图，颜色值都没损坏，为什么仍然不是正确的一帧？

**答案与补救**：时刻不同，车的位置、轮廓及帧身份不一致。若仍归因于速度，改用“两张不同时间拍的照片拼接”例子，不引入更多接口术语。

### 第 02 课 视频显示与检测结果为什么分开

**目标与前置**：承接第 01 课。能区分视频 FPS、检测 FPS、结果延迟和结果年龄。

**讲解顺序**：画视频和检测两条支路；用“视频 30 FPS、检测 5 FPS”的假设例子解释独立节奏；说明同一批框会被多帧显示复用；最后讲新结果暂存、显示帧起点整表切换和过期撤框。30/5 仅是教学假设，不是本板实测帧率。

**项目实例**：检测第 100 帧期间，视频可能已到第 106 帧。结果带来源帧号与时间信息；完整 pending 表在 HDMI SOF，即新显示帧开始时切为 active 表。一帧内保持 active 不变。CNN 方案规定超过 500 ms 的结果不再画框。

**选择与代价**：保留实时视频可避免检测计算拖慢显示；代价是框可能滞后。整帧切表解决新旧框表混用，500 ms 上限限制陈旧程度，二者都不保证框与当前移动目标完全重合。目标方案没有因此自动增加跟踪预测。

**图示与定位**：画视频帧与检测结果两条时间线；定位 [S1]“框解码与显示”、[S3] 的 display、[S4] 的 Future output interface。

**检查题**：显示到半帧时立即换框表，会出现什么现象？

**答案与补救**：上下部分使用不同框位置，可能断框、跳变或混用。若只说延迟，应要求指出“同一帧内换表”的具体后果。本题是当前待答题。

### 第 03 课 项目的三条边界

**目标与前置**：承接第 02 课。能区分旧 HOG/SVM 实现、CNN 目标方案、开发端训练工具。

**讲解顺序**：先交代保留的历史实现；再画 CNN 部署数据流；最后把 PC/GPU 上的训练、教师模型、参数导出放到图外，用参数包连接训练端与 FPGA 端。

**项目实例**：旧链路包含背景差分、CCL、灰度 ROI、HOG/SVM 等资产；当前 CNN 目标用 RoadYOLO-S4-512，检测 person 和 vehicle，运动与静止目标均在目标范围。YOLOX-S 是开发端教师，可辅助审核与蒸馏，不是上板推理依赖。

**选择与代价**：继续学生网络可以复用模型、整数参考、图描述和已有算术。换模型会连带改变训练、解码、量化与硬件支持，并不会自然消除漏标或域偏移。保留旧代码方便恢复，但阅读时必须先确认一份文件属于哪条路线。

**图示与定位**：画“数据/教师/训练 → 学生模型包 → FPGA 推理”；定位 [S1]“主要决策”“为什么不现在更换训练网络”“总体系统与官方模板的关系”。

**检查题**：教师模型识别更准，为什么不能把教师权重直接加载进当前学生网络的 FPGA 实现？

**答案与补救**：拓扑、张量形状、算子和参数含义不同；蒸馏是训练时转移监督信息，不是把异构权重直接替换进去。若回答只是资源不够，补充即便有存储空间，形状与计算语义仍不匹配。

### 第 04 课 输入缩放与数值约定

**目标与前置**：承接第 01、03 课。能解释 1280×720 为什么映射为 512×288，以及输入处理为什么必须一致。

**讲解顺序**：先算横纵均为 2/5；说明保持 16:9，无需为该比例增加 letterbox；再画五个输入样本如何按面积权重形成两个输出；最后讲 RGB 顺序、NHWC/NCHW 和 pixel−128。

**项目实例**：一维输入 [0,0,100,100,100]，按权重 (2,2,1,0,0) 与 (0,0,1,2,2) 除以 5，得到 [20,100]。这只是解释横向面积权重的小例子；真实二维实现保留横向中间精度，再纵向加权，最后统一除以 25，做一次最近偶数舍入。

**选择与代价**：缩小图像降低计算和存储开销，也减少小目标像素。面积缩放比随意抽点更明确地保留覆盖信息，但需要加权与中间位宽。DDR 输入保存 UINT8 RGB，进入 Stem 时做一次 pixel−128；软件张量 NCHW 与 DDR 的 NHWC 必须显式转换。

**图示与定位**：画五格到两格的面积重叠图；定位 [S4] 的缩放规则、[S3] 的 input、[S2] 的输入尺寸常量。

**检查题**：硬件也输出了 512×288，但用“每隔几个像素抽一个点”，为什么还不能认为它与训练预处理一致？

**答案与补救**：尺寸一致不代表像素分布一致，采样规则改变会影响细节和网络输入。让学习者对照例子算抽点和加权的差异。

### 第 05 课 卷积怎样从像素得到特征

**目标与前置**：承接第 04 课。理解窗口、权重、乘加、输入通道、输出通道和特征图。

**讲解顺序**：先用单通道 3×3 窗口逐项相乘再求和；再移动窗口；然后扩展到 RGB 三通道，解释一个输出通道会汇总多个输入通道；最后介绍 stride 和 padding。

**项目实例**：九个输入 [1,2,3,4,5,6,7,8,9] 与全 1 的九个权重得到 45，偏置为 −5 时得到 40。它只演示乘加，不代表训练得到的滤波器。再回到 Stem：普通 3×3、stride2、3→16，输出 256×144×16。

**选择与代价**：局部共享权重让相同特征可在多个位置被识别；更多通道能表达更多特征，也增加计算和中间数据。特征通道是学习得到的响应，不应固定说成“一层专门找车轮、下一层专门找汽车”。

**图示与定位**：手画滑窗并标出一个输出点；定位 [S2] 的 ConvBNAct 与 RoadYOLOS4.stem。

**检查题**：一个输出点使用了三个输入通道，最后的结果是分别保存三个数，还是按该输出通道的权重汇总？

**答案与补救**：对输入通道及窗口位置的乘积归约，得到该输出通道的一个数。再用两个输出通道说明同一输入可以被两组不同权重解释。

### 第 06 课 DW 和 PW 怎样分工

**目标与前置**：承接第 05 课。理解深度卷积 DW 与逐点卷积 PW，并能解释减少计算的来源。

**讲解顺序**：DW 在各通道内独立看 3×3 空间邻域；PW 在同一个位置用 1×1 权重混合通道；将二者串联，对照普通卷积；最后说明降低计算量并不直接等于硬件同比加速。

**项目实例**：忽略边界等因素，Cin=16、Cout=24 时，一个输出位置的普通 3×3 卷积为 9×16×24=3456 次 MAC；DW+PW 为 9×16+16×24=528 次 MAC。该计算比较算术量，不包括激活、搬运和控制，也不证明两个结构能表达完全相同的函数。

**选择与代价**：减少空间与通道混合的联合计算，但改变模型表达方式，需要训练验证。DW 算术较少，映射到共享计算核时更容易暴露空槽与任务周转成本；PW 通道归约较长，可复用输入和权重。

**图示与定位**：画“每通道各自滑窗 → 同位置混合通道”；定位 [S2] 的 DSDown、LiteResidual、DetectionHead。

**检查题**：如果只有 DW，没有任何通道混合，一个通道能直接利用另一个通道的特征吗？

**答案与补救**：DW 本身不能；后续 PW 等通道混合算子承担这件事。若混淆输出通道与像素位置，回到一格多通道的画法。

### 第 07 课 为什么保留 S4 S8 S16 三尺度

**目标与前置**：承接第 05、06 课。理解 stride 是相对输入的空间步长，不是网络层数或固定框尺寸。

**讲解顺序**：从 512×288 输入推导三张预测网格；再把一个小目标投影到不同尺度；说明高分辨率位置更密，但计算与存储成本也更高；最后解释三尺度共同工作的意义。

**项目实例**：S4 为 128×72，S8 为 64×36，S16 为 32×18，共 12096 个位置。假设目标在网络输入里宽 8 像素，在 S4 网格上约跨 2 格，在 S16 上约半格；这个例子说明分辨率风险，不是检测成功率的保证。

**选择与代价**：保留 S4 是为了保护道路小目标的细节与较密预测位置；它也是较贵的一路。低分辨率特征通常有更大的感受范围，但不能据此保证一定能找回已经丢失的小目标信息。

**图示与定位**：画同一小矩形覆盖三种网格；定位 [S2] 的 STRIDES 和 forward 返回值、[S1]“冻结的网络结构”。

**检查题**：删掉 S4 可能减少哪些开销，又可能让哪类目标更难检测？

**答案与补救**：减少高分辨率头及相关运算/数据开销，但可能损失小目标效果。不能凭直觉给出具体速度或精度变化，需要测量。

### 第 08 课 骨干与特征融合为什么都需要

**目标与前置**：承接第 07 课。能用一张图说明 Backbone、SPPF、PAN、残差与 CSP 的职责。

**讲解顺序**：骨干逐级提取特征；SPPF 通过串联池化融合不同范围的信息；PAN 把深浅特征沿上下两个方向融合；残差保留加法通路，CSP 让部分通道经过处理、部分旁路。分两次讲，先总体信息流，再解释算子。

**项目实例**：按 forward 追踪 p2、p3、p4，再到 td3、td2、bu3、bu4。CSPLite 的一半通道走残差单元，另一半旁路，之后拼接并投影。concat 是沿通道拼在一起，residual 是同位置对应元素相加，二者不能混为一个操作。

**选择与代价**：多尺度融合兼顾定位细节与语义信息，但增加分支、尺度对齐、访存及调度责任。软件中的 split/concat/nearest 在固定图里可以用视图地址表达；残差加法和池化仍需真实计算，不能都叫免费操作。

**图示与定位**：画 U 形融合关系，并用颜色区分 concat 与 add；定位 [S2] 的 CSPLite、FusionCSP、SPPFSqueeze、RoadYOLOS4.forward，以及 [S5] 的视图映射。

**检查题**：两个 H×W×24 张量，concat 后与逐元素相加后的通道数分别是多少？

**答案与补救**：沿通道 concat 得 48，相加仍为 24；相加还要求对应位置、形状与部署数值尺度兼容。

### 第 09 课 网络预测怎样变成最终框

**目标与前置**：承接第 07、08 课。区分原始预测、分数、坐标解码、Top-K 与 NMS。

**讲解顺序**：解释每个位置七个原始值；先讲“框在哪里”和“像不像目标”两类任务；再做一个坐标解码；最后用三个重叠框演示 Top-K 和同类别 NMS。

**项目实例**：原始顺序为 tx、ty、tw、th、objectness、person_logit、vehicle_logit，后两项及 objectness 不能直接当成已归一化概率。教学例子取 grid=(10,5)、stride=4、tx=ty=0.5、tw=th=0，则中心为 (42,22)，宽高为 (4,4)，均为网络输入坐标。源图坐标还需按契约缩放、舍入和裁边。

**选择与代价**：每类 Top128 限制后处理候选量；NMS 抑制同类重复框；每类最多 32 框、两类合计 64。限额让计算和存储有界，密集场景中也可能限制召回。骑行者的人框与车框属于不同类别，可同时保留。

**图示与定位**：画同一目标三个候选框；定位 [S2] 的 DetectionHead、[S3] 的 prediction/postprocess、[S1]“框解码与显示”。

**检查题**：某幅图有 60 辆应检车辆，系统每类最多输出 32 框，仅输出上限就会造成什么限制？

**答案与补救**：即使其余环节理想，车辆召回最多为 32/60≈53.3%。这是该假设场景下的上限，不是当前模型实测召回。

### 第 10 课 数据与评价怎样影响架构判断

**目标与前置**：承接第 03、09 课。能区分模型学得不好、标签不完整、场景不匹配及评价规则不同。

**讲解顺序**：先讲人工真值 GT；用漏标例子说明错误监督；再解释按场景隔离训练/验证/测试；最后讲 Precision、Recall、IoU 和 AP50，并将教师辅助、蒸馏与学生训练连起来。

**项目实例**：真实有 10 个目标，输出 8 框，其中 6 框按匹配规则算正确，则 Precision=6/8=75%，Recall=6/10=60%。AP50 综合变化阈值下的表现，不能用这一组 Precision/Recall 直接代替。教师画出的框仍需审核，不能自动称为完整 GT。

**选择与代价**：按场景隔离比随机打散相邻帧更能检验泛化，但数据建设更费力。训练改善与架构收益需在同一评价口径下比较；阈值、Top-K、NMS 和输出上限都会影响结果。旧 E7/S2/S5 是阶段来源标签，后续授课涉及“当前最好权重”时必须读最新训练报告。

**图示与定位**：画数据 → 训练 → 验证选择 → 冻结 → 独立测试；定位 [S1]“训练接续计划”、[S6]、[S7]。读取旧报告时把日期写清楚。

**检查题**：同一段视频的相邻两帧，随机分到训练集和测试集，为什么测试结果可能过于乐观？

**答案与补救**：场景、背景、对象外观高度相似，未真正检验新场景能力。若回答只涉及标签数量，画两个几乎相同的画面说明泄漏。

### 第 11 课 INT8 量化怎样节省资源又保留意义

**目标与前置**：承接第 05、10 课。理解整数编码、scale、宽位累加、重定标、舍入、饱和与 QAT 的关系。

**讲解顺序**：先用“整数刻度 × 单位”解释 scale；再演示乘法后单位变化；接着讲最近偶数舍入与饱和；最后画激活层和原始预测层两条数值路径。QAT，即量化感知训练，在理解数值路径后再讲。

**项目实例**：教学中令 scale=0.25，整数 6 表示 1.5；不同 scale 下同一整数不代表同一数值。最近偶数示例为 2.5→2、3.5→4。项目使用 INT8 激活与权重、INT32 偏置、signed33 内部累加、INT32 最终结果；经重定标到 INT16 Q7.8。61 个激活卷积经 SiLU 再重定标为 INT8；6 个原始预测卷积输出 INT16，并绕过 SiLU 与 INT8 后重定标。

**选择与代价**：降低存储量和乘法成本，但必须验证量化误差。残差相加和 concat 需要相容尺度。QAT 需要模拟实际 BN 折叠、scale、bias、查表、舍入和饱和；一个 SiLU QAT 钩子或通用 fake quant 不能单独证明部署等价。

**图示与定位**：画两条数值路径并在箭头上标位宽；定位 [S3]、[S2] 的 RoadSiLUQAT/prepare_experimental_qat、[S8]。本课拆为“单位”和“部署路径”两次讲。

**检查题**：一条分支的整数 10 表示 1.0，另一条整数 10 表示 2.0，能直接整数相加并沿用任一原 scale 吗？

**答案与补救**：不能，先对齐尺度；真实和为 3.0。若只记住 INT8 名词，回到厘米与毫米相加的类比。

### 第 12 课 24 MAC 计算核怎样工作

**目标与前置**：承接第 06、11 课。理解 MAC 为乘加，24 个物理乘法槽与一个逻辑卷积输出之间的区别。

**讲解顺序**：先画 8 个输入广播到 3 路权重；每路形成部分和；多组累加得到三路结果；再讲 first/last、bias、尾 lane 和结果确认。

**项目实例**：PW 的 Cin=16 时，每路至少需两个 8 输入组完成通道归约；Cin=192 时为 24 组。8×3=24 表示共享计算核的并行乘法数量，不表示一拍完成 24 个完整卷积输出。每路 bias 只在 first 加一次。

**选择与代价**：有限并行计算便于控制 FPGA 资源；组归约、结果握手和任务切换带来时间成本。signed33 给中间和额外空间；最终 INT32 溢出仍按契约报错，不能用截断冒充正确结果。

**图示与定位**：画 8 输入、3 权重路和三路累加器；定位 [S1]“保留的 MAC 算术接口”、[S3] 的 accumulation。具体 RTL 只选当时任务的冻结源清单，不凭文件名挑任一历史副本。

**检查题**：Cin=24 的一个 PW 输出通道，用 8 输入一组，至少要接受多少组？这是否就是任务总周期？

**答案与补救**：至少 3 组；总周期还可能包括加载、停顿、流水延迟、任务关闭和写回。先不要求记具体流水级数。

### 第 13 课 固定图执行器怎样复用同一套硬件

**目标与前置**：承接第 08、12 课。理解“软件中的层”与“物理硬件模块”不是一一对应关系。

**讲解顺序**：用同一台机器依次加工不同批次作类比；介绍层、tile、输出通道组的循环；再说明固定图描述符提供地址、形状、参数位置和模式；最后讲层完成屏障。

**项目实例**：冻结模型有 67 个卷积，图描述含 106 个节点，并不意味着需要 67 套 MAC 或 106 个独立硬件模块。换层时改变输入输出地址、权重与量化参数等控制信息。同一帧任务内模型版本应一致。

**选择与代价**：固定图只服务当前白名单算子和形状，减小开发范围；不承担通用网络编译器的灵活性。代价是更换拓扑需要重新生成并验证图、地址与调度。已有 graph.json 只说明图和布局，不自动证明硬件执行器已完成全网运行。

**图示与定位**：画“层描述符 → 搬运/计算/写回”，以及回到下一 tile/下一层的循环；定位 [S5]、[S9]、[S1]“层描述符与张量布局”。

**检查题**：某层最后一个算术结果产生了，但它还没有完成可见写回，下一层能直接读取完整结果吗？

**答案与补救**：不能，必须满足存储可见性与依赖条件。用“加工完”和“入库可领取”两个事件区分。

### 第 14 课 DDR 小块缓存与张量布局

**目标与前置**：承接第 04、13 课。能区分容量、带宽、延迟和复用，并理解 tile 与 halo。

**讲解顺序**：DDR 存放大张量，片上存储承接当前局部；画 4×4 输出小块及卷积所需周边输入；讲空间边界和通道尾部；最后从逻辑坐标推到物理地址。

**项目实例**：一帧 512×288×3 的 UINT8 输入为 442368 B。对于连续 4 个输出、3×3/s2，单方向输入覆盖为 (4−1)×2+3=9，因此内部 4×4 输出的输入覆盖为 9×9。特征布局用 tile4x4_hwc：tile 内按像素再通道排列，真实通道数不自动补到 8。

**选择与代价**：小块避免把全网特征图塞进片上 RAM，但引入 halo、地址计算、DDR 等待及跨块重复读取。split/concat/nearest 视图能减少物化搬运；卷积逻辑越界补 0、maxpool 越界补 −128、物理空槽填 0 必须区分。

**图示与定位**：画 4×4 tile 和 9×9 覆盖边界；定位 [S3] 的 ddr/operator_padding、[S5]、[S9]。地址算式等理解坐标后再展示。

**检查题**：DDR 容量能装下所有张量，为什么仍可能跑得慢？

**答案与补救**：容量不等于带宽；传输、重复读、仲裁和响应等待仍耗时。用仓库很大但装卸口很窄作类比，并指出真实 DDR 还存在突发与时序成本。

### 第 15 课 DW 空间共享与 PW 权重驻留

**目标与前置**：承接第 06、12、14 课。理解优化优先从减少重复工作和空槽开始。

**讲解顺序**：先画三个相邻 DW 窗口的重叠；再说明同通道三空间点映射到三条输出路；随后讲 PW 的 16 个 tile 位置共享权重；最后区分数学利用率与端到端加速。

**项目实例**：DW3×3/s1 的三个横向相邻窗口共有 3×5=15 个输入，分两组 8 输入；三路共 27 次有效乘法，在 48 个物理槽中占 56.25%。s2 的并集为 21 输入、三组，共 27/72=37.5%。这是打包方案的槽利用率，不是实测 FPS；尾部不足三点、边界和调度成本另算。

**选择与代价**：保留 MAC 算术接口，通过改变数据安排提高使用效率；代价是稀疏权重映射、三地址元数据和有效路掩码。DW 三路对应同一通道不同位置，量化参数应相同；PW 三路对应不同输出通道，参数可能不同。

**图示与定位**：画三窗并集和 PW 权重跨 16 位置复用；定位 [S1]“选定的 DW 和 PW 调度”。授课时如引用优化收益，再选当时同输入、同范围的实际报告。

**检查题**：DW 三空间点打包后，把三条物理输出路分别套用三个不同通道的量化参数，会发生什么？

**答案与补救**：同一逻辑通道的三个位置被错误缩放。让学习者先说每一路代表“位置”还是“通道”，再讨论数值。

### 第 16 课 ready valid 与背压

**目标与前置**：承接第 12、13 课。能逐拍判断数据是否传输，以及等待时谁必须保持什么。

**讲解顺序**：解释 valid 表示当前数据有效、ready 表示接收方可以接收；只有两者同时为 1 才消费一次；画等待期间 payload 保持；最后联系结果队列容量预留与摄像头支路的特殊限制。

**项目实例**：连续四拍 valid=[1,1,1,1]、ready=[0,0,1,1]，只发生两次传输。前三拍等待同一份数据，第三拍成交后第四拍才能是下一份。ready/valid 的这一语义适用于契约定义的可停顿同域通道，不能直接让摄像头停下来。

**选择与代价**：背压防止下游满时丢数据，却会降低有效吞吐。输出 reservation，即预留容量，是在发射任务前确保它的结果能被容纳。II=1 只说明特定条件下可每拍发射一组，不代表每拍完成一个任务。

**图示与定位**：画四拍 valid、ready、data、accept；定位 [S1]“通用传输规则”“保留的 MAC 算术接口”。

**检查题**：valid 连续保持 5 拍，ready 只在最后一拍为 1，应该把这份数据处理几次？

**答案与补救**：一次。若说五次，指出计数必须跟随握手接受事件而非裸 valid。

### 第 17 课 跨时钟域与输入槽所有权

**目标与前置**：承接第 02、14、16 课。理解 CDC，即跨时钟域；能区分描述符接收确认与数据存储释放。

**讲解顺序**：不同节拍的两个人交接一份文件；介绍单比特控制同步与多比特 payload 的差异；讲冻结数据、request、目标复制、ack；再画输入槽 FREE→CAPTURING→READY→READING→FREE；最后加入 epoch 和复位取消。

**项目实例**：目标域确认已复制任务描述符，说明地址、帧号等信息已收到，并不说明图像数据已经读完。输入槽需要最后一个相关读响应被消费且没有在途请求才释放；也不必机械地等整网 done，因为输入读完与后续网络计算是不同阶段。

**选择与代价**：完整快照握手维护帧身份和数据一致性，代价是保持时间与确认等待。只同步一个脉冲不能证明整条变化中的数据总线安全。复位取消旧任务时，在途 DDR 响应仍需归属、排空或明确丢弃，不能让旧数据命中新任务。

**图示与定位**：画源/目标两条时钟线、payload 稳定窗口、request/ack 和槽状态机；定位 [S4] 的 Capture slots, task identity and CDC，补看 [S11] 的有界显示 CDC 案例。

**检查题**：收到“描述符复制完成”的 ack 后，能立即把对应输入槽交给摄像头覆盖吗？

**答案与补救**：不能，描述符已复制与图像最后一次读取完成不同。若仍混淆，把纸条上的仓库地址和仓库中的货物分开画。

### 第 18 课 DDR 请求接受与写入可见性

**目标与前置**：承接第 14、16、17 课。区分提出请求、接口接受、返回数据、结果可被后续读取。

**讲解顺序**：先画一个读请求及返回，说明 return owner 用于找到所属任务；再讲 AW/W 分别接受；最后讲写入可见性与后续读屏障。实际 PAXI 行为以生成 IP 和厂商契约为准。

**项目实例**：CNN 预留读返回容量并记录 owner 后发请求；接口即使没有 RREADY，返回也不能凭空丢失。写请求进入队列不代表数据已能读到；也不能套用其他 AXI 工程，虚构本接口不存在的 B 响应。CNN 与视频共享存储系统时，视频优先会带来检测等待。

**选择与代价**：明确归属和可见性可防串帧、读旧值、提前发布 READY，但需要计数、容量管理和完成条件。简单固定等 N 拍只有在协议和边界已证明足够时才有意义，不能代替未知完成事件。

**图示与定位**：画请求/接受/返回/消费四个事件；定位 [S4] 的 DDR client and byte addressing、[S3] 的 integration_gate、[S11] 的测试边界。诊断工程的时钟频率不能自动替换 CNN 集成契约的频率。

**检查题**：一项四地址 DDR 诊断通过，能否证明 52—64 MiB CNN 区域、全部地址换算、视频并发和整帧输入发布都正确？

**答案与补救**：不能，只能证明该测试覆盖的条件；还需要容量/边界/掩码/并发/可见性等对应证据。具体缺项按当时报告核对，不能只靠文件夹名。

### 第 19 课 周期预算与物理时序怎样一起看

**目标与前置**：承接第 12—18 课。区分算术量、周期、频率、吞吐、延迟、资源和时序余量。

**讲解顺序**：先用周期除以频率算时间；再分解计算、加载、等待和写回；说明可能重叠的活动时间不能直接相加；然后解释综合资源、布局布线、setup/hold 与约束覆盖。

**项目实例**：100 MHz 目标下，5 FPS 对应每帧平均 20000000 周期预算。214465536 MAC 除以 24 为 8936064 理想计算周期，仅是假设全部槽持续有效时的算术下限，不含尾块、DW 空槽、控制、访存、池化或 NMS，不能直接当全帧测量。

**选择与代价**：增加并行计算可能挤占存储与路由资源；提高频率受实际路径限制。setup 余量为正也要看 hold、复位检查、时钟和外部约束覆盖。诊断工程的“已计时路径零违例”不能单独推出完整系统时序签核。

**图示与定位**：画一条端点总周期轴，用互斥停顿原因划分；定位 [S1]“执行顺序和完成条件”“必要验证”、[S11] 的物理结果和限制。

**检查题**：报告写“100 MHz、24 MAC”，为什么仍不能宣布达到 5 FPS？

**答案与补救**：不知道全帧真实周期与有效使用率，也没有自动包含数据搬运及后处理；必须结合实际实现可达时钟与完整工作负载。若只谈精度，先把性能证据链补全。

### 第 20 课 用证据作出架构选择

**目标与前置**：完成前述课程。能给出条件明确、代价明确、证据范围明确的选择理由。

**讲解顺序**：把“准确、算对、装得下、跑得稳、跑得快”分别列出；将现有报告放到对应项；然后比较优化调度、减少头部通道和换整个网络三种动作；最后用一次完整口头复述串起全流程。

**项目实例**：批准框架中的 H24 仅将三个检测头内部 48→24，保留骨干、PAN、S4/S8/S16 和输出表达。选择它需要相同数据与评价口径下的精度比较，以及完整周期证据；某次标签修正实验失败，并不能单独推出应该缩网。

**选择与代价**：先改善有证据的瓶颈，可保留已有资产并减少验证范围；保留原模型仍可能无法满足时限，不能无限微调回避差距。换拓扑、改数值、改接口或改变真实外设约定各自需要对应的重新验证。

**图示与定位**：画五列证据表；定位 [S1]“唯一缩网备选”“执行顺序和完成条件”、[S3] 的 release_gates 以及授课时最新的有界报告。

**检查题**：小块逐项对拍通过、诊断布局布线通过、已有一份 bit 文件，这三件事能否共同证明道路检测已经达标？还差哪几类证据？

**答案与补救**：不能自动合并成整机结论；需模型与输入绑定、全网数值、真实 DDR/视频闭环、实际整机资源时序和周期、独立精度及持续板测。必须核对三份证据是否属于同一候选与同一使用范围。

| Frame / SOF | 一帧 / 一帧开始事件 | 检测任务号不等于所有物理源帧号 |
| Pixel / Channel | 像素位置 / 同位置的数值分量或特征维度 | 输入 RGB 三通道与中间多特征通道作用不同 |
| Tensor / Layout | 多维数据 / 数据在内存中的排列 | 数值和形状相同不代表物理排列相同 |
| Stride / Padding | 滑动步长 / 逻辑边界补值 | stride 不等于输出框固定大小 |
| DW / PW | 分通道空间卷积 / 1×1 通道混合卷积 | DW 三输出路可代表三个位置，PW 三输出路可代表三个通道 |
| Backbone / Neck / Head | 特征提取 / 特征融合 / 任务预测 | 三者共同构成网络，不是三块必然独立的物理硬件 |
| MAC / DSP | 乘加运算 / FPGA 的硬件资源类别 | 运算次数、并行槽数、映射 DSP 数不是同一量 |
| Tile / Halo | 当前处理的小块 / 为邻域运算补取的周边输入 | 输出块尺寸不等于所需输入块尺寸 |
| Scale / RNE | 整数刻度对应单位 / 最近偶数舍入 | 整数相同不保证真实值相同；RNE 不总是五入 |
| SiLU / LUT | 非线性激活 / 查找表 | LUT 近似需要数值契约，不能任意换表 |
| GT / QAT | 可信标注真值 / 量化感知训练 | 教师预测不自动成为 GT；部分 QAT 钩子不等于部署等价 |
| IoU / NMS | 框交并比 / 抑制重复候选的方法 | 本项目同类抑制条件为严格大于 0.5，等于时不抑制 |
| Valid / Ready / II | 数据有效 / 可接受 / 启动间隔 | II=1 不等于全任务一拍完成 |
| CDC / Ack / Epoch | 跨时钟域 / 对指定事件的确认 / 协调重启代际 | 必须说明 ack 确认的到底是复制还是使用完成 |
| Setup / Hold / Slack | 建立时间 / 保持时间 / 相应时序余量 | 只看一个最差余量不足以说明所有路径被覆盖 |
| FPS / Latency / Age | 帧处理吞吐 / 处理延迟 / 当前结果年龄 | 视频 FPS、检测 FPS 和框的新鲜程度要分别看 |

## 七 项目事实与实现状态的使用规则

### 稳定的课程基线

本教案以 2026 年 10 月 8 日批准框架与编制时仍存在的模型、部署契约为依据：输入 512×288 RGB，person/vehicle 两类，S4/S8/S16 三尺度，67 卷积与 61 SiLU，24 MAC、signed33 内部累加、RNE、INT16 原始预测头。100 MHz、5 FPS、资源上限和精度阈值均按目标或验收契约讲授，不能写成现有整机测量结果。参见 [S1]、[S2]、[S3]。

旧根架构中的 HOG/SVM 是历史实现；教学主线讲 CNN 目标。不同历史验证目录可能包含同名 RTL，各课需要看实现时应从该次报告冻结源清单追踪，不把名字相同当成版本相同。

### 2026 年 10 月 13 日可用于案例的有界快照

最新选读的 DDR 显示 CDC 诊断记录为 BOUNDED_CDC_DIAGNOSTIC_PASS；其 whole_system_signoff 和 strict_delivery 均为 false，board_readback 为 NOT_RUN。报告记录了独立诊断工程的物理结果和临时诊断位流，顶层包含实际 DDR2 IP 与 HDMI，但不含 CNN。参见 [S10]、[S11]。

该报告的已计时记录无负余量，并明确保留外部接口缺少延迟、STA 覆盖率 92.69%、严格门禁未闭合及未执行真实板测等限制。其测试只覆盖 4 个地址、64 字节独立空间、128 字节累计比较量，不能推广成完整 DDR 区域、视频并发或 CNN 5 FPS。[S11]

这更新了早先对话所引用的 10 月 11 日条件 PAXI 仿真快照：现在可讲更进一步的独立诊断案例，但不能把这两种候选拼成“CNN 已上板闭环”。这里不是全项目所有分支的实时状态盘点；涉及最新精度、最新最优权重、最新完整网络进展时，授课前另读相关最新收据。

Git 已于 10 月 11 日初始化。编制时确认仓库为本项目目录，当前分支 work/roadyolo；早先对话的“无 Git”描述属于旧状态。[S12]

### 每次授课前的简短检查

1. 读本教案进度区，确认上一道待答题。
2. 读该课指定的相关段落或函数，避免按历史记忆背诵当前实现。
3. 若讲的是原理，标注例子中的假设；若讲的是项目状态，核对日期、候选、输入、范围与结果。
4. 若新证据改变框架或实现状态，先解释变动，再更新受影响的教案段落；不要回写或覆盖历史失败报告。
5. 继续一次一个问题；不要因为教案已写了答案就替学习者作答。

一、本周到底交付什么

用户最新选择：不要求准确率门槛；检测不要求5 FPS，2 FPS可以；摄像头必须连续运行。
因此本周交付目标为：摄像头→官方ISP/DDR→HDMI持续直播；FPGA从新采集完整帧完成当前CNN、解码/NMS并更新真实框；有效检测结果持续≥2次/秒。
视频沿官方720p时钟与显示时序，CNN忙时跳过完整源帧，不能将直播降成2帧/秒或用静态图片代替摄像头交付。
每次完整有效空结果也计一次推理完成；绘制同一旧框、重发旧表、TEST注入框不计新检测。
全部推理与框处理在FPGA；PC仅用于开发、参考、下载和记录。

时间按连续7个工作日、每天6～7小时有效推进规划，共42～49小时；下表采用6.5小时/日，共45.5小时。
多聊天可准备互不重叠组件，但集成、重型TD、板测存在串行依赖，不能将4个聊天折算成工期直接除4。
这是有条件的冲刺计划，不是保证七天完成。完整67层RTL、DDR视频并发、联合资源及实际2 FPS均尚未证明。

本周保留RoadYOLO-S4-512、512×288、S4/8/16、67卷积、当前24 MAC和动态重定标/SiLU，不默认换网络或重新训练。
唯一联调模型采用 frozen-Stem QAT-G10：
cnn/reports/qat_frozen_stem_g10_20261014_v1/package/
payload SHA256：b35d4a66a69e441dc29bc60c7e3f507661f48da5f33b810d7340f6ed17a65145。
原manifest的诊断标记保留。未改源码/权重前，不能把“没有精度门槛”理解成可以用随机权重或伪造框。

二、简单而唯一的实现结构

SC500 → 官方MIPI/ISP/AWB → 原视频DDR环 → HDMI直播
                         │                   ↑
                         └→ 2/5彩色缩放       │
                            → 独立DDR输入槽   │
                            → 固定图执行器    │
                              → 单一24 MAC    │
                              → 动态重定标/SiLU
                              → DDR特征/跳连/预测
                            → 串行解码/Top128/NMS
                            → 完整64框表CDC → SOF切表/画框

只保留一套视频/DDR/PLL/HDMI、一套算术、一份完整ROM。Stem、DW、PW、CSP、PAN和检测头分时使用同一核。
固定图遍历层、tile、输入组、输出组即可，不增加任意网络编译器、控制外设、通用交叉开关或第二阵列。
concat/split/nearest沿现graph视图地址，不新增完整拼接/上采样副本；SPPF三次池化分别写DDR。
残差保留signed9加法和INT8饱和；六个预测卷积保留INT16旁路，不能被SiLU/INT8截断。

模块与交接接口：
1. 视频与capture（C8）：AWB96四RGB lane；精确面积缩放输出两lane/有效掩码；摄像头不可被CNN ready反压。
   每帧512×288×3=442368字节。SOF选择FREE槽；整帧字节、尺寸及写可见性都成立才发布READY。
2. DDR服务（C8，C9提供差距单）：统一逻辑byte地址；client/epoch/task/return_owner随接受锁存。
   AW/W各自按真实ready，遵守匹配PAXI限制；128bit数据和高有效mask；接受、读可见、旧事务退休分开。
3. 图/算术（C7，C4交CSP任务适配）：activation64、weight192、bias96，valid/ready与first/last；结果96及三路原子fault。
   参数/地址/mask/tag保持同步；现signed33、最大192有效乘积/24组、RNE与II不改。
4. 后处理（C7）：读取三尺度INT16七字段；使用已有sigmoid/exp表；两类各Top128、每类最多32框；同分按cellID稳定排序。
   采用有界串行最小堆/排序和精确整数IoU，避免每个新候选无条件扫描全128项；不增加并行DSP阵列。
5. 显示（C8）：每框97bit，元数据含源帧/模型/时间；源表保持到最后一项复制确认，完整pending只在HDMI SOF变active。
   视频、CNN FPS、结果年龄分开显示或记录；表空、取消、故障不能显示上一代成功。

两输入槽不建立长推理队列。优先新完成的帧；尚未读取的过旧READY帧，可在确认写已可见且无在途访问后丢弃。
不能覆盖CAPTURING/READING槽，也不能用CNN done代替最后输入读响应释放。
本周不扩复杂独立热复位恢复；若真实DDR取消排空尚未具备，错误时停止提交并按已确认的协调恢复边界处理，不假装可独立复位后继续复用。

三、资源必须怎么符合

器件硬限：Slice≤21216、DSP≤40、ERAM≤108。以下是分配目标，不是整机实测值。

归属                         Slice常规目标   DSP   ERAM   只计算一次的范围
A 官方视频底座                   12400         8     40   摄像头/ISP/原视频DDR/HDMI/时钟
B 单一计算与固定图调度            4600        30      5   24MAC+动态后处理；SiLU1+公共工作存储4
C 完整数值ROM及预取                900         0     56   一份140522B包及160bit读取
D 缩放/新增DMA/检测后处理/框显示    1100         0      6   缩放2、DMA/CDC2、TopK/NMS2
合计                            19000        38    107
相对硬限余量                     2216         2      1

19,000是常规收敛目标；实际联合实现若为19,001～21,216，只能在所有必需模块已包含、PLB/MSlice及实际时序通过时作高风险候选。
可根据首次联合报告公开重分配B/C/D目标，不能各聊天自行领取余量。40/108/21,216不放宽。
沿RB1的布线管理目标：PLB≤2386、MSlice≤7300；PLB≥2520或MSlice≥7706先处理拥塞。它们是余量管理线，不是新增器件硬限。

目前为什么还不能宣布资源符合：
- 官方视频历史实测12358Slice/8DSP/40ERAM。
- 深PW独立壳4101Slice/30DSP/9ERAM：输入2、权重6、SiLU1。
- 首残差CSP独立壳5396Slice/30DSP/1ERAM，非完整CSP2；不能当成额外再加30DSP，也不能直接扣掉猜测的壳成本。
- 历史ROM联合接入增量2697Slice，与C目标900差距明显，范围也不同；缩减收益必须实测。
- 现S1仅功能10场景通过，新物理实现尚未运行；旧前三层15794Slice不能作为S1资源。

必须落实的四项资源收敛：
R1 权重仓：保留PW输入2ERAM，6ERAM整分片权重改为当前三输出通道活动bank。
   最大3×192=576B、24×8bit×24深，目标浅LUTRAM；原2304B常驻仓退出候选。保持192bit并行权重口。
   group-major循环同时改组间装载、busy、expected_tag和真实退休；组装载等待计入总周期。输入/输出/CSP旁路生命周期须证明能落公共4ERAM目标。
   这是当前111→107ERAM计划成立的关键。仍保留原8工作ERAM时，40+56+1+8+2+2+2=111，直接超限。
R2 ROM：先RM1的group重复160bit输出寄存删除，再独立压选择树。结构上最多少3840声明寄存位，不能换算成必省3840Slice。
   reader外部握手/响应周期保留；14组真实可达、56ERAM和初始化校验保留。RM1的ROM-R2选择树修改若使时序恶化，则撤回选择树修改，仅保留已验证的ROM-R1重复寄存删除，不反复随机route。
R3 共核：深PW/CSP仅交调度与必要缓存适配；私有MAC/PP、窄口壳、图案源、golden比较、TEST显示不进入最终视频候选。
   不删真实地址登记或写回控制；含功能的测试状态不能整段盲删。
R4 新增功能串行：TopK与NMS复用每类候选存储；sigmoid/exp读原完整ROM，不新增两份表RAM。
   框叠加先复用现视频路径；必须计64框比较、source-held/pending/active及CDC成本，不把显示逻辑当免费。

容易突破预算的细节：
缩放两份512×3×13累计器39936bit，两ERAM仅余1024bit原始容量；实际bank/写口若多一块，必须从共同台账解决，不能截精度。
TopK每类128×160bit=20480bit，两类2ERAM，只证明容量；160bit记录读写可串行拆成4个40bit词。
三份结果表仅97×64×3载荷18624bit，含三份265bit元数据19419bit；按128bit槽对齐的载荷则24576bit。
三表的CDC/显示生命周期不能凭bit数合并。理想对齐载荷约384个DRAM LUT，实际复制/控制/像素比较还需计Slice/PLB。
若64框逐像素并行比较导致资源超额，先研究按行预处理有序边界的有界复用，不直接增加整帧mask RAM或删框数；该方案须先证明行消隐内完成。
每次实际综合都核对动态操作数、有效RAM地址/数据/使能和唯一DSP实例，防止常量裁剪制造资源通过。

DDR预算：两512KiB输入槽，feature_begin=55574528，70份现分配合计7204864B，feature_end=62779392，arena_end=67108864。
候选逻辑区仍52～64MiB；此容量账不证明与实际视频环不重叠。C8必须核对匹配控制器native映射、实际容量及唯一视频/CNN地址表。
全层特征和跳连留DDR；本周不另做全网in-place存储优化。

四、2 FPS的周期账与结果年龄

100MHz / 2 = 50000000周期/次结果。只需2FPS并不降低ROM、特征容量或视频带宽需求，也不等于整网已跑得动。
新S1同向量完整前三层正常端点15848967拍，原17252079；减少1403112拍，DDR读97564、写78336均不变。
这是受控端点、测试参数和含诊断检查的前缀。不是实际视频并发，也不是整个CNN；剩余34151033拍只是预算余额。
旧13层条件投影与现S1的层范围、参数和窗口不同，不能与15848967直接相加，也不能拿旧标为measured的3层数字替换最新完整前端。

本周管理额度（不是速度预测）：
前端Stem/down2及其取数/写回                16000000
剩余网络算术、非卷积及图调度              24000000
额外ROM预取、DDR竞争和未并入前两项的等待    3000000
解码、TopK/NMS、完整表提交                  2000000
源采集等待、显示边界及整体余量              5000000
合计                                      50000000

真实账本按互斥时间窗口重新分类；已在前端/层周期里的DDR或采集不得再计一次。原诊断输入填充不能冒充真实摄像头采集。
尽量把READY→完整结果做到45M拍内，为采集与显示留余量；它是约束，不是已证明上界。
帧率以不同source_frame_id的完整有效结果计数，报稳定窗口平均和最差结果间隔；SOF表切换、零框和错误分别统计。
视频显示FPS、CNN完成FPS、实际表更新FPS和结果年龄分别测。重复旧表不能提高检测FPS。

必须单列的显示契约问题：
原框过期为500ms，用户目前只降低检测速度，未明确改变过期阈值；本计划默认保留500ms。
设新结果生效时源图已老A毫秒，连续两次表更新间隔P毫秒。要整段都可画旧表，需A+P≤500ms。
P恰好500ms且A>0时无法满足，因此2FPS可能出现短暂撤框；视频仍可连续直播。
若接收时A已超过500ms，整表不得作为当前框显示。不能只报告2FPS而隐瞒所有结果已过期。
优先选择最新完整源帧、减少排队、显示age。若用户希望2FPS时框持续保持，提出“仅演示模式1000ms过期且显示年龄”的明确选择；未获选择前不修改阈值。
2FPS更新率不等于500ms端到端延迟；共享时基、CDC和SOF的延迟必须一起量到。

六、准确率结果预计是多少

检测没有一个通用“准确率百分数”。对本工程分别报告Precision（画出的框有多少正确）、Recall（真实目标找出多少）和AP50。
当前唯一INT8开发模型在17张已用来选模的开发图上，score阈值0.5、匹配IoU≥0.5的已保存结果：

类别       Precision   Recall    AP50
person       48.21%      29.35%   26.33%
vehicle      32.61%      17.24%   13.15%
两类平均AP50约19.74%。它不是“两类平均识别正确率”。

当前规划预期：若同图、同payload、同预处理，且67层中间值、三头输出与解码/TopK/NMS最终框表已验证逐位一致，阈值及评估程序相同，则同一固定集上的P/R/AP50应与软件完全相同。
参与该固定集比较的帧不能丢失、重复、串帧或被额外截框；漏结果也必须计入评价，不能从统计集剔除。直播按计划跳过源帧与这个固定集对拍条件分开报告。
这不是对新现场的泛化预测。目前只完成前缀CPU和部分RTL证据，尚未满足上述整网前提。
源帧检测精度用对应source_frame_id的真值评价；当前直播画面叠的是最新结果，并非严格源帧，不能把当前画面错位当作源帧指标。

不能只挑17图报喜：同一INT8模型旧256图AP50为person1.48%、vehicle6.18%，明显更差。
17图共179个GT（person92、vehicle87），机位不均衡且用于开发选择；旧256密集目标、场景和来源不同。
两组是历史锚点，不能把它们的最小/最大值当作新摄像头精度区间或置信区间。
新机位可能好于、差于或不同于这些结果；当前没有足够独立标注来承诺现场80%、90%或95%。

与父FP32相比，当前17图平均AP50仍下降29.41个百分点。纯RTL接通不会修复这一模型/量化损失。
因此这一周不训练的合理预期是：能对部分明显人车产生真实框，但误报/漏检可能较多，不能预计成为可靠高精度检测器。
演示初始阈值沿已测0.5；调低阈值可能多框也可能多误报，改后指标必须重新标明，不能继续引用旧P/R。
优先固定光照、较大近处、低速或短暂停留的人车作为可控演示，并展示实际误报/漏检；不把挑选片段宣称现场统计准确率。

2FPS会增加动态框错位：若源帧框和当前画面同宽w、横向移动d，简化IoU=(w-d)/(w+d)（0≤d<w），d>w/3时低于0.5。
这不改变源帧离线检测指标，却影响直播观感；小目标、高速横穿最明显。按帧率与框龄解释，不靠提高分数阈值掩盖。
若需要现场数字，只对独立连续片段的实际抽样源帧补完整真值后报P/R/AP50及样本数；不把一段“看起来能框”换算成百分比。

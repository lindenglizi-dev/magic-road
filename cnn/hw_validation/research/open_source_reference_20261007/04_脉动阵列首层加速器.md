# FPGA-CNN-accelerator-based-on-systolic-array：首层加速器边界

## 来源、日期、许可证与成熟度

- 主来源：[仓库/README](https://github.com/GuoningHuang/FPGA-CNN-accelerator-based-on-systolic-array)、[GPL-3.0 LICENSE](https://github.com/GuoningHuang/FPGA-CNN-accelerator-based-on-systolic-array/blob/main/LICENSE)，核查日期 2026-10-07，分支 `main`；本轮未稳定取得 commit hash。
- README 定位很明确：2023 集创赛国二、纯 Verilog、只算量化 YOLOv3-tiny 第一层“卷积+LeakyReLU+maxpool”，其余网络经 PCIe 回 PC/GPU；开源工程目标是 Xilinx Zynq UltraScale+ `xczu3eg-ubva530-2LV-e`，不是 PH1P35MDG324。竞赛演示成熟度高于草案，但不是整网 FPGA 核，更不满足本赛题“核心计算不可外置”。

## 真实目录与重点文件职责

真实路径保留了拼写 `accerator/`：`coe/`、`sim/`、`sources/ip/`、`sources/new/`。重点源文件为：

- [`ConvLayer.v`](https://github.com/GuoningHuang/FPGA-CNN-accelerator-based-on-systolic-array/blob/main/accerator/sources/new/ConvLayer.v#L31-L45)：RGB 输入，卷积后接两路 pooling。
- [`convolution3.v`](https://github.com/GuoningHuang/FPGA-CNN-accelerator-based-on-systolic-array/blob/main/accerator/sources/new/convolution3.v#L40-L125)：汇总 RGB、硬编码偏置/量化乘数/LeakyReLU 缩放。
- [`convolution_r.v`](https://github.com/GuoningHuang/FPGA-CNN-accelerator-based-on-systolic-array/blob/main/accerator/sources/new/convolution_r.v)、`_g.v`、`_b.v`：每个颜色分量的窗口、权重和阵列路径。
- [`SMB.v`](https://github.com/GuoningHuang/FPGA-CNN-accelerator-based-on-systolic-array/blob/main/accerator/sources/new/SMB.v)：三行/九 RAM 窗口和地址控制。
- [`WB.v`](https://github.com/GuoningHuang/FPGA-CNN-accelerator-based-on-systolic-array/blob/main/accerator/sources/new/WB.v#L50-L129)：两核权重切换；当前可见赋值还把多数权重硬编码为 0/1，并依赖 `blk_mem_gen_weight`。
- [`convfixew.v`](https://github.com/GuoningHuang/FPGA-CNN-accelerator-based-on-systolic-array/blob/main/accerator/sources/new/convfixew.v#L65-L83)、[`PE.v`](https://github.com/GuoningHuang/FPGA-CNN-accelerator-based-on-systolic-array/blob/main/accerator/sources/new/PE.v#L8-L38)：两条 9-PE 乘加链，依赖 Xilinx `xbip_multadd_0`。
- [`pooling.v`](https://github.com/GuoningHuang/FPGA-CNN-accelerator-based-on-systolic-array/blob/main/accerator/sources/new/pooling.v)：2×2 最大池化与行缓存。

## 数据流、接口、量化与握手

输入是 `din_r/g/b + valid_in + repeat_in`，输出两路 16-bit 结果和 valid，没有 ready，因此不能承受下游反压。每个 RGB 分量以两个 9-PE 链同时算两个卷积核；三色结果相加后进入固定常数量化/激活，再池化。PE 的 F/W 为 8-bit、级联 C/P 仅 16-bit，[九项链式累加就可能溢出](https://github.com/GuoningHuang/FPGA-CNN-accelerator-based-on-systolic-array/blob/main/accerator/sources/new/PE.v#L8-L38)，更不等于 RoadYOLO 的 signed 33-bit 中间与最终 INT32。

`convolution3.v` 对一路减硬编码 `3845`，另一路未见同样 bias；随后以 `31316` 乘法和位片截取，再按正负分别乘 `30419/24335` 并加 12，[没有通用 per-channel bias/scale、RNE 或饱和证明](https://github.com/GuoningHuang/FPGA-CNN-accelerator-based-on-systolic-array/blob/main/accerator/sources/new/convolution3.v#L50-L123)。这些是特定首层常数，不能套到 SiLU1024 LUT。

## 与 RoadYOLO 的相同与差异

相同点是 INT8、3×3 首层、行缓冲、权重驻留和有限 DSP 下分批输出。差异是 YOLOv3-tiny 第一层普通 RGB 卷积+LeakyReLU+pool，而当前冻结网络是 DW/PW CSP+SiLU、512×288、stride4/8/16；本工程 480×256 输入、148.5MHz HDMI 行流，且后续依赖 PC/GPU。其“87 DSP 板上两核并行”资源/FPS不能外推到 PH1P 的 40 DSP、108 ERAM、100MHz。

## 采用分级与省时建议

- **可直接用：无。** GPL-3.0 与现项目许可兼容性需先确认；Xilinx IP 也不能直接映射 PH1P。
- **需移植：** 若未来改为整帧流式前端，可重写 SMB 的行窗思想，但要换安路 PH1P RAM、补 ready/valid、33/32-bit 数值链；紫光同创 Pango 原语也不能当作安路原语。
- **仅理念：** 两输出核批处理、像素复用、卷积后立即池化。当前 RoadYOLO 无对应首层 pooling，不能照搬融合。
- **最省时优化：** 继续用已验证 24MAC=8×3 小块，不移植 18-PE/Xilinx IP。先用现有全网 cycle 表定位最大项；若确为 PW 重复装载，再把“输入 tile/权重驻留后连续完成多个输出通道”的调度思想用于现有核，否则停止。

## 未验证风险与下步最小验证

本轮未运行 RTL、仿真、综合或板测；符号、溢出、IP 延迟、`repeat_in` 边界和 valid 对齐仍未确认，八项门禁均未执行。最小验证只需用 9 个 `-128×-128` 与混合符号向量检查 16-bit PE 链相对 INT32 golden 的偏差，再拉断 valid 检查窗口计数是否只在有效拍推进；确认不满足后不做 PH1P IP 移植。

## 简要总结

该工程提供“首层专用、两核并行、行流处理”的竞赛设计参考；本轮没有复现其板测，对 RoadYOLO 只能借调度理念，不能替换整网或当前 DW/PW 核。

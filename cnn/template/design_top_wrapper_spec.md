# design_top_wrapper: isolated 720p template

This file specifies cnn/template/design_top_wrapper.v, derived mechanically from
user_source/hdl_source/design_top_wrapper.v. This is a legacy video template,
not a CNN implementation or a claim that RoadYOLO works on hardware.

## Interface and behavior

Top-level ports, pin assignments, MIPI RX, camera configuration, ISP/AWB,
96-to-128-bit packing, DDR bridge/controller, video FIFO scheduling, PLL and HDMI
transmitter are inherited unchanged. See the adjacent RTL module port list for
the complete widths: I_sys_clk and I_rst_n inputs; camera SCL/SDA, camera reference
and reset; two button inouts; screen PWM and four TMDS outputs; differential MIPI
clock and four data lanes; DDR address[12:0], bank[1:0], clock/control, DQ[15:0],
DM[1:0] and differential DQS[1:0]. No new external port is introduced.

The removed branch comprises gray analysis, background/CCL, geometry classifier,
ROI frame banks, HOG, tracker/events and the two overlay instances. Four optional
ISP analysis outputs are left open. HDMI receives mixer RGB/VS/DE directly,
removing the two overlay pipeline stages. No fake CNN module is instantiated.

## Clock, reset and cycle contract

System reference is 50 MHz. Retain the existing generated PLL and controller
configuration: approximately 60 MHz camera byte domain, 100 MHz auxiliary domain,
66.667 MHz DDR user domain, 75 MHz HDMI pixel and 375 MHz serial clocks.
HDMI active area is 1280x720, total 1650x750: about 60.606 Hz at 75 MHz.
These are source/STA configuration values, not board measurements.
The source reset topology and its shortcomings remain unchanged: internal reset
uses PLL lock. This extraction does not repair reset synchronization.
Video-in and video-out retain their original asynchronous FIFOs and four video
frame bases. No additional latency or backpressure is added to those paths.
Analysis data is not consumed. DDR physical latency is not fixed by this spec.

## Timing scenario

At each active HDMI pixel the existing mixer data and DE/VS go directly to the
transmitter; blanking and full frame timing remain generated by the original VTC.
This illustrative WaveJSON is not a DDR timing measurement:

```json

```
